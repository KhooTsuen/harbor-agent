# 能力边界审查归档（2026-11-03 ~ 11-05）

> **这份文件是什么**：一次**有始有终**的能力边界审查的正式记录 —— 查了哪八块、
> 每条问题的原始证据、修了什么、验到哪一层、哪几条决定不修。
>
> **不是什么**：不是设计稿（那是 [`Runtime领域模型.md`](Runtime领域模型.md)）；
> 不是测试报告（数字看命令输出，入口清单看 [`回归基线.md`](回归基线.md)）；
> **更不是「Harbor 已经安全」的结论书** —— 它只记录这一轮查过什么。
>
> 为什么要留它：这轮审查横跨 P0/P1/P2 四个阶段、十几个提交，分散在 `CHANGELOG.md`
> 的不同小节里。没有一份总账，下次的人（或模型）只能靠翻提交历史猜「哪些是查过并
> 决定不修的」，于是把已经判过的事再查一遍 —— 或者更糟，把「有意保留」当成漏掉的洞改掉。

## 一、范围与过程

### 1. 初始目标

一句话：**逐块确认 Harbor 的八个能力领域「边界清不清楚、闸门在不在该在的地方」**，
每一条结论必须挂在具体源码路径 + 函数上，判定分三档：

| 档 | 含义 | 处置 |
|---|---|---|
| **A** | 边界清晰、单一真相源、有注释或自检兜住 | 记结论，不动 |
| **B** | 设计债务：能跑、不是洞，但同一件事有重复表达或缺护栏 | 逐条判定「修 / 保留 / 延期 / 已失效」 |
| **C** | 真实缺陷：用户可感知的功能失效，或安全边界不一致 | 修，并补回归判据 |

八块：模型、任务、工具、记忆、经验、权限、审计、浏览器扩展。

### 2. DSH 的定位（先说不清楚的容易误会）

参照对象是 **DeepSeek Harness** 的公开文档（`architecture` / `capability-seams` 中文版）。
它提供的是**分析视角**，不是 Harbor 的目标架构：

- **用了**：seam 三角审查法（Service Definition + Provider + Consumer 三者一起看）、
  「模型可见即已记录」这条不变量、「想加什么 → 改哪里」的归属表。
- **明确不照搬**：everything-is-a-plugin / 无特权内核、上百个 `ctx` seam + 服务注册表、
  profile-bundle-patch 多层组合、会话格式 generation 迁移链、waterfall 的 `next()` 委托。
  理由逐条写在 `CHANGELOG.md` 的「P2 第二阶段」前后几节里。
- **结论**：**没有证据支持「Harbor 需要架构重构」**。现存耦合大多是显式设计 + 有注释 +
  有自检的，符合这个项目「可恢复、可回滚」的取向。

## 二、逐项记录

### C 类（两条，均已修）

#### C-1 敏感文件「批准了也读不到」— `2521464`

- **原始问题**：用户对 `.env` / `.ssh/id_rsa` 点「允许」，仍然返回「需要授权」。
- **根因**：`capability.cjs` 的 `if (grant && !sensitive)` —— 敏感一命中，连用户刚批的
  那条授权一起否掉。同一条判据链上另有五个病，一次治了（父目录继承、会话隔离漏判、
  once 被别的会话消费、无效记录拿到全权、续期不生效）。
- ** 영향**：默认配置（`permission:'ask'` + `fileScope:'workspace'`）上就成立，
  不是边缘组合。
- **落地判据**：`205-sensitive-grant`（4 组）、`206-sensitive-grant-record`（7 组）；
  判据是**真的读没读到**、**授权还剩几条**，不看文案。
  真机另有 `tools/e2e-sensitive-grant.mjs`：确认卡弹出 → 脚本自己点「允许」→
  假上游第 2 个请求体里真的带着那个假密钥（读不到的话密钥永远不会出现在请求里）。

#### C-2 MCP 调用绕过「本轮运行时约束」— `d8992a0`

- **原始问题**：`tools/index.cjs` 的 MCP 分支写在函数开头就 `return`，而
  `allowTools` / `allowWrite` / `allowNetwork` 三道闸在它后面几十行。于是用户说
  「只分析，不修改」，MCP 工具照样执行 —— **被明令禁止的操作真的跑了**。
  同一分支还有 fail-open：`ask` 档但拿不到 `confirm` 函数时直接往下执行。
- **改法**：新增 `electron/core/tools/mcp-gate.cjs`，判据、拒绝文案、审计收在一处；
  顺序与内置工具那一节保持一致。MCP 能力无法可信分类，所以按「可能写 + 可能联网」
  处理（fail-closed），不做 `readOnlyHint` 分级。
- **落地判据**：`204-mcp-runtime-gate` ①~③ —— 判据是 **`callTool` 的实际调用次数**
  加审计 `ok`，两者分开断言。修前三条约束下调用次数都是 1，修后都是 0。

> ⚠️ **三个 MCP 提交别混成一个成果**（这是本次归档专门核对过的一处）：
>
> | 提交 | 修的是什么 | 现象 |
> |---|---|---|
> | `d8992a0` | **C-2**：MCP 完全不经过「本轮运行时约束」三道闸 | 禁止的操作执行了（调用次数 1，应为 0） |
> | `dc9a3f2` | 批准粒度：整类 `mcp` → **按服务器** | 批了 `fetch`（只读），另一台 `filesystem` 的写工具免问执行 |
> | `9f844cc` | 批准粒度：按服务器 → **按这一次调用** | 同一台服务器内，批了读就把写/删/换目标一起放行 |
>
> 第三笔还顺带撤掉了设置页那个「服务器工具权限」下拉 —— 它在内核**没有任何读者**，
> 选了「只读」不会让那台服务器变只读。撤掉而不是灰掉：灰掉仍在暗示功能存在。
> 老配置里的 `permission` 字段保留读入、不回写、不迁移。

## 三、验证证据：每条结论验到哪一层

**层级定义**（别把后三层混着说）：

- **静态核对**：读源码 / 抠类型 / 比对两份清单，不执行
- **纯函数**：require 一个模块，喂数据看返回值
- **内核集成**：真 loop / 真工具 / 真落盘，**模型或外部服务被替换**
- **隔离探针**：临时脚本 + 隔离数据根 + 打桩计数器，判「真的发没发出去」
- **真机链路**：真 Electron + 真界面 + 真内核，只有模型是假的
- **未验证**：没有任何自动证据

| 事项 | 静态 | 纯函数 | 内核集成 | 隔离探针 | 真机 | 未验证 |
|---|---|---|---|---|---|---|
| C-1 敏感授权 | ✅ | ✅ | ✅ `205`/`206` | ✅ | ✅ `e2e-sensitive-grant` | 多窗口同时点「允许」 |
| C-2 MCP 运行时约束 | ✅ | ✅ gate 判据 | ✅ `204` | ✅ 调用计数 | — | 真 MCP 服务器的行为差异 |
| MCP 审批粒度（两轮） | ✅ | ✅ | ✅ `204` ⑤ | ✅ asked/calls 计数 | — | 同上 |
| 记忆元数据 / 去重 / 改字 | ✅ | ✅ | ✅ `207`/`208` + SEC-057/060/061/062/065 | ✅ | — | 真模型会不会滥用 `scope:'session'` |
| 双执行器一致性 | ✅ | ✅ | ✅ `209`（各跑真命令） | ✅ | — | 串行版没有生产调用方 |
| 任务 ↔ 模型调用 | ✅ | ✅ | ✅ `210`（真 `fetch`、指标真落盘） | ✅ | — | 失败的调用与 CLI 后端一行都不记 |
| `edge_*` 目标准入 | ✅ | ✅ | ✅ `211`（打桩 `runEdge`，判发出几条） | ✅ | — | **真 Edge 加载扩展后的端到端** |
| Native Host 信任边界 | ✅ | — | ✅ `154`/`156`/`157`/`160` | ✅ 真管道 + 真 token | ✅ `155`/`202` | 真浏览器侧边栏人工点验 |
| B-1 维度同步 | ✅ | — | ✅ `70` ⑦（含缺陷注入实测报红） | — | — | — |

**这份表怎么读**：

- 「真机」列空着的，意思就是**没有任何自动证据**，不是「验过了没必要跑」。
- 隔离探针里替换掉的东西（假 MCP、假上游、打桩的 `runEdge`）说明结论的**适用范围**
  只到「Harbor 这一层判得对不对」，**不覆盖**外部进程自己的行为。
- `npm run preflight` 全绿不等于「Harbor 没有其他安全缺陷」：它跑的是 `verify` + 应用自检，
  真机 e2e、`security:gate` 严格档**都不在里面**（口径见 `回归基线.md` 第一节）。

## 四、遗留清单（不自动成为下一版的必做需求）

按「实际影响 × 风险 × 开发价值」粗排，**不是排期**。

### 值得优先考虑（有真实用户影响）

| # | 遗留 | 影响 | 为什么这轮不做 |
|---|---|---|---|
| L-1 | **`edge_*` 没接确认链**：网络策略「每次先问」档位下它不产生任何问询 | 用户选了「先问」，用 Edge 工具导航时一次都不会被问 | 要把这一族接进确认路径 = **权限体系扩展**；用户 2026-11-05 拍板「本轮只拦明确禁止」 |
| L-2 | **真 Edge 扩展端到端未验证** | 「扩展装上了、在真浏览器里点一下能用」全靠人工 | 端到端要真在用户的 Edge 里装扩展，会碰真实浏览器配置；任务书明确要求不接触 |
| L-3 | **MCP 分级权限**（`server.permission` 现在没有读者，声明入口已撤掉） | 只读档 / 只分析轮里**纯只读的 MCP 工具也被误拒** | 方案已写清（`安全模型.md` §4），但它拿「用户对自己配的服务器的声明」当证据。第一步不是改判据，是先补一个**可信的声明入口** —— 要拍板 |

### 已被明确接受的边界（不是漏洞，别再当洞查一遍）

| # | 事实 | 性质 |
|---|---|---|
| L-4 | **Native Host 同用户进程信任边界**：token 文件 ACL 与命名管道默认 ACL 都给同用户完全控制（`mode: 0o600` 在 Windows 上被忽略） | **平台现实**。token 只挡「别的 Harbor 实例」和「旧 host」，挡不住同用户的另一个进程。方案 A（来源标记）收益是**可观测性**不是安全性 → 未实施 |
| L-5 | **MCP 通道没有路径闸** | 不是漏了检查：MCP 工具的参数 schema 由第三方给，Harbor 这层没有「路径」概念可判。真正的边界是那个服务器进程自己的配置 + 系统账号权限。**没有进程沙箱** |
| L-6 | **任务状态变更不写 audit**（B-7） | 台账 `updatedAt` / `finishedAt` + 事件流已有；再落一份属新增落盘面 |
