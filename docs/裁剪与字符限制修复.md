### 问题 2：定位结论

- 限制在**渲染层**，三处都用同一个常量 `src/constants/index.ts` 的 `MAX_INPUT_LENGTH = 4000`：
  1. `src/stores/useThreadStore.ts` 的 `setInput`：`value.slice(0, MAX_INPUT_LENGTH)` —— **真正的硬上限**（粘贴超长被静默切掉）；
  2. `Composer.tsx` 的 textarea：`maxLength={MAX_INPUT_LENGTH + 200}`；
  3. `Composer.tsx` 的 `tooLong = input.length >= MAX_INPUT_LENGTH` → `canSend` 为假 → **发送键变灰**。
- **为什么是 4000**：`git log -S MAX_INPUT_LENGTH` 只追到**初始提交**（`9556df4` 初始提交：Personal Agent 0.23.0），没有任何理由记录在案 —— 是遗留的防御值，不是算出来的。
- 主进程 / IPC **没有任何**长度校验（`chat.cjs` 里只有能力边界检查，不是长度）；也没有配置项。
- 下游（放开会影响的）：
  - 提示词：`context-builder` 按 `budget.conversation`（30% → 默认 3686 字符）裁，超出的模型看不到 —— **既有行为**，本次未改；
  - 渲染：输入框是受控组件，每次键入整串重渲（所以要真机量响应时间）；
  - 会话落盘 / IPC：无长度限制。
- 新增的真机探针 `tmp/probe-long-input.js`（跑在隔离的便携版上，不碰真实 data/、不发真请求）
  **当场抓到一个真 bug**：贴满上限时 `tooLong` 为真 → **输入框满格却发不出去**（还得自己删一个字符）。
  4000 时代就有，只是没人踩到那个边界。
