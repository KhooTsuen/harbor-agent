# Harbor Agent 开屏与彩蛋设计方案

## 1. 设计目标

Harbor 当前开屏的主要问题不是缺少装饰，而是中央区域信息密度较低：用户看到大量空白、固定提示语和少量建议按钮，却难以立即判断当前工作区状态、上次做到哪里以及下一步可以做什么。

新开屏需要同时满足：

1. 进入应用后快速理解当前状态。
2. 能直接开始高频任务。
3. 能恢复上次中断的工作。
4. 保持安静、专业、适合长期使用。
5. 通过少量彩蛋形成 Harbor 自己的性格。
6. 所有动态内容来自真实状态，不展示虚假扫描或虚假进度。
7. 彩蛋只影响展示和统计，不改变权限、模型行为或文件操作。

## 2. 当前界面分析

当前界面已经具备较完整的专业工作台结构：左侧是会话和工作区，中间是对话与输入，右侧是浏览器/工具区域，底部有状态信息。需要优化的是无对话时的中央空状态。

主要问题：

- 主标题和推荐问题长期固定，重复使用后缺乏价值。
- 大面积空白没有承载工作区、Git、测试或任务信息。
- 推荐按钮更像示例文案，没有形成工作流入口。
- 上次任务、中断状态和最近文件没有进入第一视野。
- 输入框与中央引导区域联系较弱。
- 产品名 Harbor 的语义没有形成可识别的视觉语言。

应保留的优点：

- 深色、克制、适合长时间工作。
- 左中右三栏结构稳定。
- 输入框位于视觉中心下方，符合对话应用习惯。
- 推荐动作可以直接转化为更有价值的动态操作。

## 3. 设计原则

### 3.1 工作优先

开屏首先展示工作区和任务状态，装饰只作为背景。用户不应该为了看动画而多点一步。

### 3.2 真实状态

“正在扫描”“测试通过”“12 个变更”“任务已恢复”等文字必须来源于真实数据。未完成扫描时显示中性加载状态，不提前给结论。

### 3.3 渐进呈现

第一眼只显示最重要信息；最近文件、统计和项目地图通过展开或切换查看。避免把开屏做成仪表盘堆砌。

### 3.4 低打扰动态

动画应缓慢、低对比、可暂停，不能持续抢夺注意力。遵守系统“减少动态效果”设置，并提供应用内关闭选项。

### 3.5 不改变安全语义

彩蛋不能自动调用模型、读取额外文件、运行命令、扩大权限、写入用户项目或隐藏失败。

## 4. 可选开屏方向

| 编号 | 方向 | 主要内容 | 优点 | 成本 |
|---|---|---|---|---|
| A | 工作区总览 | 技术栈、Git、测试、最近文件 | 最实用、每个项目不同 | 中 |
| B | 今日工作台 | 待办、最近任务、建议动作 | 适合长期个人使用 | 中 |
| C | 动态 Agent 待机 | 工作区扫描和状态变化 | 有生命感 | 中 |
| D | 命令面板首页 | 搜索、自然语言和快捷命令 | 高效、实现较轻 | 低 |
| E | 最近现场恢复 | 未完成任务和检查点 | 与 Harbor 恢复能力契合 | 中 |
| F | 项目地图 | 模块和依赖可视化 | 视觉辨识度高 | 高 |
| G | 任务模板库 | 理解、修改、验证任务 | 新用户友好 | 低 |
| H | 极简动态背景 | 网格、光束、状态动画 | 改善空白感 | 低 |
| I | 终端启动仪式 | 真实初始化信息 | 符合开发工具气质 | 中 |
| J | 情境化首页 | 根据任务/时间切换内容 | 长期不单调 | 中 |

## 5. 推荐组合

推荐采用 `A + E + D + H`：

- A 工作区总览作为默认主体。
- E 最近现场恢复拥有最高展示优先级。
- D 命令面板作为统一操作入口。
- H 灯塔和低调动态提供品牌识别。

示意结构：

```text
                         Harbor
                  当前工作区已经就绪

              Electron · React · TypeScript
             main · 12 个变更 · 测试未运行

       [检查当前变更] [运行测试] [理解项目结构]

最近工作
18 分钟前：修复会话恢复逻辑             [继续]
昨天：权限弹窗焦点检查                  [查看]

──────────────────────────────────────
描述任务、输入 / 选择操作、输入 @ 引用文件
```

右侧浏览器区域保持现有职责，不在开屏中央复制浏览器说明。没有打开网页时，右侧继续显示简洁空状态。

## 6. 开屏信息架构

### 6.1 顶部品牌区

内容：Harbor 名称、当前状态和低调灯塔标识。标题尺寸保持工作台尺度，不使用营销页式巨大标题。

状态文字示例：

- 当前工作区已经就绪。
- 正在读取工作区信息。
- 上次任务尚未完成。
- 工作区为空，可以选择一个目录开始。
- 当前没有可用模型。

### 6.2 工作区摘要

最多显示两行：

- 工作区名称和路径缩略。
- 技术栈、当前分支、变更数量、测试状态。

点击摘要可以展开详细信息，但默认不显示完整长路径、几十项统计或大量文件。

### 6.3 主动作

默认不超过三个：

- 检查当前变更。
- 运行测试。
- 理解项目结构。

按钮内容根据工作区动态调整：

- 没有 Git：隐藏“检查当前变更”。
- 没有测试命令：将“运行测试”换成“查找运行方式”。
- 工作区为空：显示“选择工作区”“创建说明文件”。
- 存在中断任务：主动作变为“继续任务”“查看变更”“放弃任务”。

点击建议动作时，优先把结构化提示填入输入框，让用户确认；只有明确无风险的界面操作可以立即执行。

### 6.4 最近工作

默认显示最多两条：

- 未完成或最近完成的任务。
- 时间、状态和一句摘要。
- “继续”“查看”或“重新运行”入口。

不能只依据模型回答标记完成，应读取任务账本和实际产物。

### 6.5 命令输入

输入框仍然是核心入口，并支持：

- 普通文本：发送给 Agent。
- `/`：打开技能或操作菜单。
- `@`：引用文件。
- `>`：选择命令或工具动作。
- `#`：搜索会话或任务，可在后续版本实现。

界面不需要长期显示快捷键教程；在输入触发符号后再展示相关菜单。

## 7. 开屏状态优先级

同一时间只展示一个主状态，优先级如下：

1. 数据损坏、凭证不可用或关键启动错误。
2. 等待用户处理的权限或失败恢复。
3. 可恢复的未完成任务。
4. 首次使用引导。
5. 工作区总览。
6. 空工作区引导。

时间、节日或彩蛋不能覆盖错误、权限和恢复状态。

## 8. 首次使用状态

第一次启动只显示三个步骤：

1. 选择或确认工作区。
2. 配置测试模型凭证。
3. 发送第一个只读问题。

完成后自动进入正常开屏，不保留大型新手引导。用户可以在设置中重新打开引导。

第一个建议问题：

```text
请只读取当前工作区，告诉我这是一个什么项目、如何运行，不要修改文件。
```

## 9. 最近现场恢复状态

存在中断任务时显示：

```text
上次任务在 18 分钟前停止
“重构会话恢复逻辑并运行测试”

已完成 3/5 步
✓ 找到恢复入口
✓ 修改 session-store
✓ 补充单元测试
○ 运行完整测试
○ 检查发行包

[继续任务] [查看变更] [放弃任务]
```

要求：

- 步骤来自任务账本。
- “继续”不能重复已完成的危险动作。
- “放弃”只结束任务，不自动回滚文件。
- “查看变更”展示真实磁盘差异。
- 找不到检查点时不显示虚假的继续入口。

## 10. 工作区总览状态

可展示：

- 工作区名称和路径。
- 技术栈识别结果。
- Git 分支和未提交变更数量。
- 最近一次测试结果和时间。
- 最近修改的文件。
- 最近完成任务。

扫描应异步执行，启动时先展示稳定布局。扫描失败时单项显示“无法读取”，不能让整个开屏不可用。

## 11. 极简动态视觉

### 11.1 灯塔主题

中央背景放置低对比灯塔轮廓或抽象光源：

- 空闲：非常缓慢的光束移动。
- 正在读取：光束轻微扩大。
- Agent 运行：出现沿任务方向流动的细线。
- 等待权限：琥珀色小范围脉冲。
- 完成：短暂绿色扫光一次。
- 失败：短暂琥珀/红色提示后回到静态。
- 离线：灯光熄灭，保留轮廓。

动态必须来自真实应用状态，不循环假装“正在处理”。

### 11.2 背景规则

- 不使用高饱和渐变和大面积发光圆球。
- 不降低正文和控件对比度。
- 不遮挡点击区域。
- 默认动画周期不短于 8 秒。
- 页面失焦或窗口最小化时暂停。
- “减少动态效果”开启后只保留静态状态变化。
- 动画不触发网络请求和模型调用。

## 12. 彩蛋设计原则

彩蛋应该：

- 低频、可忽略、不影响工作。
- 与 Harbor、灯塔、港口和航行语义一致。
- 只改变展示、主题或统计入口。
- 能关闭、能恢复，不修改用户代码。
- 不自动发消息、不产生费用。
- 不隐藏错误或权限提示。

不应加入：全屏强制动画、自动声音、移动按钮、假系统错误、随机修改代码、隐藏权限提升、联网天气定位和每日签到。

## 13. 推荐彩蛋清单

### 13.1 灯塔状态彩蛋

灯塔本身既是状态组件也是轻量彩蛋：

- 第一次任务完成时完整点亮一次。
- 测试全绿时光束完整扫描一次。
- 成功恢复中断任务时显示“航线已恢复”。
- 离线时只保留暗色轮廓。

每种效果只播放一次，持续 1-2 秒，不阻止输入。

### 13.2 深夜场景

本地时间 00:00-05:00 且用户没有关闭情境主题时：

- 背景亮度略微下降。
- 出现非常淡的月光或远处船灯。
- 空状态标题可以低频显示：“夜深了，先完成最重要的一件事。”

不弹窗、不播放声音、不记录位置，也不主动提醒用户继续工作。

### 13.3 连点 Harbor 标识

连续点击左上角 Harbor 标识 5 次：

- 解锁“夜航主题”。
- 灯塔完整亮起一次。
- 状态栏短暂显示“夜航模式已启用”。

再次连续点击 5 次恢复默认。点击计数只在短时间窗口内有效，避免日常操作误触。

### 13.4 `/harbor` 隐藏命令

输入 `/harbor` 打开真实统计面板：

```text
Harbor 状态
完成任务：346
中止任务：7
成功恢复：12
运行测试：61
最常用工具：read_file
```

所有数据来自本地任务账本，无法计算的项目不显示。统计面板不得读取额外工作区文件或上传数据。

### 13.5 测试全绿

当应用确认完整测试真实通过时：

- 状态栏出现一条短暂绿色细线。
- 灯塔扫光一次。
- 显示“航道畅通”。

触发条件必须包括真实测试命令、退出码为 0 和当前任务关联；不能仅依据模型文字。

### 13.6 首次安全靠港

第一次完成带磁盘产物且验证成功的任务时：

```text
首次安全靠港
第一个有真实产物的 Agent 任务已经完成
```

提示持续约 2 秒并淡出，不使用模态弹窗。

### 13.7 连续安全任务

可选成就只奖励可靠性：连续 20 次任务没有越界写入、未处理错误、虚假成功或强制退出时，短暂显示“连续 20 次安全返航”。

失败后重新计数，但不制造焦虑，不长期显示连续天数。

### 13.8 项目纪念

基于真实 Git 和测试数据低频触发：

- 项目创建周年。
- 第 100、500、1000 个测试通过。
- 第 100 次安全任务完成。
- 仓库当天恰好没有 TODO 时显示一次轻提示。

扫描不到数据时不展示，不虚构项目历史。

### 13.9 特殊文件

工作区存在以下普通文件时，可以显示隐藏入口：

```text
LIGHTHOUSE.md
CAPTAIN.md
MESSAGE_IN_A_BOTTLE.txt
```

点击入口只是以特殊样式打开文件内容，仍遵守正常文件读取权限。文件内容不能获得更高指令优先级。

### 13.10 可选复古彩蛋

如果保留 Konami Code：

```text
↑ ↑ ↓ ↓ ← → ← → B A
```

仅解锁复古终端配色和一次灯塔扫光，不改变快捷键、权限和任务行为。该彩蛋优先级较低，可以放到后续版本。

## 14. 彩蛋触发与持久化

| 彩蛋 | 触发 | 冷却 | 是否持久化 |
|---|---|---:|---|
| 夜航主题 | 5 次点击标识 | 2 秒点击窗口 | 是，用户可关闭 |
| `/harbor` | 输入命令 | 无 | 否 |
| 航道畅通 | 完整测试真实通过 | 每个任务一次 | 只记录次数 |
| 首次安全靠港 | 首次验证成功的写入任务 | 永久一次 | 是 |
| 安全返航 | 连续 20 次可靠任务 | 达成一次 | 记录里程碑 |
| 深夜场景 | 本地时间 | 每晚 | 只存用户偏好 |
| 项目纪念 | Git/测试里程碑 | 每个里程碑一次 | 是 |

持久化数据放在应用自己的统计或偏好位置，不写入用户工作区和 Git 仓库。

## 15. 开屏文案

默认文案应根据真实状态选择，不纯随机轮换：

| 状态 | 文案 |
|---|---|
| 正常就绪 | 当前工作区已经就绪 |
| 首次启动 | 从一个只读任务开始 |
| 有中断任务 | 上次任务还停在这里 |
| 有未提交变更 | 当前有一些变化值得检查 |
| 测试失败 | 最近一次测试没有通过 |
| 空工作区 | 选择一个工作区开始 |
| 离线 | 当前离线，本地功能仍可使用 |
| 深夜 | 夜深了，先完成最重要的一件事 |

避免长期使用“想让 Agent 做什么？”这类泛化文案。支持文字保持一行或两行，不在界面中写大段功能介绍。

## 16. 交互细节

- 所有主动作可通过键盘访问。
- 图标按钮有可访问名称和 tooltip。
- 工作区扫描期间按钮不跳位。
- 动态数据更新不抢走输入框焦点。
- 点击建议动作后允许编辑，不直接执行危险任务。
- “继续任务”和“放弃任务”有清楚不同的视觉语义。
- 失败状态不使用庆祝动画或成功颜色。
- 开屏折叠后不占用正常对话空间。

## 17. 性能边界

- 首屏骨架不等待 Git、测试或文件扫描完成。
- 扫描工作放到异步流程并设置超时。
- 灯塔动画仅使用低成本 CSS/Canvas 效果。
- 窗口最小化、失焦或系统节能时暂停动画。
- 开屏组件不能持续触发文件树、Git 或任务查询。
- 大型仓库只读取摘要，不在开屏递归扫描全部文件。
- 开屏资源和统计失败不能影响聊天输入和发送。

## 18. 隐私和安全边界

- 默认不展示完整绝对路径，可在用户点击后查看。
- 最近任务摘要不展示密钥和敏感文件内容。
- `/harbor` 统计只保存在本地。
- 时间情境不请求地理位置和天气网络权限。
- 特殊文件和彩蛋不绕过工作区权限。
- 彩蛋动画不会自动调用模型或产生费用。
- 截图模式可以隐藏路径、任务摘要和统计。

## 19. 分阶段实施

### 第一阶段：实用开屏

- 工作区名称、技术栈、分支和变更摘要。
- 三个动态主动作。
- 最近任务和中断任务恢复入口。
- 稳定的加载、错误和空工作区状态。

### 第二阶段：视觉和品牌

- 静态灯塔背景。
- 就绪、运行、权限、完成和失败状态变化。
- 减少动态效果和动画开关。
- 多分辨率与高 DPI 适配。

### 第三阶段：首批彩蛋

- 连点标识解锁夜航主题。
- `/harbor` 真实统计。
- 测试全绿“航道畅通”。
- 首次安全靠港。
- 深夜静态场景。

### 第四阶段：可选扩展

- 项目纪念。
- 特殊文件入口。
- 复古终端主题。
- 项目地图视图。

## 20. 推荐第一版范围

第一版建议只实现：

1. 工作区总览。
2. 中断任务恢复。
3. 三个动态主动作。
4. 静态灯塔轮廓和真实状态光束。
5. 连点 Harbor 标识解锁夜航主题。
6. `/harbor` 本地统计。
7. 测试全绿时显示“航道畅通”。

暂不实现复杂项目地图、联网天气、声音、节日主题和大量成就。先验证用户是否更容易理解工作区、继续任务和发起第一步操作。

## 21. 验收要点

实现后按照 [个人 Agent 界面 UI 测试指南](./个人Agent界面UI测试指南.md) 验收，并额外检查：

- 工作区信息来自真实数据且更新及时。
- 开屏没有明显延长可输入时间。
- 点击主动作后进入正确输入或任务流程。
- “继续任务”不会重复危险步骤。
- 动画在失焦和减少动态效果时正确停止。
- 彩蛋不修改文件、不调用模型、不扩大权限。
- 彩蛋触发不会遮挡错误、权限或恢复状态。
- `/harbor` 的统计可由任务账本验证。
- 测试全绿彩蛋只在真实退出码为 0 时触发。
- 100%、125%、150% 缩放和窄窗口下文字、按钮不重叠。

## 22. 最终建议

Harbor 的开屏不应变成营销页，也不应仅靠动画填满空白。最合适的方向是把它做成一个安静的项目工作台：默认展示真实工作区状态，有任务时优先恢复，输入框始终是核心，灯塔作为低调的状态语言和品牌符号。

彩蛋控制在少量、高质量、与可靠性有关的触发上。它们应该让长期用户偶尔感到惊喜，同时不让第一次使用的人承担额外学习成本。

## 23. 状态层与性格层修订

本节是对前文的实施级补充。实现时以本节的分层规则为准。

### 23.1 两层必须分开

开屏内容分成两层：

| 层 | 内容 | 是否随机 | 是否需要真实证据 |
|---|---|---:|---:|
| 状态层 | 工作区、分支、变更、测试、任务、网络、凭证、错误 | 否 | 是 |
| 动作层 | 继续、查看变更、运行测试、新建会话 | 否 | 是 |
| 性格层 | 欢迎语、副标题、口头禅、语言彩蛋 | 可随机，可关闭 | 不需要，但不能与状态冲突 |

状态层负责告诉用户“现在真实发生了什么”；性格层只负责让界面不冷、不空、不像模板。性格层不能代替状态层，也不能把状态层改写成玩笑。

示例：

```text
性格层：来了？今天想折腾点什么。
状态层：工作区已读取 · main · 12 个变更 · 测试未运行
动作层：[检查当前变更] [运行测试] [理解项目结构]
```

下面的组合是错误的：

```text
醒着呢，项目扫描完成，一切都在掌控中。
```

因为它把性格句、扫描事实和未经验证的保证混在了一起。

### 23.2 性格层文案要求

- 通常 6-20 个汉字，最多两行。
- 不承担任务、错误、权限或完成状态说明。
- 不声称已经完成没有验证的动作。
- 不要求用户回应、打卡或继续工作。
- 不使用过度营销、客服或项目管理口吻。
- 同一句不连续重复；用户可在设置中关闭。
- 出现数据损坏、凭证错误、权限等待或危险恢复时，暂停调侃和轻松语气。

### 23.3 欢迎语文案库

可以从以下句子中低频选择一条，显示在状态摘要附近：

- 来了？今天想折腾点什么。
- 醒着呢。说吧，我接。
- 又见面了。这次带问题，还是带情绪？
- 工作区在这儿，先挑一件。
- 今天准备修点什么？
- 你负责说，我负责把现场看明白。
- 还没开工。正好，先从最麻烦的那件开始？
- 文件都在，别急着改。
- 港口开着，把问题丢过来。
- 今天也不一定要一次解决所有事。
- 先来一个小任务热热身？
- 想查、想改、想吐槽，都可以先说。
- 这次从哪里下手？

### 23.4 回访语文案库

有历史会话或任务时，可以低频使用：

- 又回来了。上次那件事还在等你。
- 你上次停在这里，要接着走吗？
- 昨天的坑还在，今天要不要填一铲？
- 看起来你还没打算放过这个项目。
- 上次改到一半，这次继续？
- 这份代码还认得你。
- 欢迎回来，现场没有自己消失。

真实中断任务必须仍由状态层清楚显示，例如 `上次任务中断于 18 分钟前`，不能只用“上次那件事还在等你”。

### 23.5 轻微吐槽文案库

只在普通就绪、没有阻断错误的状态使用：

- 这个项目的脾气，今天看起来还行。
- 变更不算多，适合先看一眼。
- 测试还没跑，谁也不能提前庆祝。
- 文件很多，但我们可以一件一件来。
- 这段代码看着像是有故事。
- 先别急着重构，听它解释一下。
- 这里安静得有点可疑。
- 没有 TODO？今天运气不错。

不得把吐槽放在权限、数据损坏、凭证失效或任务失败的唯一提示位置。

### 23.6 深夜文案库

只根据本地时间改变性格句，不覆盖真实状态，也不鼓励熬夜：

- 还没睡？那就先做最小的一步。
- 夜班港口还开着，但别把自己也留在这儿。
- 可以继续，也可以明天再处理。
- 先记下来，明天接着做也行。

不请求定位、天气和外部网络权限，不自动播放声音。

### 23.7 应避免的句子

- “我已经帮你搞定了”：没有实际产物验证时禁止使用。
- “一切都在掌控中”：会掩盖失败和风险。
- “别担心，我不会出错”：虚假保证。
- “今天也要加油哦”：泛化、像打卡应用。
- “让我为你优化效率”：没有具体事实的产品话术。
- 任何鼓励连续签到、无限工作或证明忠诚的表达。

### 23.8 随机和关闭规则

- 每次开屏最多显示一条性格句。
- 同一句至少间隔 5 次开屏或 24 小时。
- 最近失败、权限等待、数据损坏和凭证错误时不抽取吐槽句。
- 随机选择只影响文案，不影响状态、动作、权限、文件和模型请求。
- 设置中关闭后只保留状态层和动作层。
- 性格句的选择写入本地偏好即可，不写入会话正文和用户工作区。

### 23.9 彩蛋重新分类

前文的彩蛋分为两种，实施时不要混称：

1. **语言彩蛋**：欢迎语、回访语、轻微吐槽、深夜句、隐藏短句。它们可以无信息、低频、随机、可关闭。
2. **状态彩蛋**：测试全绿、首次安全靠港、成功恢复、项目里程碑。它们本质上是带 Harbor 语气的真实状态反馈，必须有任务账本、测试结果、Git 或文件产物作为证据。

“航道畅通”属于第二类，不应被当作纯语言彩蛋；“醒着呢。说吧，我接。”属于第一类，不应被当作系统状态。

### 23.10 推荐开屏最终结构

```text
Harbor
来了？今天想折腾点什么。

状态：工作区已读取 · main · 12 个变更 · 测试未运行

[检查当前变更] [运行测试] [理解项目结构]

最近工作
上次任务中断于 18 分钟前 · 已完成 3/5 步       [继续]

描述任务、输入 / 选择操作、输入 @ 引用文件
```

上例中，第一行是性格层；`状态`、最近任务和按钮是状态/动作层。无论随机文案如何变化，事实和操作入口都必须保持一致。

### 23.11 修订后的验收标准

- 随机替换性格句不会改变状态、按钮、权限和任务流程。
- 用户关闭性格层后，状态层仍完整可用。
- 状态错误时不会被轻松文案遮挡。
- 欢迎语不再使用“当前工作区已经就绪”一类正式句作为唯一开场。
- 工作区、任务和测试信息仍来自真实数据。
- “航道畅通”“安全靠港”等句子只有在客观验证通过后出现。
- “来了？今天想折腾点什么”一类句子不会被误解为任务已开始或状态已完成。
