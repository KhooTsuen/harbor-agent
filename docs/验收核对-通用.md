> 和 [`验收核对-第16章.md`](验收核对-第16章.md) 同属「内部验收清单」。那份只覆盖
> 1.1.2 那个时点的 31 项；这一份收**之后新增的能力**和**历史上出过毛病、每次发版都该过一遍**的路径。
>
> 记号沿用那一份：
>
> | 记号 | 意思 |
> | --- | --- |
> | ✅ 行为 / ✅ 在 | 有断言可复验（能证到「存在且有人用」，证不到「好用」） |
> | 👁 需上手 | 得实际点一遍才算数 —— 断言照不到层与层之间的接线 |

> **为什么 👁 不是可选项**：这个项目出过两次事故（发不出消息、流式内容全不更新），
> **两次都过了 tsc + lint + 全部测试**。接口对得上 ≠ 能用。

## 二、发消息与会话

| # | 项 | 怎么验 / 看什么 |
| --- | --- | --- |
| 5 | ✅ 行为 | **发送后立即有反馈**：本地先加占位消息、先置「这条在跑」再等后端（断言盯的是**先后顺序**；实测首反馈 10ms） |
| 6 | 👁 | **流式内容实时更新**：发一句会产生长回复的话，看**文字、工具过程、引用**是不是一行行长出来 —— ⚠️ 这条出过事故（拆文件之后流式全不更新），每次动 `stores/thread/**` 必看 |
| 7 | ✅ 行为 | **半截回复也不丢**：流式过程中分段落盘（自检组 `53-partial-persist`）。手动验：跑到一半强杀进程，重启后那半截还在 |
| 8 | 👁 | **重启后当前对话是满的**：不用先点别的对话再点回来（出过这个 bug：磁盘上 2 条、界面 0 条） |
| 9 | ✅ 在 | **当启动**：一条对话在跑时切到另一条，互不干扰（「在跑」按对话记，`sendingThreads` 是数组）。切来切去的手感要上手看 |

## 四、权限与安全

| # | 项 | 怎么验 / 看什么 |
| --- | --- | --- |
| 16 | 👁 | **写文件先给 Diff**：展开确认弹窗看到「改成什么样」；**拒绝之后它不重试同一个操作**，会换路子或来问你 |
| 17 | ✅ 行为 | **critical 命令一律拦**：设置 → 工具里有风险试算；跑格式化 / 提权 / 递归删这类会被直接拒（自检组 `03-fs-safety`、`61-destructive`） |
| 18 | 👁 | **出圈要授权**：让它读工作目录之外的文件 → 弹授权；「允许本次」只对本次会话有效 |
| 19 | ✅ 行为 + 👁 | **网络策略真的拦得住**：deny 的主机连不上；`ask` 不会误伤已配置的 MCP 服务器（自检组 `73-net-policy`）。真机验法：塞一个 `network: deny` 的 MCP → 它起不来并说明原因，一键改成「允许联网」后能起 |
| 20 | ✅ 行为 + 👁 | **技能钉选**：钉一个声明 `network: deny` 的技能 → 即使全局是 `allow`，联网动作也被拒（自检组 `73-net-policy`）。界面在「对话设置 → 技能」 |

## 怎么跑

- **断言部分**：`npm test`（内核自检，2500+ 项）、`npm run test:unit`（前端，660+ 项）
- **真机部分**：`npm run shot:electron`（CDP 驱动**打包版**，可带探针脚本）、
  `npm run acceptance`（真模型跑 5 类任务，按**产物**判成败）
- **每次发版的最低要求**：`npm run verify` 全绿 + 上表 👁 的项**至少抽一半**真的点一遍
  （改 UI / 会话 / 发送 / 权限时，相关的那几条**必点**）

> 补一条老实话：这张表过了**不等于**没问题 —— 它只等于「清单上的事都做了」。
> 真出问题的地方，往往在两张表都没写到的地方。
