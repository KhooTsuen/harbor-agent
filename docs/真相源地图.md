# 真相源地图（契约登记 + 重复候选）

> **这是什么**：回答一个问题的工具箱 —— **「同一个事实，在几个地方被定义？」**
> 它由两部分组成，一正一反：
> - **正面（Q1）**：`npm run contracts` —— 已登记的契约：谁是真值、谁必须跟它一致、有没有自检钉住。
> - **反面（Q2 的候选）**：`npm run dup` —— 还没登记的重复**候选**，**只报告、永不拦门**。
>
> 起因与判据见 [`research/truth-map-design.md`](research/truth-map-design.md)；
> 原始清单来自 [`Architecture Reality Audit.md`](Architecture%20Reality%20Audit.md) §3 / §4。
> 想知道「有多大 / 谁引用谁」看 [`项目地图.md`](项目地图.md)（那是 B，本文是 C）。

## 一、先说清：两个问题，别混在一起

| | 问题 | 能不能机械判定 |
|---|---|---|
| **Q1** | 这个约定，真值在哪个文件？谁必须跟它一致？有没有自检钉它？ | ✅ 能 → `npm run contracts` |
| **Q2** | 这两处，是不是在说**同一件事**？ | ❌ 不能 → 只能出候选给人判 |

**Q2 判不了的证据（仓库里现成的反例）**：

- `level` 在 `risk.cjs` 是「危险度四级」、在 `scale.cjs` 是「要不要问三级」—— **同名不同义**。
- `keyOf` 在 `artifact.cjs` 与 `changeset.cjs` 各有一份 —— **看着一样，其实各管各的范围键**。

所以一条铁律：

> **机械可以「找候选」，不可以「下判决」。**
> 一个「扫到重复就报红」的闸，会把上面这些**合法差异**全变成假阳性，最后没人看它。

## 二、正面：契约登记表 `npm run contracts`

每个跨模块约定登记一行，五个字段：

| 字段 | 含义 |
|---|---|
| `sot` | 唯一真相源文件（真值所在） |
| `mirrors` | 必须与 `sot` 逐字一致的镜像（可空） |
| `pin` | 钉住它的自检组（`scripts/selftest/groups/<pin>.mjs`）；**`null` = 没钉（缺口）** |
| `driftConsequence` | 漂了会怎样：`不一致但报错`（有钉子兜） / `静默出错`（没钉子） / `只是冗余` |

- 清单定义在 [`../scripts/contracts.mjs`](../scripts/contracts.mjs) 的 `CONTRACTS`。
  **条数看命令输出，本文不背**（`AGENT.md` 硬约束 8：会涨的数字不写死）。
- 命令会**自检这张表本身**：`sot` / `mirrors` / 自检组路径真不存在就报红并退出码 1 —— **表自己也不能漂**。

## 三、反面：候选扫描器 `npm run dup`

扫 `src/` + `electron/` 里的**标识符样字符串字面量**（事件名 / 字段名 / 文件名），按出现文件数分组：

- **A 段**：跨 ≥3 个源文件出现 —— 高信号（工具名 `run_shell`、状态名 `waiting_user`、事件名 `agent.*`…）。
- **B 段**：恰好 2 文件、且是点分事件样名字，或碰到已登记契约文件 —— **第二份真值爱藏这**。

两条硬规矩：

- **永不拦门**：不进 `verify`、退出码恒为 0。它是**给人看的雷达**，不是闸门（理由见 §一）。
- 注释里提到过的另标「（注释里也提过）」—— 往往说明**有人已经认过这事**。

## 四、已知缺口（登记了、还没钉）

`npm run contracts` 里 `pin === null` 的条目就是缺口 —— 意思是
**那个约定漂了，没有任何自检会报红**。当前最典型的一个（设计稿 §5 的种子）：

```text
electron/core/decisions.cjs 的 3 个事件名
       （confirm_request / confirm.timeout / clarify.timeout）
  ↕ 与 electron/core/event-types.cjs 逐字重复
而 decisions.cjs 不 require event-types.cjs、也没有 emit({ → 自检 126 扫不到它
```

⇒ 这 3 个名字**改一处漏一处，没人报红**。修法（C2 第一条）：让 `decisions.cjs`
从 `event-types.cjs` 取这几个名字，而不是各写一份字面量。

## 五、怎么算「做完了」

- **C1（已做）**：`npm run contracts` 打出登记表；本文与它一致。
- **C3（已做）**：`npm run dup` 跑出的候选里，上面那个缺口的事件名**在结果里**（能被人一眼判定）。
- **C2（未做）**：逐条补钉 —— 每条一个自检组，**一条一条单独批准**
  （每条都可能暴露真漂移，要改代码、不是只加一个红的测试）。

## 六、明确不做

- ❌ 不合并「所有」重复 —— 大多数是**合法差异**（审计 §9.2 六条）。
- ❌ 不做大重构（改 `risk` / `scale` 结构、补 Run / Turn 实体）—— 那是别的立项。
- ❌ 不让候选扫描器进 `verify`、变成拦门的闸。
- ❌ 不按「文件数 / 模块数」判断健康度。
