## #8 browse 加提示（**只调研，等拍板**）

### 现状（读出来的事实）

- Agent 打开网页时，渲染层**已经**做了两件事（`src/components/layout/browser/useBrowseBridge.ts`）：
  1. `setActiveRightTab('browser')` —— 右侧面板会切到「浏览器」标签，**并且如果面板是折叠的会自动展开**
     （`setActiveRightTab` 里写着 `rightPanelVisible: true`）；
  2. `navigate` 动作还会弹一条 toast：`正在用浏览器读取网页 <url>`。
- **缺的是「读/点/打字」这三个动作**（`browse_elements` / `browse_click` / `browse_type`）：
  它们只切标签、**没有任何 toast**。也就是说「在已有的页面上操作」在界面上是静默的。
- 主进程侧有事件台账（`log-actions.cjs` 里有 `browser:result`），所以「下次真出现」时能翻日志。
- 系统通知那条通道是现成的（`handlers/notify.cjs`，它已经能区分「窗口没在前台 / 被盖住」）。

### 三个问题的回答

1. **怎么加？** 不建议「标签闪烁」。建议两件小事（都可验证、都不刷屏）：
   - 给「读/点/打字」补一条 toast，**按动作类型去重**（连续点 10 次只提示一次
     「正在操作网页：点击」，换动作类型再提示）；
   - 只加一个**静态角标**（浏览器标签上的小圆点）表示「Agent 正在这个标签里动网页」，
     不闪、可点。
2. **会不会骚扰？** 闪烁会：一个任务里 browse 十几次是常态（`browse` 是只读工具，不拦）。
   toast 若**每次调用都发**也会；按「动作类型变化才提示」+「一次任务最多一条系统通知」才不吵。
3. **是治本还是安慰剂？** **在复现不出原症状之前，任何提示都只是透明性改进，不能说治本。**
   但「读/点/打字零提示」是**可复现的具体缺口**，补它是真修（不是安慰剂）；
   而「加提示让用户知道 Agent 开了浏览器」这个原始诉求，本质是「用户没在看屏幕」——
   真正的解是**应用不在前台时发一条系统通知**（复用 `notify.cjs` 的前台判定），
   而不是在界面上闪。

### 建议的拍板项

- 选 A：只补「读/点/打字」的 toast（去重）+ 标签静态角标（小改动，可验证）。
- 选 B：A + 「应用不在前台时，一次任务最多一条系统通知」。
- 选 C：都先不做，只在 `log-actions` 里能查到（等下次真出现再抓现场）。

**我的建议是 A**（成本最低、不吵、能验证），B 作为可选加强。
