## 二、六块重点能力：覆盖到哪一层

层级定义（**别把后面三层混着说**）：

- **纯函数** —— 只 require 一个模块，喂数据看返回值
- **内核集成** —— 真 loop / 真工具 / 真落盘，**模型或外部服务被替换**
- **真进程 / 真界面** —— 真 Electron、真子进程、真注册表、真 DOM
- **未验证** —— 没有任何自动证据

| 能力 | 纯函数 | 内核集成 | 真进程 / 真界面 | 未验证 |
|---|---|---|---|---|
| Agent 任务执行与工具调用 | ✅ | ✅ `05-agent-loop`（真 loop + 真 tools + 真 task/changeset，`chatStream` 被换成 stub） | ✅ `e2e-fail-streak` / `e2e-tool-failure-visible`（真界面 → 真 loop → 真 shell → 真 DOM） | 真模型选工具是否合理（只有 `--acceptance` 花 token 才验） |
| C-1 敏感文件授权 | ✅ `205` / `206` | ✅ `205` 覆盖批准→读到、精确路径、父目录不继承、会话隔离、once 归属、续期 | ✅ `e2e-sensitive-grant`（真确认卡 → 脚本点「允许」 → 假上游第 2 个请求体里带着假密钥） | 多窗口 / 多会话并发点「允许」 |
| C-2 MCP 运行时约束 | ✅ `gate` 判据 | ✅ `204-mcp-runtime-gate`（**调用计数**为判据，不靠文案） | — | 真 MCP 服务器的行为差异（全部是假 MCP） |
| Memory 作用域 / 归属 / 去重 | ✅ | ✅ `207` / `208` + `security:memory` 的 SEC-057/060/061/062/065 | — | 真模型会不会滥用 `scope:'session'` |
| Native Host 与 Edge 扩展 | ✅ | ✅ `154`（**真子进程喂 3 帧、读回 3 帧**）、`156`/`157`/`160` | ✅ `155`/`202`（真读 fuse wire；真写注册表再还原） | **真 Edge 加载扩展后的端到端通话**；侧边栏人工点验 |
| 任务失败恢复 | ✅ | ✅ `22-recovery` / `25-autorecover` / `26-continue` / `191-tool-failure-fact` | ✅ `e2e-retry-rollback` | 断电 / 磁盘满（安全套件里只覆盖下载链） |

**共同的洞**：真机那一层全部**不在** `verify` / CI 里，靠人记得跑。

## 四、这条链自身的问题（本次核对发现）

### 1. 恒真断言 12 处，其中 1 处是真的没在验 —— **已修**

扫法：`check('…', true)` 全量筛。

- **真问题 1 处**：`04-reliability.mjs`「事务可以被清理」原来写 `check(…, true)`，
  `prune()` 的返回值和清理结果**根本没看** —— 删不掉也照样绿。
  现在钉成 `pruned.ok === true && pruned.removed >= 1 && get(cs.id) === null`
  （先用探针确认过 `prune(0)` 的实际返回是 `{ok:true,removed:1}`、之后 `get()` 读回 `null`）。
- **结构性合理的 11 处**：非 Windows 跳过分支（`50-path-encoding` ×3、`155` ×1）、
  「前面已经红了，这条只补信息」（`54-version-sync`）、
  「只验不抛异常」（`32-notify` ×2 —— 真的抛了整组会崩，所以不是假绿）、
  「喂给探针的**故意恒真输入**」（`112-probe` ×3，用来验证探针会把没交证据的判据降级）。

### 2. 门禁负例没人跑

`scripts/security/mutation/gate-negative.mjs` 是**门禁自己的测试**（合成报告喂真判据，
验证 8 类异常都被挡）。它不在 `verify`、不在 CI、也不在 `preflight` —— 也就是说
**门禁坏掉不会有任何东西报出来**。和 `test-rules.mjs` 要解决的是同一类问题，但那份接进去了，这份没有。

### 3. 真机 e2e 有脚本、没入口

`tools/e2e-*.mjs` 全部要人手动敲。它们是「CDP 能力可用」的活证明，也是
「测试全绿但功能废」那两次事故之后唯一的真机证据 —— 但没有任何机制提醒你跑。

### 4. `security:gate` 与 `security` 的口径不同，容易被当成同一个

`verify` 挂的 `security` 是**默认档**（有 FAIL 才非零，NOT_RUN 不挡）；
发布要求的**严格档**是 `security:gate`（P0 不许 FAIL / BLOCKED / NOT_RUN）。
`verify` 绿**不代表** `security:gate` 绿。发布前必须单独跑。

## 五、尚未被任何自动测试覆盖的真实场景

按「出了问题最难看」排序：

1. **真 Edge 里加载扩展 → 侧边栏真的能对话**：`154`/`156`/`157`/`160` 验的是协议与内核，
   `202` 验的是装得上；**「装上之后在真浏览器里点一下能用」没有任何自动证据**。
2. **真模型的行为质量**：所有自动测试的模型都是假的。工具选得对不对、话说不说得清，
   只有 `npm run preflight -- --acceptance`（花 token）能覆盖。
3. **多窗口 / 多会话并发授权**：`206` 有并发断言，但那是同进程内的并发；
   两个真窗口同时点「允许」没有验过。
4. **真 MCP 服务器**：全部用例用假 MCP（只验调用计数）。真实服务器的超时、重连、
   返回畸形数据都没验。
5. **断电 / 磁盘满**：只在下载链做过真注入；任务台账、会话文件、改动事务没做过。
6. **打包版升级 / 迁移**：`54-version-sync` 验版本号一致，但「旧版数据被新版读」没有自动化。

## 六、后续版本的最低回归标准

发版前**至少**跑完这些（缺一项就不算发得了）：

```bash
npm run preflight                 # verify（含内核自检 + 前端单测 + 安全默认档）+ 应用自检
npm run security:gate             # 严格档：P0 不许 FAIL / BLOCKED / NOT_RUN
```

改了下面这些，**额外**必须补：

| 改了 | 必须补 |
|---|---|
| `electron/core/tools/**`、`capability*`、`approval` | 真机走一遍授权链（`node tools/e2e-sensitive-grant.mjs`） |
| 工具结果形状 / 失败判定 | `node tools/e2e-tool-failure-visible.mjs` |
| 渲染层交互卡 / 选择器 | `node tools/e2e-clarify-card.mjs`（它自己会点卡） |
| 扩展 / Native Host | `node tools/e2e-*` 里与扩展相关的；再人工在 Edge 里点一次 |
| 失败恢复 / 重试 | `node tools/e2e-retry-rollback.mjs` |
| 并行 / 批量执行 | `node tools/e2e-fail-streak.mjs` |
| 任何 UI | 截图（`npm run shot:electron -- --dev`），别只看测试绿 |

> 一句话：**自动测试绿 + 至少一条真机链路走过**，才算这一版「验过」。
> 只跑 `verify` 就发版，等于把 CI 的覆盖范围当成产品的覆盖范围。

## 七、加一条新断言时

- 判据**优先用计数 / 行为**，别用文案：`204` 的教训是「只断言返回里有没有『拒绝』两个字，
  一个先拒了又照跑的实现照样全绿」。
- 别写 `check(name, true)`。真要表达「不抛异常」，就把可能抛的那句包起来并断言别的东西。
- 隔离数据一律走 `env.mjs` 的 `SANDBOX` / `paths.DIRS.data`（自检时是 `data/selftest-data`），
  **绝不**写 `join(ROOT, 'data', …)` —— 会落进用户真数据且不清理。
- 新组要在 `scripts/selftest/groups.mjs` 的 `GROUPS` 里注册。**没注册 = 没跑**，
  而「没跑」和「跑过了」在输出里长得一模一样。
