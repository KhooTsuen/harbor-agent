# 开发笔记（原 README）

> 这份是开发过程中攒下来的笔记 —— 配色怎么定的、玻璃拟态为什么默认关、
> 目录结构、工具系统与 Agent 循环的设计、踩过的坑、已知取舍。
> **对外介绍看根目录的 [README](../README.md)。**

本地优先的个人 AI Agent 工作台。数据、密钥、会话全部留在本机。

**技术栈**：Electron（主进程，管文件/命令/模型请求）+ React 18 + TypeScript（严格模式）+ Vite + Tailwind + Zustand + Framer Motion。

## 跑起来

```bash
npm install
npm run dev        # 起 Vite + Electron（热更新）
npm run build      # 类型检查 + 构建渲染层
npm start          # 直接跑 Electron（用已构建的 dist/）
npm run dev:web    # 只起浏览器 UI 预览（不具备桌面文件/终端/模型能力）
```

### 为什么要有 Electron

浏览器**读不了本地文件、跑不了命令**。要做真功能就必须有 Node 侧，
所以主进程负责工具执行和模型请求，渲染层只管画界面。

### 两种运行环境

| | Electron | 浏览器（`dev:web`） |
|---|---|---|
| 配置存哪 | `data/config.json`（主进程） | localStorage |
| 对话回复 | 真实调用已配置的模型 | 仅 UI 预览，不调用模型 |
| 文件/命令 | 真实读写与执行 | 不可用 |

渲染层通过 `src/lib/backend.ts` 问一句 `isElectron` 就知道自己在哪，
**UI 代码两边完全共用**。

## 这套配色是怎么来的

**不是照设计规范抄的，是从截图里量出来的。**

2026-09-14 对 23 张同类 AI IDE 的界面截图做了 PIL 像素统计，结论有两条和"想当然"不一样：

| | 常见想象 | **实测** |
|---|---|---|
| 底色 | 带蓝味的深色（如 `#0E0F12`） | **中性近黑 `#101010`**（`#0e0e0e`~`#101010` 占 36%~73%） |
| 主按钮 | 品牌色底 | **白底黑字**（三张不同截图一致） |
| 焦点色 | 亮蓝 `#2B8FFF` | **蓝紫 `#6b7cf7`**，且**用得极少** |

核心结论：**这类界面的辨识度不在"用什么蓝"，而在"几乎不用彩色"** —— 按钮靠白、层级靠灰阶、彩色只出现在焦点环和品牌位。

### 两套主题并存

界面上可以切换，方便对照：

- **`default`** —— 实测值（默认，旧版本里叫 `codex`，会自动迁移）
- **`spec`** —— 需求文档给的色板（`#0E0F12` / `#2B8FFF` / `#10A37F` …）
- **`light`** —— 亮色
- **`system`** —— 跟随系统

切换只改 `<html data-theme="...">`，CSS 变量跟着换，**不写两份样式**。

## 玻璃拟态：默认关闭

需求文档要求给侧边栏、Composer、设置弹窗、菜单、顶部栏都加毛玻璃。**我把它实现出来了，但默认关着**，原因是：

- 抓到的 **11 篇官方文档**（含专门讲界面的 Appearance 设置页）**零次提到** blur / vibrancy / transparency
- **25 张截图的像素方差极小**——真有毛玻璃，透出底层内容会产生大量过渡色

在「设置 → 外观 → 玻璃拟态」里可以打开，效果会同时作用于 `.glass`（弹窗/菜单/Toast）和 `.glass-panel`（侧栏/顶栏/Composer）。

顺带做了三层回退：

```css
@supports not (backdrop-filter: blur(1px)) { ... }        /* 浏览器不支持 */
@media (prefers-reduced-transparency: reduce) { ... }     /* 系统要求减少透明 */
[data-glass='off'] ...                                    /* 应用内开关 */
```

## 字体

`public/fonts/` 里放了三个 woff2（共 78 KB），**随项目走，不依赖系统装没装、也不依赖外网**：

- **Inter**（可变字体 100–900）→ 界面与正文
- **IBM Plex Mono** 400 / 500 → 代码、终端

中文字符由 Inter 之后的系统字体兜底。

## 功能清单

- **三栏布局**：可拖拽调宽（`ResizeHandle` 支持键盘 ←→）、侧栏可折叠成 48px 图标条
- **对话**：用户消息右对齐气泡 / 助手消息左对齐无气泡；流式打字机；出错可重试
- **Markdown 渲染**：自己写的解析器（不用 `innerHTML`）。支持标题、粗体/斜体/删除线、
  行内代码、链接（含裸 URL 自动链接）、图片、引用（可嵌套）、有序/无序列表（可嵌套）、
  任务列表、**表格（含对齐）**、分隔线、反斜杠转义、硬换行、代码块元信息
  （` ```ts title="a.ts" {1,3-5} ` → 文件名 + 行强调）
- **代码块**：32 种语言语法高亮（自己写的分词器，不用 `dangerouslySetInnerHTML`）、
  语言显示名、**超 40 行自动折叠**、**下载成文件**、复制、行号开关、
  自动换行、行强调、diff 整行底色（diff 时自动关行号）
- **真实 Agent 回复**：Electron 通过 OpenAI 兼容接口流式输出，并可调用文件、终端、搜索、记忆和 MCP 工具；浏览器预览才会使用静态回复
- **Diff 审查**：文件可折叠、行号、`+n −n` 统计、增删行整行底色
- **终端**：**真 PTY + xterm**。挂一个真的伪终端，键盘输入、彩色输出、
  全屏程序（vim / top / python REPL）都能跑。「重新启动」和「清屏」在标签栏，
  切到别的标签不会杀会话（回来还在）
- **预览终端**（仅限浏览器预览）：没有后端时用一组固定回应，不碰本机文件
- **文件树**：按扩展名换图标、按文件名过滤、点开在右侧预览
- **侧栏分两栏**：上半是**对话文件夹**（一个工作目录一个文件夹，可以有多个）；
  下半是**单独对话**（不挂目录也能聊）。中间那条分隔线可上下拖，
  键盘 ↑↓ 也能调，带像素级限位
- **每条对话自己的目录**：发消息、顶栏、输入框底部都按这条对话的目录走；
  目录不在（拔了 U 盘、换了机器）会自动回落到默认工作目录
- **并行线程**：侧栏多线程 + 状态点（空闲/执行中/完成/失败/等待）+ 底部「任务」面板监工
- **记忆**：`data/memory.md` 附在每轮系统提示里，模型可用 `remember` 工具主动记，设置有编辑页
- **联网搜索**：四个后端，模型可用 `search_web` 工具
- **技能**：`SKILL.md` 扫描，按触发条件注入
- **MCP**：外部服务器连接，工具按写操作处理
- **场景模型**：八个场景（对话/标题/优化/翻译/建议/压缩/OCR/画图）可各配模型
- **上下文压缩**：手动 `/compact`、40% 提示、60% 后台自动压
- **诊断包**：一键导出配置+日志+会话结构（密钥打码），排查问题用
- **设置**：13 个页 —— 通用 / 外观 / 快捷键 / 模型与提示词 / 模型 / 工具 / **安全** /
  技能 / 记忆 / 扩展 / 用量 / 数据 / 关于
- **安全边界**：文件默认只能动工作目录（出去要授权、敏感文件单独批）；
  Shell 按行为分四级（危急直接拦）；MCP 默认不继承环境变量；
  审计日志记录每次工具调用（参数自动脱敏）；API Key 存在系统加密的凭证库里，
  **不写进 config.json**。详见 `docs/安全模型.md`
- **任务可恢复**：一次 Agent 运行 = 一条任务 + 一个文件改动事务（ChangeSet）。
  关掉程序再打开会提示「有条任务没干完，继续吗」；改错了能**整批撤销**
- **记忆**：结构化（类型 / 范围 / 来源 / 置信度），按相关性注入而不是整篇塞；
  冲突时新的取代旧的但保留历史；含密钥的内容拒绝入库
- **模型路由与降级**：可选按任务类型换模型；失败按错误类型重试（退避）或换供应商，
  换之前会明确告知
- **权限确认**：删除线程、重置数据等危险操作弹窗
- **Toast**：四种语义，右下角堆叠，自动消失
- **空状态**：无插画，用「标题 + 描述 + 建议按钮」

## 可访问性

- 所有交互元素可 Tab 聚焦，统一 `:focus-visible` 焦点环
- 按钮有 `aria-label`；弹窗 `role="dialog"` + `aria-modal` + `aria-labelledby`
- Switch 用 `role="switch"` + `aria-checked`
- 拖拽手柄是 `role="separator"` + `aria-valuenow`
- `prefers-reduced-motion` 全量关闭动效
- 玻璃拟态有 `prefers-reduced-transparency` 回退

## 工具系统

模型能调用这 7 个内置工具（MCP 服务器还会动态追加）：

| 工具 | 权限 | 说明 |
|---|---|---|
| `read_file` | 读 | 带行号返回，支持 offset/limit |
| `list_dir` | 读 | 默认一层，可递归到 4 层；`node_modules`/`.git`/`dist` 自动跳过 |
| `write_file` | **写** | 新建或整篇覆盖，父目录自动建 |
| `edit_file` | **写** | 精确替换，**oldText 必须唯一**，否则拒绝执行 |
| `run_shell` | **写** | 有超时、输出截断，**危险命令直接拦**（`rm -rf /`、`format`、fork bomb 等 11 类） |
| `search_web` | 读 | 四个后端可切（设置 → 工具） |
| `remember` | **写** | 往 `data/memory.md` 记一条；**算写操作** —— 记忆影响之后所有对话，记错比改错文件影响更久 |

**权限三档**（设置 → 工具）：

- **只读** —— 写操作直接拒绝，只能用 read/list
- **需要确认** —— 每次写操作弹窗问你（默认）
- **完全访问** —— 不打断

`edit_file` 那条「必须唯一」是从踩坑来的：允许「替换第一处」的话，模型改错位置你完全看不出来。
找不到或匹配多处时，它会返回**可能的位置**帮模型自己纠正。

## Agent 循环

```
调模型 → 模型要工具 → 执行 → 结果喂回去 → 再调模型 → … → 不再要工具
```

两层边界：最多 **25 轮**（防止工具连环调用烧 token）、`AbortSignal` 全程可中断
（包括正在跑的 shell 子进程）。

## 自测

```bash
npm test                      # 内核自测（不联网、不需要 Electron）
npm run test:unit             # 前端单元测试（vitest）
npm run test:app              # 无窗口跑一遍，打印主进程 + 渲染层真实状态
npm run pty:check             # 验 node-pty：纯 Node 和 Electron ABI 都要过
npm run build                 # tsc --noEmit + vite build，类型零容忍
npm run shot                  # 截浏览器预览（自己起 headless Chrome，会执行 JS 再截）
npm run shot:electron         # 截**桌面版**（真 PTY、托盘那类只有 Electron 才有的）
npm run package               # 打成便携版 exe
```

**每一项跑了多少条不写在这里** —— 数字写下来就会漂（这份文档漂过一次）。
看命令自己的输出。

`npm test`（内核）覆盖：路径审计、配置校验（脏数据纠正/夹取）、会话 JSONL 读写、
会话的目录分组、7 个工具的行为、权限三档的拦截、**风险分级**、
**路径授权与越权拦截**、**全局脱敏**、**凭证库不落明文**、**审计记录**、
**任务与检查点**、**改动事务与回滚**、**错误分类与重试判定**、
结构化记忆（含冲突与检索）、模型路由、项目说明、搜索后端与格式化、MCP 边界、
以及**一轮完整的 Agent 循环**（把模型换成桩，真的跑一遍「发一句话」）。

`npm run test:unit`（前端）覆盖：Markdown 解析、语法高亮（含「拼回原文不丢字符」
这种整体性断言）、Markdown 渲染（用 `renderToStaticMarkup` 真渲染成 HTML 再断言）、
导出/导入、字体、配置映射。

`test:app` 会输出：数据目录是否都在 C 盘外、preload 桥是否可用、字体有没有真的加载、
React 有没有渲染出来、会话文件能不能真的写出去、**真 PTY 能不能开起来并回显**。
**光看构建通过说明不了这些。**

`pty:check` 单独验原生模块，两种 ABI 都要试：

```bash
node scripts/pty-check.cjs                                # 纯 Node（ABI 137）
ELECTRON_RUN_AS_NODE=1 electron scripts/pty-check.cjs     # Electron（ABI 149）
```

两个都过才算能用 —— 只对着 Node 验的话，跑进 Electron 就是「装上了但用不了」。

## 模型接口

> 便携版和 Electron 桌面开发版都走真实后端。浏览器页面只保留 UI 预览，不应被当成完整 Agent 使用。

Electron 模式使用 `electron/core/llm.cjs` 调用 OpenAI 兼容的真实流式接口，并由 `electron/core/loop.cjs` 驱动工具循环。浏览器模式仅用于 UI 预览；只有 Vite 开发服务器显式设置 `VITE_USE_MOCK=1` 时才加载 `src/lib/mock/`，生产构建不会进入演示路径。两种模式共用同一套 UI。

## 踩过的坑

| 坑 | 现象 | 原因 |
|---|---|---|
| **`file://` 下的绝对路径** | Electron 里窗口一片空白，**没有任何报错** | Vite 默认把资源写成 `/assets/...`，在 `file://` 下会解析到磁盘根目录。要设 `base: './'` |
| **同上，字体也中招** | 界面字体退回系统默认 | CSS 里 `url('/fonts/...')` 同样是绝对路径。把字体挪进 `src/assets/` 用相对路径，交给 Vite 打包 |
| **npm 11 拦 postinstall** | 提示 `esbuild` 的 install.js 没跑 | 实际不影响（二进制已在包里），但看到警告会以为坏了。验证方法：`npx esbuild --version` |
| **npm 11 同样拦下了 node-pty 的安装脚本** | `require('node-pty')` 直接报找不到原生模块 | 这个**真影响**，不是警告。二进制没搬到位。手动跑 `node node_modules/node-pty/scripts/post-install.js`（`npm run pty:check` 能验出来） |
| **node-pty 杀会话时崩一个 helper 进程** | 控制台刷出 `AttachConsole failed` 和一整条堆栈 | 用 Windows 内置 conpty 时，`kill()` 会 fork 一个 helper 去枚举控制台进程；父进程本来就带着控制台时（从终端里跑 `npm start`）那个 helper 必挂。传 `useConptyDll: true` 走包内 DLL，整条路径就不存在了 —— 顺带子进程也真被杀了 |
| **原生模块装上了、但没进便携版** | 开发时终端好用，打包后「终端打不开」 | `dist/` 里只有前端 bundle，`require('node-pty')` 得在 `resources/app/node_modules` 找到它。`scripts/build-portable.mjs` 里单加了一步拷贝（且只拷一份平台预编译，30MB 而不是 64MB） |
| **切个标签就把终端会话杀了** | 去「审查」看一眼再回来，跑一半的 vim 没了 | 面板随标签卸载 → 组件卸载 → 清理函数里 `ptyStop`。改成 CSS 隐藏不卸载，重新可见时 `ResizeObserver` 会自然触发一次 `fit()` |
| **一批 edit 里一条不匹配就整批回滚** | 显示「Successfully replaced N blocks」，实际改动**全没了** | 改完必须重新读一遍文件确认，别信提示 |

## 已知取舍

- **安全边界是架构级的，但风险分级是启发式的**：`risk.cjs` 会漏（新工具、
  混淆写法）。它的作用是「把话说清楚、给用户一个确认点」，不是沙箱
- **MCP 网络策略不做强制拦截**：只有策略 + 审计，没有内核级限制
- **凭证在拿不到系统加密时会退化为明文**：设置页与诊断包都会**明确报出来**，
  不假装加密了
- **改动事务有上限**：超过 `maxFileBytes`/`maxFiles` 的文件不进快照，
  回滚时会被列在「没恢复成功」里 —— 不会假装全都能撤
- **浏览器 webview 没做隔离**：`sandbox: false` / `webviewTag: true` 保持原样
- **PTY 只带了 Windows x64 的预编译**：`node-pty` 本身支持 macOS / Linux，
  但打包时只拷了 `prebuilds/win32-x64`（另外几套 28MB，用不上）。要换平台跑，
  得在 `scripts/build-portable.mjs` 里把对应平台的预编译一起拷进去
- **终端一次只有一个会话**：右栏终端面板对应一个 PTY，没有分屏、没有多标签
  （真要用多终端，直接开系统终端更合适）
- **语音输入**：未实现，而且**没留接入位置**（全项目搜不到 mic 相关代码）。
  将来要做就是新增，不是“接上”
- **国际化**：未实现，且**配置里没有语言字段**。目前文案写死为简体中文，
  要改就是逐个组件抽 key
- **工具历史回放**：会话恢复时以安全的文本摘要回放工具名称、成败和部分输出，不伪造不同厂商的原生 tool-call 消息
- **虚拟列表**：消息超过 80 条时启用估算窗口；高度差异很大的消息可能产生轻微滚动位置误差
