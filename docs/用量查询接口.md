# 统一用量查询接口（给后续界面用）

> 真相源：`electron/core/usage-query.cjs`（口径）+ `electron/core/usage-ledger.cjs`（读盘）。
> 本文只写**怎么用**和**哪些数字不能瞎解读**。改接口先改那两个文件，再回来改这里。

## 调用方式

```js
// 通道：usage:query（入参白名单见 handlers/usage.cjs）
const { ok, result, error } = await window.harbor.usageQuery({
  from: 1790000000000,   // 可选，毫秒时间戳
  to:   1799999999999,   // 可选，含端点
  providerId: 'deepseek',
  model: 'deepseek-chat',
  taskId: 'task_xxx',
  sessionId: 'sess_xxx',
  entry: 'api',          // 'api' | 'cli'
  purpose: 'chat',       // chat | compact | scene | vision | prewarm | collab，或「（未标注）」
  includeEmptyDays: true // 热力图要
})
```

`ok:false` 时**不要**当成「0 次请求」渲染 —— 那是「查不出来」，两者在界面上必须长得不一样。

## 返回结构

```js
{
  semantics: { promptIncludesCache: true, completionIncludesReasoning: true,
               timezone: 'local', costIsProviderReported: true },
  scanned, matched,          // 账本总行数 / 命中筛选的行数
  totals: Bucket,
  byProvider / byModel / byProviderModel / byPurpose / byEntry / byTask / bySession: { [key]: Bucket },
  byDay: { 'YYYY-MM-DD': Bucket },
  days: Bucket[]             // 按天升序；includeEmptyDays 时有空白日
}
```

`byProviderModel` 的键是 `providerId + '\u0000' + model`，每个 bucket 里额外带
`providerId` / `model` 两个字段。**同名模型分属两家时只有这一个维度不混。**

### Bucket

```js
{
  requests, known, unknown, legacy,      // 四类请求数
  coverage,                              // known / requests，没有请求时是 null
  prompt, completion, total,             // token 合计（已知的行才加）
  cacheHit, cacheMiss, reasoning,        // 缓存与思考（**已含在上面的 prompt/completion 里**）
  cost,                                  // 服务商真给的金额；一条都没给 → null
  errors, aborted,
  fieldUnavailable: { prompt, completion, total, cacheHit, cacheMiss, reasoning, cost }
}
```

空白日（`empty: true`）的 `requests` 为 0、`coverage` 为 `null`。

## 解读规则（这几条写错了界面就会骗人）

1. **`total` 不是「一共花了多少」**，是「**已知的那些**请求合起来多少」。
   要说完整消耗得配 `coverage`：`本月 100 次请求，82 次拿到真实用量（覆盖率 82%），
   已知消耗 X token，剩下 18 次没有上报、真实总量未知。`
2. **`unknown > 0` 时不许显示「合计」**，只显示「已知合计」。
3. **`legacy > 0`** 说明有旧格式记录（采集口径还没定型时写的）。数值可信但来源不同，
   界面上要么标注「含历史记录」，要么过滤掉只显示新口径。
4. **`cacheHit` / `reasoning` 不要加到 `prompt` / `completion` 上**：前者已包含。
   `semantics.promptIncludesCache` 就是给界面判断这件事用的。
5. **`fieldUnavailable.x > 0`** 表示「有 N 条没这个字段」（比如那家不给缓存信息），
   显示命中率时要说「N 条无数据」，不能把缺失当 0 算进分母。
6. **`cost === null` 不是「免费」**，是「服务商没告诉我们金额」。
   想显示预估费用就用定价表另算，并且**标明是估算**。

## 热力图

```js
const r = await query({ from, to, includeEmptyDays: true })
r.days.forEach((d) => {
  if (d.empty) paint(d.day, 0 /* 这天没调用 */)
  else if (d.known === 0) paint(d.day, 'unknown' /* 有调用但没用量 */)
  else paint(d.day, d.total)
})
```

**「这天没调用」和「有调用但没拿到用量」必须用不同颜色**，否则「静默为零」会把
「这家中转不给 usage」伪装成「你没用过」。

日期按**本机本地时区**归日（`new Date(at)` 取本地年月日），和用户在日历上看到的一致。

## 和老接口的关系

| 数据源 | 现状 | 什么时候换 |
|---|---|---|
| `stats.json` + `stats:summary` | **仍在用**（设置页「用量」标签读它） | 设置工作区那轮换成 `usage:query` |
| `turn_start.input`（`ContextGauge`） | **仍在用**（那是**估算**，不是真实用量） | 同上；换的时候注意别把估算标成真实 |
| `token-metrics.summarize` | 仍在，已被 `usage-query` 覆盖（数字逐项一致，组 226 ⑱ 钉住） | 可以逐步不再被新代码调用 |

两套并存期间**必须标明**：`stats.json` 那套是老口径（没有「未知」这个概念，失败的行根本不在里面），
`usage:query` 才是「每一次真发出去的请求都有账」。
