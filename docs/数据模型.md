# 数据模型

> 回答一个问题：**磁盘上都有什么、谁指向谁、字段什么意思。**
>
> 想先看「这些词是什么」看 [`核心概念.md`](核心概念.md)；想看状态怎么流转看 [`Runtime状态机.md`](Runtime状态机.md)；
> 想升级/搬数据看 [`更新与数据迁移.md`](更新与数据迁移.md)。
>
> 规矩：**这份文档只描述现状，不发明格式。** 字段以代码为准（每节都写了在哪），
> 改了字段就回来改这里 —— 否则它就成了下一份过期的文档。

## 一览

| 实体 | 落盘位置 | 代码 | 生命周期 |
|---|---|---|---|
| 会话（对话） | `data/sessions/<id>.jsonl` | `core/session*.cjs` | 用户新建 → 归档/删除 |
| 任务（一件活） | `data/tasks/<id>.json` | `core/task*.cjs` | 建 → 跑/暂停/恢复 → 完成/失败/放弃 |
| 任务索引 | `data/tasks/_index.json` | `core/task-index.cjs` | 只是个**加速表**，不是真相源，坏了自动重建 |
| 改动事务 | `data/changesets/<id>/`（`meta.json` + `files/*.snap`） | `core/changeset.cjs` | 第一次写文件时开 → 结束/整批撤 |
| 检查点 | 任务里的 `checkpoints[]`（**没有独立文件**） | `core/task-notes.cjs` | 跟着任务，最多留 50 条 |
| 成果（Artifact） | `data/artifacts/<id>/`（`meta.json` + `v1.md`/`v2.md`…） | `core/artifact.cjs` | 每变一次追加一版，最多 50 版 / 2MB |
| 记忆 | `data/memory.json`（+ `memory.md` 可读版） | `core/memory*.cjs` | 记 → 被新条目取代（`supersededBy`），不删 |
| 技能 | `data/skills/<id>/SKILL.md` | `core/skills.cjs` | 手写目录，应用只读它 |
| 项目 | `data/projects.json` | `core/projects.cjs` | 首次见到工作目录时自动登记 |
| 路径授权 | `data/capabilities.json` | `core/capability.cjs` | 一次性 / 本会话 / 永久 |
| 审批记录 | `data/audit/`、`core/tools/approval.cjs` | `core/tools/approval.cjs` | 追加式，可撤销的是**永久**那几条 |
| 配置 | `data/config.json` | `core/config.cjs` | 每次改都写；坏了从备份起 |
| 凭据 | `data/credentials.json`（safeStorage 加密） | `core/credentials.cjs` | 只存密文，**永不进 config / 日志 / 导出** |
| 审计 / 事件 / 日志 | `data/audit/`、`data/events/`、`data/logs/` | `core/audit.cjs`、`core/events.cjs`、`core/log.cjs` | 按天切，按大小轮转 |

## 谁指向谁

```mermaid
graph LR
  P[项目 projects.json] -->|projectId| S[会话 sessions/*.jsonl]
  P -->|projectId| T[任务 tasks/*.json]
  S -->|sessionId| T
  T -->|checkpoints[].changeSetId<br/>changeSetId| C[改动事务 changesets/]
  T -->|taskId / sessionId| A[成果 artifacts/]
  T -->|steps[]| U[工具调用<br/>（不是独立实体）]
  T -->|permissions[]| K[路径授权 capabilities.json]
```

**两条重要的事实**（体检就是照它们查的）：

- **删任务只删任务文件**（`task-io.remove`）。改动事务、成果**都留着** ——
  所以「事务的任务不在了」是正常现象（`npm run doctor` 把它算 `提示`，不算 `对不上`）。
- **删对话会把这条对话的任务一起删**（`task:purge` → `task.removeBySession`），
  但**不会**删它产生过的成果。

## 任务（`data/tasks/<id>.json`）

一个任务一个文件 —— 坏一个只坏一个。字段分五组（默认值都在 `core/task-create.cjs`）：

**身份**：`id` · `title`（从目标里提炼的动作名，模型在计划块里写 `# 名字` 会覆盖）·
`goal`（用户原话）· `mode` · `sessionId` · `projectId` · `workdir`

**计划与进度**：`plan[]` · `planVersions[]`（改过的计划留着）· `turns`（调了几次模型）

**发生过的事**：`steps[]`（见下）· `checkpoints[]` · `changedFiles[]` · `commands[]` ·
`changeSetId` · `result`（最终正文）

**停下来/怎么再继续**：`status`（六种）· `pauseReason`（`budget` / `loop` / `interrupted` /
空）· `pauseDetail` · `budgetHit` · `loopHit` · `nextAction` · `pausedAt` · `resumeCount` ·
`permissions[]`（这次会话里批过的路径）

**用量与来路**：`tokens` · `tokensIn` / `tokensOut` · `retries` · `toolStats` ·
`model` / `models[]`（中途换过模型时看这个）· `budget` · `promptVersion` / `promptVersions[]` ·
`steering[]`（执行中改方向的记录）· `errors[]`（`{at, message}`）· `promptDiag`

**重新生成**：`regeneratedFrom`（重做的是哪条）· `budgetCarry`（用量基线，预算不重置）·
`supersededBy`（被哪条替代了）

> ⚠️ **`steps[]` 里一次工具调用留两条记录**，不是一条：
> 一条是「意图 + 结果」（带 `intent` / `completed` / `outcome`，见 `core/task-intent.cjs`），
> 一条是带参数的流水（带 `args`）。所以统计调用次数时要**二选一**，
> 两条都数就翻倍 —— `core/run-stats.cjs` 里就是这么处理的。

## 会话（`data/sessions/<id>.jsonl`）

一行一条 JSON，**追加式**写（中途崩了只丢最后一行）。

- **第一行永远是 `meta`**：`{type:'meta', id, title, mode, model, reasoning?, workdir, projectId?, threadSettings?, createdAt}`
- 之后是事件：消息、工具调用、压缩点、会话状态（`core/session-write.cjs`）
- 消息行带 `role` / `content`（字符串**或**多模态数组）/ `reasoning` / 图片 / 分轮信息
- 加密开着时每行是 `e1:<base64>`（`core/session-crypto.cjs`），密钥由系统 safeStorage 派生
  —— **密钥绑当前 Windows 账户**，把 `data/` 拷到别的机器那些行读不出来（会跳过并计数，不静默丢）

> ⚠️ 改消息形状时**两边都要改**：落盘侧（`session-write.cjs`）+ 读回侧
> （`src/stores/app/disk.ts` 的 `storedToUi`）。已经栽过两次：`images`（2026-09-28）、
> `reasoning`（2026-09-30，重开会话思考块整块消失）。

## 改动事务（`data/changesets/<id>/`）

- `meta.json`：`{id, taskId, sessionId, title, status, startedAt, finishedAt, files[], supersededBy}`
- `files[]` 每项：`{path, existed, size, snap}` —— `snap` 是**写之前的原文**快照（`files/<n>.snap`）
- 规矩：**写文件之前先留快照**；`existed: false` 表示这个文件当时还不存在（撤销时删掉即可）

## 成果（`data/artifacts/<id>/`）

- `meta.json`：`{schemaVersion, id, type, name, path, taskId, sessionId, threadId?, sourceMessageId,
  createdAt, updatedAt, latest, versions[]}`
- `versions[]` 每项：`{version, bytes, createdAt}`，正文**外置**在 `vN.md`（几十 KB 的报告不进内存）
- 三条规矩：append-only、同一 `(范围, name, path)` 视为同一个成果的新版本、内容没变不加版本
- 边界：**不与改动事务抢活** —— 「磁盘上哪些文件被改了、怎么整批撤」归 changeset；
  「这份成果长什么样、改过几版」归这里。这里不做 diff / 合并。

## 记忆（`data/memory.json`）

条目形状见 `core/memory-schema.cjs`：`id` · `type`（偏好/事实/流程/项目规矩/约束…）·
`scope`（`global` / `project` / `workspace` / `task` / `session`）· `text` ·
`source`（`user_explicit` / `model_suggested` …）· `confidence` · `importance` ·
`createdAt` · `supersededBy`（被哪条取代 —— **保留历史，但不再注入**）

## 改数据结构的规矩（硬约束 #5）

1. **必须写迁移**，且**保留旧数据**（不就地删）
2. **新字段要有默认值**，老文件缺它就按默认走（`task-io` / `artifact` 都是这个套路：
   读的时候兜底，不批量回写几千个文件）
3. **拿旧数据文件实测启动一次**才算验过
4. 改完回来改**这份文档**（上面每节末尾的字段表就是给下一次改的人看的）

## 出问题了先体检

```bash
npm run doctor            # 扫 data/：悬空引用、坏 JSON、缺文件、索引漂移
npm run doctor -- E:/Harbor
```

它**只报告，不修**。判断「哪些是删东西留下的正常垃圾、哪些是真对不上」的分级说明
写在 `electron/core/data-doctor.cjs` 的文件头。
