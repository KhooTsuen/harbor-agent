# 写验证脚本的检查清单

> ⚠️ **清单可参考，例子已过期**（2026-10-06 标注）：正文里的例子脚本（`tmp/*.mjs`、随手写的探针）
> **多数已不在仓库** —— `tmp/` 有卫生检查（条数 / 体积超限会被清）。要写验证脚本，
> 优先用仓库里的入口（`package.json` 的 `scripts`）。

> 给**临时验证脚本**（`tmp/*.mjs`、随手写的探针、清理脚本）用的。
> 正式验收脚本（`tools/acceptance*.mjs`）另有一套：三态判据 + 观测护栏 + 反向用例 + 前置检查，
> 见 `docs/判据自检.md`。
>
> **为什么临时脚本也要看这个**：它是一次性的，但**它得出的结论照样会被当成事实**写进报告、
> 拿去做决定。这个月 10+ 次假结论全部出自这一层。骨架在 `tools/probe.mjs`。

## 用骨架（三件事默认就做了）

```js
import { probe } from '../tools/probe.mjs'
const p = probe('这次要验什么：一句话')
p.ready('前置：安装版存在', existsSync(EXE), '先跑 npm run package')
p.requireReady() // 前置不成立 → 退出 2，不产出任何结论
p.check('版本是 1.21.0', text.includes('1.21.0'), `页面文本=${text.slice(0, 120)}`)
p.finish() // 最后一行；有 fail 或 unknown 都非 0
```

它替你做的：**没交证据的判据自动降级 `unknown`**、前置不成立就拒绝开跑、
漏 `await` / 未捕获异常 / 忘了 `finish()` 都会让退出码非 0。

## 八条检查项（每条都对应一个真实踩过的坑）

1. **期望值是哪来的？**
   别凭记忆敲常量。优先「用另一种方式现取一份」（读源文件 / 查线上 / 数一遍），
   敲死的常量必须在脚本里注明出处。→ 坑：探针期望值写错，于是「功能坏了」和「判据写错了」
   长得一模一样。

2. **你采样的那个点，是不是被测对象？**
   凡是「我先点了/改了，再断言」的，断言的是**操作之后**的状态。
   → 坑：测试自己把颜色改掉了，然后断言「应该是原色」，红得莫名其妙。

3. **判据不许返回 `undefined`。**
   `if (x === 'a') return true` 漏了 `else` → 恒 `undefined`。交给骨架的 `check`，
   它会把它判成**不成立**（而不是悄悄当 ✅）。

4. **别手写「要执行的代码」字符串。**
   模板串里 `\n` 变真换行 → `SyntaxError: Invalid or unexpected token`。
   → 用 `p.js(fn, ...args)` 传**真函数**，转义交给 `JSON.stringify`。

5. **注释里别塞反引号**（同上一条的另一种死法：提前截断模板串，后半段变成代码）。
   走 `p.js(fn)` 就完全不存在这个问题。

6. **清理 / 杀进程脚本：按 PID 或自己的标记来，别按命令行子串匹配。**
   → 坑：脚本把自己（或自己所在的那条命令行）匹配进去了。跑之前先打印「将要对谁做这件事」，
   并默认 dry-run，核对过再 `--apply`。

7. **先确认产物真实存在、扩展名对。**
   会话是 `.jsonl`，不是 `.json`；任务台账才是 `.json`。路径写错了照样返回「空」——
   而「空」和「没有」在脚本里长得一样。→ 任何「找不到」的结论，都要先证明**路径是对的**
   （`ls` 一次、打印目录前几条）。

8. **对照两段文本前先归一化。**
   去掉 markdown 记号（`` ` ``、`**`）、折叠空白、统一换行，再逐行比。
   → 坑：没剥反引号，报了「不一致」；剥完发现一字不差。

## 两条纪律

- **`unknown` 不是 ✅。** 观测不到就写 `unknown`（`p.unknown('观测不到的原因', '看到的证据')`），
  退出码非 0，让人一眼看见「这儿没验成」。
- **先让它红一次。** 写好的判据，拿一个「肯定不成立」的输入喂一遍，确认它真的会红。
  能通过不算测试，能失败才算。
