## [2026-10-03 13:2x] 第 0 批：调研（只写方案，不写论文）

### 缺口 A：测试脚本自身的可靠性

- 现状：`tools/acceptance-verdict.mjs` 已有三态判据 + 证据必填 + 观测护栏，`acceptance-report.mjs`
  已有「前置不成立就拒绝开跑」，自检 `106-acceptance-verdicts` 已有反向用例。**但这套只服务
  正式验收脚本**；临时脚本（`tmp/*.cjs`）没有任何护栏，而它的结论照样被当成事实写进报告。
- 区别的本质：正式脚本是**长期资产**（有人 review、有 CI、坏了会修）；临时脚本是**一次性的**，
  但**出错代价一样**（假结论 → 错误决定），防护却是零。所以缺的不是能力，是**入口**。
- 方案：加一个极薄的骨架 `tools/probe.mjs`（复用 `acceptance-verdict.mjs`，不重写判据）：
  证据为空 → **自动降级 unknown**（专治「判据恒 undefined → 假绿」）；`ready()` 前置不成立就
  拒绝开跑；`spike()` 是**框架自测**（拿肯定不过的输入喂它，断言它会红）；`js(fn)` 把真函数
  序列化注入，从根上消掉「模板串漏 return / `\n` 变真换行 / 注释带反引号」三类坑。
  再配一份 `docs/验证脚本检查清单.md`（8 条真实坑 → 8 条可对照的检查项）。
- 风险：又长出一个「框架」。→ 约束：一个 mjs（≤200 行）+ 一份文档，不碰验收链。
- 需要拍板：无（最小改动，随时可删）。

### 缺口 B：自动化测试不是默认动作

- 现状：`workspace-summary.cjs` 已经能识别测试入口（`npm test` / `cargo test` / `go test`），
  但它只用在**开屏总览**上；「先建最小验证」全凭模型记得。
- 不同：改 Harbor 自己有现成 verify 链（缺的是「去跑」）；做新项目**没有测试入口**
  （缺的是「先建一个能一条命令跑起来的最小用例」）。所以两件事要给**两种**提示。
- 方案：新 `verify-hint.cjs`，按「有没有测试入口」二选一出话；只挂在**新活第一轮**
  （`task-context` 的 fresh 分支）——不是每轮都喊，否则就是噪音。可检查性：自检直接断言
  「无入口时含『先建最小验证』、有入口时给命令且**不含**那句话」，并断言**有台账时不注入**。
- 风险：提示词变成说教 → 用「只在第一轮 + 两种口径」压住；字数上限写死在文件头。
- 需要拍板：无。

### 缺口 C：长任务上下文断层（最值钱的一条）

- 现状：`task-context.cjs` 已经注入了「任务台账」（计划 / 最近一步 / 已改文件 / 停手后文件又变过），
  但那只覆盖**立了任务的活**；「这个目录是什么、测试怎么跑、有哪些顶层模块」这类
  **项目级事实**每轮都不在，被裁剪后模型只能重新侦察。
- 关键洞见：裁剪丢的是**对话里的探索结果**；如果把它变成「**从磁盘再算一次就能得到**」的东西，
  就不怕丢。所以**不新建存储**，做一层**派生视图**即可。
- 方案：新 `project-facts.cjs`：浅层扫工作目录（复用 `workspace-summary` 的技术栈/测试命令识别），
  产出一段 ≤900 字符的事实块，**每轮重算**（天然不过期）；进程内记上一轮的值，变了就显式写
  「⚠ 与上一轮相比变了：测试命令 无 → npm test」。挂在 `project.buildPromptSection` 那个出口
  （和 AGENT.md 同层，层顺序不动）。
- 和 memory.json 的关系：**不写盘、不进记忆** —— 它是「现状」，不是「记忆」；写进去反而会和
  用户能编辑的记忆混在一起、还要处理失效与去重。
- 风险：多一次浅层 IO（≤10 次 stat，已有「单文件 ≤64KB」同级标准）；事实块可能和模型记忆冲突
  → 块尾写死「以本轮扫描为准」。
- 需要拍板：无（不新增字段、不新增状态、不新增 IPC）。

### 缺口 D：Hindsight 的 Reflect 雏形

- 现状：`memory-recall.cjs` 的 `retrieve()` 是 **Recall** —— 逐条取回、按分数排序、原样注入。
- 本质区别：Recall 交**条目**（模型自己综合）；Reflect 交**综合结论**（跨条目归并、说明出处）。
  最小可行版**不需要额外模型调用**：按 type 归组 + 关键词命中筛选 + 模板成句，就是雏形。
- 方案：新 `memory-reflect.cjs`：`reflect({ query, projectId })` 只取
  `constraint / workflow / decision / habit / project_rule` 且分数达阈值的前 3 条，
  输出一段 ≤400 字符的「这类活以前踩过什么坑」，每条带记忆序号（可追溯）。
  挂**新任务第一轮**（和缺口 B 同一个位置），没有命中就返回空串（不注入空标题）。
- 和缺口 C 的关系：**不是同一层**。C 是「磁盘现状」（客观、可重算、无历史）；D 是「历史经验」
  （主观、不可重算、要积累）。两者正交，所以分两个文件、两段文字。
- 风险：无关记忆干扰当前任务（`memory-recall.cjs` 文件头已经写过这个坑）→ 用阈值 + 只第一轮 + 条数上限压住。
- 需要拍板：无。
