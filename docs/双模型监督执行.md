# 双模型监督执行

双模型是用户主动选择的可选模式，默认仍为单模型。本功能对应原待办清单 **5、6**，没有改动原清单编号。

## 入口与角色

在“模型与服务商 → 双模型协作”开启功能并配置协作预算，在当前对话选择“双模型”和两个具体连接、模型。A 是指导模型，负责理解目标、分派、检查和交付；B 是工作模型，负责检索、创作或开发执行。两种角色均支持现有的 OpenAI 兼容 API 与 Codex CLI 路径。

角色绑定所选连接与模型，不在阶段之间偷偷切换供应商或降级。连接失效、凭据缺失、工作目录无效时明确停止。Codex CLI 作为 B 需要已启用的 Harbor MCP 桥；开发任务另需工具桥已有的写入开关。找到 CLI 不代表登录和模型调用已经验证成功。

## 一次协作怎样运行

1. A 按用户原始目标形成结构化计划：任务类别、目标、范围、执行步骤、预期成果和检查标准。
2. B 根据计划执行，保留实际工具调用、输出、失败、未知结果和阶段成果。
3. A 对照标准检查 B 的成果与真实证据，并给出检查结论。
4. `NEEDS_CHANGES` 时，A 的具体补充要求连同前轮成果交回 B，在预算内自动开始下一轮；`BLOCKED` 时保留成果并停止；`PASS` 时由 A 整理用户真正需要的完整答案。
5. 达到轮数、时长或已报告 Token 上限，或者连续返工没有新进展时，保留记录并说明未完成。取消和明确拒绝继续传递给当前执行方，不通过换角色重试来绕过。

普通内部交接不增加一次“先批准整个计划”的弹窗。需要用户选择、缺少授权或现有工具要求审批时，仍使用原确认通道。正文交付 A 的成果，计划、逐轮补充要求、B 的摘要、工具记录和预算信息放在可折叠的协作记录里。

## 按任务类别验收

| 类别 | 检查内容 | 不应被误设的前提 |
|---|---|---|
| `research` 资料检索 | 实际搜索或读取记录、来源、时效与覆盖范围；有网页资料时，答复至少包含能对应实际记录的来源链接。 | 无需文件修改或项目测试。搜索摘要不代表已阅读全文，记录到来源也不代表其结论可信。 |
| `writing` 写作创作 | 是否回应内容、风格和格式要求；涉及外部事实仍需相应依据。 | 无需为了流程改项目文件或运行项目测试。 |
| `general` 综合任务 | 按该任务的目标、交付物和明确标准核对。 | 不把一般解释和分析强制套成开发任务。 |
| `development` 开发 | 实际改动和当前版本的有效项目测试记录；测试后又发生可能修改时，旧结果不支持验收。 | 模型自述“已通过”、读过测试文件、工具传输成功，均不能代替真实测试通过。 |

未知工具结果不能被认作成功。研究来源来自实际成功工具结果：搜索查询里回显的 URL、网页正文中的未读链接、无障碍树中的链接不计作已取得资料。用户最终答案中的链接与来源做规范化精确对应，避免仅凭相同前缀误判。

## 授权边界和目前的限制

各阶段使用用户原始要求作为授权依据。A 的计划、B 的摘要、网页内容和工具输出都属于资料，不能变成新的用户许可。文件根目录、会话写入与联网设置、工具桥开关和逐次审批沿用现有机制；本功能不新增 IPC 通道或权限档。

“不要运行测试”等原话会传入 A/B 的任务提示，A 应按要求报告未验证；开发任务缺少实际有效验证时不能报验收通过。**目前没有新增工具级的专门禁测语句解析器**，因此这不是对所有测试命令的独立硬拦截保证。若后续实现此类强约束，应复用统一的用户约束机制，覆盖 API、CLI 与 MCP，而非只在提示里加一句话。

Codex CLI 的 A 使用现有只读路径：规划阶段关闭本次 Harbor MCP 注入；审核阶段通过用户已开启的桥读取本次执行证据，只读登记且不额外开放联网。没有启用工具桥时明确阻塞审核，不自动开启。这不等于禁用了用户自行配置的所有全局 MCP。研究和写作的 B 不因任务类别自动获得额外权限，实际可用工具仍取决于原始要求与当前设置。

## 证据回取与审核绑定

协作期间 `recall` 优先读取内核绑定的当前执行中 B 的实际输出，Codex 对应工具是 `harbor_recall`。交接摘要保留完整工具 ID、信息状态与回取说明，预算内输出有效 JSON；按 `callId` 和 `offset/limit` 取原文，或按 `query` 检索全部实时正文。单次正文最多返回 12000 字，较长结果继续分页。这里的“完整”是 Harbor 实际记录的输出；上游工具已截断的页面仍是截断记录，不能据此声称读过全部原文。

没有实时上下文时，历史回取只读当前会话已落盘记录。目录按执行与调用 ID 去重，完整输出优先于后续轻量快照，不把重复快照算成重复调用。仅有元数据时明确表示完整正文不可用；历史目录保留最近 60 次独立调用，扫描超时明确覆盖范围不完整。相同指纹对应多个调用时改用工具 ID；旧记录的工具 ID 本身有歧义时也不猜测。未命中不代表本次没有读取。

A 的 `evidence` 为工具 ID、判断 `claim`、逐字原文 `quote` 与可选 `purpose`。`fact` 支撑事实判断；`execution` 只说明失败、受阻或空结果等执行情况。原文至少 8 字，完全空输出的执行观察允许空引用。内核核对工具归属、逐字存在和信息状态；研究审核通过至少需要事实引用。查询词、脚本仅回显标题、403 与空结果不能当作页面事实。命令真实返回的内容仍可支撑判断，但命令中任意打印的 URL 不自动升格为已读取网页来源。

引用不成立时停止自动返工，说明审核受阻，并不把本轮未获支持的 A 答复投递成阶段成果。该校验保证记录归属与引用存在，**不能自动证明每个判断的语义正确或网页结论真实**。

## 正文结算与状态记录

B 的文字带明确过程标记穿过批处理层。协作结束时只将 A 明确交付、且与协作记录一致的正文结算到原生对话流，阶段稿保留在过程区。已暂停或受阻的执行仍可交付标有局限的阶段答案，任务状态保持未通过；没有可交付答案时显示停止原因。显示、复制和导出继续共用原生 `flow.final`，没有增加从旧 `rounds/content` 推断正文的路径。

前端既接收阶段状态，也从结束事件补收协作记录。独立流快照保存本次执行的正文、工具、引用、归属和终态，供消息占位缺失时落盘；这不是对历史丢失根因的唯一归因。诊断分别记录状态校验失败的字段路径、界面消息缺失、结束接收、落盘排队与实际回执，不记录消息原文或凭据。

统一脱敏此前会把 `limits.maxTokens`、`usage.knownTokens` 的数值隐藏成字符串，导致协作 schema 校验失败。现在仅为这两个精确字段的有效非负安全整数保留数值，同名字符串及密钥仍隐藏。旧缺字段记录保持可读；已经丢失或被隐藏的信息不猜测恢复，不重写历史会话。

## 预算与停止

| 配置项 | 默认值 | 允许范围与含义 |
|---|---|---|
| `maxRounds` | 3 | 1–10；每轮包含一次 B 执行与一次 A 检查，A 的初始规划不另占执行轮。 |
| `maxRuntime` | 900 秒 | 60–7200 秒；整次协作共用截止时间，包含规划、执行、检查及等待。 |
| `maxTokens` | 0 | 0 表示不设已报告 Token 上限；正整数表示按上游已返回用量累计判断。 |

用量只累计真实返回的数值，未提供用量的调用单独记录，不能记作免费。设置了正的 Token 上限而某次调用不报告用量时，暂停后续协作并说明无法核对预算；不限 Token 时，仍受轮数与总时长约束。辅助识图调用当前没有完整用量返回，也按未知处理。

API 每次模型调用返回用量即更新全局预算，不等整阶段结束；阶段累计和最终返回按同一身份取累计值，不重复相加。父任务按本次阶段报告与去重子任务合计汇总，并保留续做前的既有用量。原生 CLI 仍只能在其返回用量后核对，不能做到请求发送前的精确计费拦截。

研究任务的无进展判断基于去重后的真实工具参数和输出，忽略工具 ID、调用顺序、审核措辞、摘要改写与重复 `recall`；写作、综合任务仍考虑正文变化。页面动态内容变化也会改变指纹，因此该判定是重复执行保护，不能替代语义验收与轮数、时长、Token 预算。

这不是计费前的硬限额：已发出的请求可能在返回用量前超过阈值，第三方服务的账单仍以其记录为准。达到上限或取消后会请求中断当前活动并关闭本请求的待答确认，保留真实停止结果与已有记录。

## 历史与恢复

协作记录继续使用 `version: 1`。新增任务类别、逐轮记录、预算、用量和终稿等字段为可选，读取旧记录时不补造旧轮次，不改写原历史文件。旧 `approval` 阶段仍能展示；新监督流程的普通交接不再生成该阶段。

每个阶段与执行轮有独立身份，工具编号带所属阶段前缀，迟到事件不能串到后一轮。未完成时不把 B 的内部摘要当正式答案；若只剩前一轮 A 的阶段成果，会明确注明后续执行尚未复核。重开只回放已保存记录，继续执行仍由用户发起；本次没有宣称可以从任意中间阶段无损自动续跑。

## 验证状态

当前属于监督执行实现交付，**尚未做真实模型或桌面验收**。按用户要求，本轮不运行测试、lint、preflight、桌面自动化或 computer use。新增的边界测试只是源码，不能记为通过。生产构建和双版本同步的最终结果另记在本轮交付报告，不能拿前一版的构建或同步记录代替。

后续用户允许验收时，优先验证一笔资料检索和一笔小开发任务，再覆盖角色互换、多轮返工、权限拒绝、运行中取消、预算用尽和重启回放；取得实际证据后再核销清单 5、6。
