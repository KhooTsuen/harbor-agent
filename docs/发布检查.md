# 发布检查 —— 发 beta / 正式版逐条勾

> 流程位置见 [`开发流程.md`](开发流程.md)。发布工具是 `tmp/` 里的常备脚本（清单见 `tmp/README.md`），
> 每一轮**复制上一轮的脚本改版本号**即可。本文件比 tmp 里的交接文档活得久 —— 两者冲突以本文件为准。

## 版本号规矩（自检 54 组会拦）

- 源头：`package.json`；同步 `package-lock.json`（两处 version）；`CHANGELOG.md` 第一条标题**逐字一致**；`README.md` 不写 x.y.z。
- 一把核对：`node tmp/check-version.cjs` —— 不绿不发布。

## 发一个 beta（标准 9 步）

1. **源码全绿**：`npm run verify`（typecheck → lint → 格式 → 行数 → 单测 → 自检 → 构建）。
2. **升号 + 写 CHANGELOG**：四处版本号；CHANGELOG 一节写清**为什么** + **验证数字**（单测 / 自检项数、真机对照）+ **诚实写遗留**（「还没做」）。
3. **提交 + tag + push**：照 `tmp/git-beta3.cjs` 改版本号跑 —— `git add -A` → `commit -F -`（多行中文走文件）→ 打 tag → push main + tag。
4. **打包**：`node tmp/release-build.cjs` —— typecheck + vite build + 组装便携版 + 打 zip。
   产物 `dist-portable/harbor-<版本>-win-x64.zip`（约 147MB，**不含 data/**，脚本会核对条目数）。
5. **GitHub Pre-release**：照 `tmp/gh-release-beta3.cjs` 改版本号跑 —— token 走 `git credential fill`；
   zip 传 `uploads.github.com`；beta 必须 `prerelease: true`。上传要几分钟，脚本自带「已存在则跳过」，重跑安全。
6. **更新安装版 E:\Harbor**：先 `node tmp/check-running.cjs` 确认应用没在跑；
   再 `node tmp/update-harbor.cjs`（robocopy `/MIR`，**排除两边 data/**；退出码 <8 算成功）。
7. **真机核对**：`node tmp/run-probe.cjs tmp/probe-about.js <日志> E:\Harbor\Harbor.exe` —— 关于页必须显示新版本号。
8. **看 CI**：`node tmp/ci-status.cjs` —— 新 commit 的运行 `success` 才算完；红了用 `tmp/wait-ci.cjs` / `tmp/gh-runs.cjs` 拉日志。
9. **收尾**：仓库记忆更新；历史 zip / 截图攒多了移进 `E:\Harbor-归档资料`（04-开发仓库留档）。

## 发正式版与 beta 的差异

- tag / 标题去掉 `-beta.N`；`prerelease: false`；其余步骤相同。
- 发正式版前，让用户用 beta 真机走过一轮验收（`npm run acceptance` + 个人版测试指南）。

## 硬规矩与已知坑

- 打包会把 `dist-portable/Harbor/data/credentials.json` 搬进 `data/backups/<时间戳>/` ——
  **设计行为**（密钥不跟便携包走），不是丢失。
- 本机 `npm.ps1` 被策略挡：用 `npm.cmd`，或直接 `node <脚本路径>`。
- 多行中文 commit 信息：`git commit -F <文件>`，不要往命令行里塞。
- 更新完的 E:\Harbor 首次启动自己跑数据迁移；`data/` 永远不手工动。
- 回滚：程序文件盖回旧版即可（`data/` 不动）；数据出问题用 `data/backups/` —— 见 [`更新与数据迁移.md`](更新与数据迁移.md)。
