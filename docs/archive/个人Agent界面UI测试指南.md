# Harbor Agent 个人使用界面 UI 测试指南

## 1. 文档目的

本文档专门测试 Harbor Agent 的界面是否“看得懂、点得动、点了真的生效”。重点不是只检查按钮有没有显示，而是验证完整链路：

```text
用户看到界面 → 用户点击控件 → 应用状态改变 → Agent 执行动作 → 磁盘/任务账本产生正确结果 → 界面反馈与实际结果一致
```

本文档面向个人 Agent，优先覆盖高频和高风险操作：启动、新建会话、输入、发送、流式输出、停止、权限、文件修改、任务详情、错误恢复和重启恢复。

## 2. UI 测试原则

### 2.1 UI 通过不等于功能通过

按钮颜色改变、弹窗关闭或消息文字出现，都不能单独证明功能成功。每个关键点击至少需要两类证据：

1. 界面证据：按钮状态、提示、消息、任务状态和错误反馈。
2. 实际证据：文件内容、文件差异、任务账本、会话文件、动作日志或进程状态。

例如，点击“发送”后必须同时确认：用户消息进入会话、Agent 实际收到请求、回答或错误返回、任务账本生成记录；点击“停止”后必须确认流式传输和相关进程确实停止。

### 2.2 真实点击优先

个人 UI 验收应通过鼠标、键盘和可见控件完成。Playwright/CDP 可以辅助定位、等待、截图和读取状态，但不能通过直接修改 store、IPC 或 `data` 文件来代替点击。

### 2.3 每项测试都可恢复

每个测试使用独立的测试工作区和测试 `data`。测试开始前复制夹具，结束后保存截图、日志和磁盘差异。不要在个人真实项目、真实凭证或唯一数据上进行破坏性 UI 测试。

## 3. 测试环境

### 3.1 推荐环境

| 项目 | 基线 |
|---|---|
| 操作系统 | Windows 10/11 |
| 应用 | `E:\Harbor\Harbor.exe` 或 `dist-portable/Harbor/Harbor.exe` |
| 屏幕 | 1280×800、1366×768、1920×1080 至少两种 |
| 缩放 | 100%、125%，有条件时增加 150% |
| 输入 | 鼠标、键盘、中文 IME、英文键盘 |
| 数据 | 独立测试 `data` 和 `workspace` |
| 模型 | 限额测试凭证，可执行简单问答和文件任务 |

### 3.2 测试夹具

在专用 workspace 中准备：

```text
workspace/
  hello.txt       内容：Hello Harbor
  README.md       简短说明
  说明.md         中文文件名和中文内容
  long.txt        1000 行以上文本
  failing.txt     供失败任务使用
```

记录测试前文件哈希：

```powershell
Get-ChildItem -Recurse E:\Harbor-personal-test\workspace -File |
  Get-FileHash -Algorithm SHA256
```

## 4. 测试工具

### 4.1 必需工具

- 鼠标和键盘：验证真实用户操作。
- 截图工具：保存每个关键状态。
- 屏幕录制工具：录制完整用户旅程。
- PowerShell：检查进程、文件和哈希。
- 文本编辑器或 `Get-Content`：检查实际文件。
- JSON 查看工具：检查任务账本和日志。

### 4.2 建议工具

- Playwright：页面点击、输入、等待、截图和 trace。
- Electron CDP：连接 Electron 页面、读取页面状态和控制台错误。
- Windows UI Automation、FlaUI 或 pywinauto：文件选择器、原生弹窗、托盘和窗口级操作。
- Process Explorer：查看 Harbor、Electron、Node 和工具子进程。
- Pixelmatch 或 Playwright screenshot diff：视觉回归。

项目已有真实验收入口：

```powershell
node tools/acceptance.mjs --app=dist-portable/Harbor --port=9338
```

它可以辅助自动化，但不能替代本文件要求的人工点击和实际产物核对。

## 6. 启动界面和窗口生命周期

| ID | 操作 | 界面预期 | 实际功能验证 |
|---|---|---|---|
| UI-LIFE-001 | 双击 Harbor.exe | 窗口出现，无白屏、黑屏或明显布局跳动 | Harbor 进程正常，应用日志无启动异常 |
| UI-LIFE-002 | 等待启动完成 | 启动画面消失，主界面可操作 | 输入框、会话列表和按钮已完成初始化 |
| UI-LIFE-003 | 最小化再恢复 | 内容、焦点和滚动位置合理 | 当前任务和网络连接没有被误取消 |
| UI-LIFE-004 | 最大化、还原和拖动窗口 | 面板不重叠，文字不被裁剪 | 输入框和按钮仍能点击 |
| UI-LIFE-005 | 点击关闭 | 有明确关闭行为，不留下模态遮挡 | Harbor/Electron/工具子进程退出 |
| UI-LIFE-006 | 任务运行时关闭 | 有中断或恢复提示 | 任务账本状态不是虚假成功 |
| UI-LIFE-007 | 重新打开 | 能看到最近会话和状态 | 会话 JSONL 可读，没有重复追加 |
| UI-LIFE-008 | 连续启动退出 10 次 | 每次界面都能正常出现 | 无明显句柄、临时文件或进程累积 |

检查进程：

```powershell
Get-Process Harbor, node, electron -ErrorAction SilentlyContinue
```

## 7. 导航、侧栏和页面结构

### 7.1 视觉检查

- 当前页面、当前会话和当前任务有清晰选中状态。
- 侧栏展开和收起后，主内容不被遮挡。
- 返回、设置、任务详情和关闭按钮位置稳定。
- 空状态页面告诉用户下一步可以做什么。
- 长会话、长标题和中文文件名不会撑破布局。
- 滚动区域明确，滚动条不会覆盖输入框或操作按钮。

### 7.2 功能检查

| ID | 点击 | 实际结果 |
|---|---|---|
| UI-NAV-001 | 点击“新建会话” | 新会话 ID 生成，旧会话不被覆盖 |
| UI-NAV-002 | 点击旧会话 | 正确加载该会话的消息和任务 |
| UI-NAV-003 | 点击设置 | 设置页打开，当前会话状态保持 |
| UI-NAV-004 | 点击返回 | 返回原页面，未保存草稿按设计保留 |
| UI-NAV-005 | 点击任务详情 | 显示当前任务，而不是另一线程任务 |
| UI-NAV-006 | 点击删除会话 | 出现确认；确认后只删除目标会话 |
| UI-NAV-007 | 点击取消删除 | 会话、文件和任务均不变化 |

## 8. 输入框和键盘交互

### 8.1 基础输入

1. 点击输入框，确认焦点可见。
2. 输入中文、英文、数字、emoji、换行和代码。
3. 检查文字没有乱码、丢失或意外截断。
4. 使用 Backspace、Delete、方向键、Home、End、Ctrl+A、Ctrl+C、Ctrl+V。
5. 切换会话，再返回，确认草稿符合设计。

### 8.2 发送行为

| ID | 操作 | 界面预期 | 实际功能验证 |
|---|---|---|---|
| UI-INPUT-001 | 空输入点击发送 | 按钮禁用或提示原因 | 不创建空任务 |
| UI-INPUT-002 | 输入短问题 | 发送按钮变为可用 | 用户消息写入当前会话 |
| UI-INPUT-003 | 点击发送一次 | 按钮进入运行/停止状态 | 产生一次模型请求，不重复提交 |
| UI-INPUT-004 | 快速连点发送 | 有防重复机制 | 任务和用户消息只生成一次 |
| UI-INPUT-005 | Enter 发送 | 行为与界面提示一致 | 只发送一次 |
| UI-INPUT-006 | Shift+Enter | 插入换行而非发送 | 消息内容保留换行 |
| UI-INPUT-007 | IME 组合态按 Enter | 不误发送未完成拼音 | 只在确认提交后发送 |
| UI-INPUT-008 | 粘贴长文本 | 输入框不崩溃 | 实际发送内容与显示内容一致 |

## 9. 发送、流式输出和停止

### 9.1 发送后观察

点击发送后检查：

- 用户消息立即显示且只出现一次。
- 发送按钮变为运行或停止状态。
- 界面没有无限 loading。
- 助手消息逐步出现，内容顺序正确。
- 输入框、会话列表和任务状态没有互相覆盖。
- 完成后按钮恢复可发送状态。

### 9.2 实际功能核对

- `sessions` 中有对应用户和助手记录。
- `tasks` 中有任务 ID、步骤、状态、模型和耗时。
- `logs` 中有动作和错误记录。
- 模型错误时任务不是成功状态。

### 9.3 停止

在流式输出期间点击停止：

1. 停止按钮可点击且反馈及时。
2. 流式文字不再追加。
3. 已显示内容保留并可重启恢复。
4. 网络请求、计时器和工具子进程停止。
5. 任务账本记录中断或取消，而不是成功。

## 10. 权限弹窗和危险操作

| ID | 操作 | 界面预期 | 实际功能验证 |
|---|---|---|---|
| UI-PERM-001 | Agent 请求读取文件 | 显示目标路径和动作 | 只读取目标文件 |
| UI-PERM-002 | 点击允许 | 弹窗关闭，任务继续 | 文件或命令真实执行 |
| UI-PERM-003 | 点击拒绝 | 弹窗关闭并说明拒绝结果 | 动作没有发生 |
| UI-PERM-004 | 请求工作区外路径 | 风险提示明显 | 越界文件未创建/读取 |
| UI-PERM-005 | 请求运行命令 | 显示命令或风险范围 | 退出码和输出进入任务账本 |
| UI-PERM-006 | 运行中关闭权限弹窗 | 状态可理解 | 不默认允许，不留下悬挂任务 |
| UI-PERM-007 | 快速重复审批 | 按钮防重复 | 只产生一次授权动作 |

权限提示至少应让用户知道：谁在请求、要做什么、作用于哪个文件或目录、允许后会有什么结果。

## 11. 文件任务：点击到磁盘结果

### 11.1 修改文件

1. 新建会话。
2. 输入文件修改要求。
3. 点击发送。
4. 看到权限提示后检查路径，再点击允许。
5. 点击任务详情或差异入口。
6. 检查界面显示的差异。
7. 用文本工具读取实际文件。

通过条件：界面中的差异与磁盘文件一致；只有允许范围内的文件改变；任务账本记录正确工具；助手回答没有声称不存在的结果。

### 11.2 新建文件

要求 Agent 新建一个文件，点击允许后检查：

- 文件在正确 workspace。
- 文件名、编码和内容正确。
- 任务详情显示成功步骤。
- 文件不是只存在于 UI 模拟状态中。

### 11.3 失败文件任务

让 Agent 修改不存在的文件或运行确定失败命令，确认错误面板、任务状态、日志和实际目录都一致。

## 12. 任务详情、日志和差异面板

### 12.1 UI 检查

- 能看到任务是否运行、成功、失败、暂停或取消。
- 步骤顺序、工具名称、耗时和错误位置清楚。
- 长输出可以滚动，不会遮挡关闭按钮。
- 成功和失败不能只用颜色区分。
- 任务详情不会显示另一个会话的内容。

### 12.2 功能检查

点击每个详情入口后检查：

- 任务 ID 与 `tasks/*.json` 一致。
- 工具序列与 `actions-*.jsonl` 一致。
- 文件差异与 workspace 哈希变化一致。
- 错误文本与实际退出码/网络错误一致。
- 刷新或重启后详情仍可读取。

## 13. Markdown、代码和链接显示

发送包含标题、列表、表格、代码块、长 URL、HTML、`javascript:` 链接和 `<script>` 的内容：

- Markdown 结构正确。
- 代码可阅读和复制。
- 链接不会执行脚本或读取本地文件。
- 长行可横向滚动或换行。
- 流式过程中标记跨 token 时，最终结构仍正确。
- 恶意内容只作为文本显示。

## 14. 会话切换和多任务

1. 新建会话 A，发送消息。
2. 新建会话 B，输入但不发送草稿。
3. 返回会话 A，观察任务状态。
4. 再返回 B，确认草稿仍属于 B。
5. 同时运行两个安全的只读任务。

通过条件：消息、草稿、任务、权限和工具日志不串线；切换会话不会停止错误任务；每个任务的磁盘产物属于正确 workspace。

## 15. 错误、网络和恢复界面

手工模拟或等待以下情况：无凭证、网络断开、401、429、服务器错误、工具非零退出、任务超时和磁盘只读。

每次检查：

- 错误文字能说明发生在哪一步。
- 有重试、取消、返回或查看详情入口。
- 不会无限转圈。
- 不会把失败显示成成功。
- 重试次数有上限。
- 重启后状态仍可解释。
- 日志和任务账本与界面一致。

## 16. 设置和配置界面

| ID | 操作 | 预期功能 |
|---|---|---|
| UI-SET-001 | 打开设置 | 页面加载且不丢当前会话 |
| UI-SET-002 | 修改模型 | 新任务使用新模型，旧任务不被偷偷改变 |
| UI-SET-003 | 保存凭证 | 不回显完整 key，重启后按设计可用 |
| UI-SET-004 | 输入无效配置 | 保存前提示，不写坏配置 |
| UI-SET-005 | 取消修改 | 原配置和运行行为保持 |
| UI-SET-006 | 重启应用 | 设置持久化且没有明文泄露 |
| UI-SET-007 | 恢复默认设置 | 只重置允许范围，不删除会话和工作区 |

## 17. 响应式布局、缩放和可访问性

在 100%、125%、150% 缩放和至少两种窗口尺寸下重复核心流程：

- 输入框、发送、停止和权限按钮不被裁剪。
- 文本不会覆盖相邻控件。
- 侧栏和主内容仍可滚动。
- 任务详情能关闭。
- 焦点可见，Tab 顺序合理。
- 图标按钮有可访问名称或 tooltip。
- 状态不只依赖颜色。
- 键盘可以完成新建、输入、发送、停止和关闭弹窗。

点击键盘可达的“发送”和“停止”后，仍要检查相同的实际任务、文件和日志结果。

## 18. 视觉回归清单

保存并比较以下截图：

- 首次启动。
- 空会话。
- 输入中。
- 发送后等待。
- 流式输出。
- 权限允许和拒绝。
- 任务成功、失败、暂停、取消。
- 任务详情和差异。
- 设置页面。
- 中文长文本和窄屏。

视觉差异需要人工确认。以下情况优先阻断：文字不可读、按钮不可点击、危险状态不明显、错误信息被遮挡、关键内容被裁剪或不同会话内容重叠。

## 19. UI 代理执行规则

个人使用建议只运行一个 GUI 代理。它必须：

- 使用独立测试窗口、端口和 workspace。
- 只通过可见鼠标/键盘完成用户步骤。
- 每个关键点击保存截图。
- 点击后等待真实状态，再检查文件、任务账本和日志。
- 不用内部 IPC 或直接改 data 冒充点击成功。
- 遇到无法识别控件、崩溃或危险权限时保存现场并停止。

验证代理可以只读检查产物，但不能抢夺 GUI 焦点或修改结果。

## 20. 推荐个人执行顺序

### 每次 UI 修改

1. `npm run test:unit`。
2. `npm run build`。
3. 启动应用，截图空会话。
4. 完成一次发送和流式输出。
5. 完成一次停止或错误测试。
6. 检查会话和任务文件。

### 涉及发送、权限或文件工具

1. `npm run verify`。
2. 只读任务。
3. 文件修改任务。
4. 拒绝权限任务。
5. 停止和恢复任务。
6. 检查真实文件差异和残留进程。

### 发布前

1. `npm run package`。
2. 在新目录启动发行包。
3. 重复核心 UI 流程。
4. 检查凭证、日志、截图和发行包。
5. 备份并恢复测试 data。

## 21. UI 通过标准

个人 Agent 的 UI 至少满足：

- 用户能找到新建会话、输入框、发送和停止。
- 点击发送后实际产生一次任务和一次用户消息。
- 流式状态清晰，完成和失败可区分。
- 点击停止确实停止请求和工具进程。
- 权限允许/拒绝与实际文件和命令结果一致。
- 任务详情、日志和磁盘产物互相一致。
- 会话切换不串线，重启后可恢复。
- 错误有可执行的下一步，不会无限加载。
- 100%/125% 缩放和中文内容下关键控件可用。
- 模型说法与实际文件、退出码和任务账本一致。

任何关键点击“看起来成功”但实际功能没有发生，都应判定为失败，并按照 [个人 Agent 测试指南](./个人Agent测试指南.md) 的失败流程保留现场。
