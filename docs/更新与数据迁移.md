# 更新、备份与数据迁移

> 面向使用者。想知道「数据都存哪」看 [README 的「你的数据在哪」](../README.md#你的数据在哪)；
> 想改代码看 [`CONTRIBUTING.md`](../CONTRIBUTING.md)。

## 怎么更新（便携版）

1. **先退出**正在运行的 Harbor（托盘图标右键 → 退出）
2. 去 [Releases](../../releases) 下载新版本的 `harbor-x.y.z-win-x64.zip`，解压
3. 把新目录里的内容覆盖到旧目录，**`data/` 除外** ——
   更省事的做法：把旧目录的 `data/` 整个拷进新目录，然后用新目录
4. 启动。第一次启动会自动跑数据迁移（见下文）

一句话记住：**程序文件可以随便换，`data/` 是你的。**

> 用 `npm run dev` 跑源码的，`git pull` + `npm install` 就是更新；
> `data/` 在同一位置，不受影响。

## 先说要紧的：升级前手动备一份

应用自己每天会备一次（见下），但**升级是单向的**：新版本写过的数据，旧版本不一定读得懂。
所以大版本升级前，建议手动把整个 `data/` 目录复制一份到别处 —— 它只有几十 MB。

## 备份

**自动**：启动时检查，距上次超过 24 小时就自动备一份，最多留 10 份。
原因是便携版有个真实风险：整个文件夹拷到 U 盘拷到一半拔了，`data/` 就残了。

**手动**：设置 → 数据 → 备份。可以「立即备份 / 恢复 / 删除某一份」。
**恢复**会先把当前状态另存一份「恢复前状态」，恢复完需要重启应用。

**备什么**：配置、记忆、对话、技能。
**不备什么**：日志、缓存、密钥 —— 密钥在系统凭证库里（Windows DPAPI），**不进备份包**，
所以把备份拷到别的机器，模型 API Key 还是要重新填。

## 数据迁移策略

这个项目对改数据结构有一条硬规矩：**必须写迁移，且保留旧数据**。落到实处是：

- **迁移在启动时自动跑**，不需要你做什么
- **能照旧读的就不重写**。例：新增「项目登记表」时只补登记项，
  一个会话文件都不重写（给几千条聊天记录回写字段，风险远大于收益）
- **配置读坏了会另存现场**：`data/config.json.broken-<时间戳>`，并用默认配置起来，
  界面上会提示你 —— 不提示的话，你只会发现「设置莫名其妙全没了」
- **破坏性操作先备份**：「清空 / 删除数据」这类按钮，备份不成功就**什么都不删**

## 会话内容加密（默认关闭）

设置 → 数据里可以打开。打开后会**逐行加密**现有对话文件（转换前自动备份），
之后新写入的行也是加密的。

两点必须知道：

- **密钥绑当前 Windows 账户**。开着加密的话，把 `data/` 拷到别的机器、
  或者换了 Windows 账户，那些行就解不开了 —— 应用会**跳过解不开的行**并提示，
  其余内容照常，不会整个对话打不开
- 它防的是「文件被直接拷走」；**不是**防「这台电脑被人用」——
  程序在你账户下运行时本来就能解密

## 回退到旧版本

- **换程序**：把旧版本的文件夹覆盖回来（`data/` 不动）
- **换数据**：用 `data/backups/` 里的某一份，或升级前手动备的那份

如果新版本写过数据、旧版本读起来不对劲，就两个一起回退：
先把 `data/` 换成备份，再换回旧程序。

## 常见问题

**覆盖安装会不会丢数据？**
不会 —— 只要别删 `data/`。也别把新目录的 `data/` 覆盖到旧的 `data/` 上（那是清空）。

**怎么知道自己是什么版本？**
设置 → 关于。

**更新日志在哪？**
[`CHANGELOG.md`](../CHANGELOG.md)，或 Releases 页每个版本的说明。

**能不能不更新？**
可以。没有强制更新、没有联网检查 —— 你不下新包，它就一直是旧版本。
