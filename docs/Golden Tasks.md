# Golden Tasks（黄金任务集 · v1，8–10 条）

> **这份文档是什么**：一小批**真实使用场景**的回归任务，用来在改架构前后量「行为有没有变坏」。
> 它不是单元测试（那测的是函数），也不是内核自检（那测的是模块能跑）——
> 它测的是**「换一个能力一般但可靠的模型，Harbor 还能不能把活干完」**。
>
> **状态**：v1 定义稿。**尚未执行**（执行需要真实模型调用 = 花钱，见文末「执行前的红线」）。
> 配套：[`Model Interaction Baseline.md`](Model%20Interaction%20Baseline.md)（指标口径 + 基线表）。
>
> **规模纪律**：任务书明确 **不要一次设计 70 个测试**。v1 只 10 条，每条都要能**手工跑、能看懂、能判定**。

---

## 0. 两条设计原则

1. **只用真实场景，不只测 Coding。** Harbor 定位是本地优先的个人通用 AI Agent，
   Coding 只是当前较成熟的能力之一（任务书第一条）。
2. **判据必须是「可观察的现象或数字」，不是「看着还行」。**
   每条任务写清：**期望动作序列**、**期望产出**、**不许出现的现象**（反向用例）。

## 1. 任务表（G1–G10）

| ID | 场景 | 覆盖的架构面 | 主要判据 |
|---|---|---|---|
| G1 | 文件理解 | 读工具 + 上下文装配 | 结论正确、不臆造 |
| G2 | 文件修改 | 写确认 + Changeset + 验证 | diff 正确、可整批撤 |
| G3 | 多步骤任务 | Task/Plan/step 台账 | 步骤不重复、计划可更新 |
| G4 | 长任务恢复 | Task 状态机 + Checkpoint | 接回同一条任务、不重做 |
| G5 | 错误恢复 | 失败上下文 + 不重复重试 | 换策略、不原地打转 |
| G6 | Memory | 记忆召回 + 注入预算 | 该召回召回、无关注入 |
| G7 | 项目隔离 | Project / 会话 / Memory 作用域 | 两条项目不串 |
| G8 | 非 Coding 工作 | 通用工具链（研究/整理/报告） | 产出可用、不强行编码 |
| G9 | 长上下文 | 上下文预算 + 裁剪 | 预算内、关键信息不丢 |
| G10 | Subagent | 子代理只读侦察 | 结论带回、不越权写 |

### G1 · 文件理解

- **场景**：让 Agent 读一个目录（选一个含 5–8 个文件的真实目录），总结结构并回答一个具体问题。
- **步骤**：① 用户给目录路径 + 问题；② Agent 用 `list_dir` + `read_file`；③ 给结论。
- **判据**：
  - ✅ 结论里的文件名 / 行号**能在磁盘上核对上**。
  - ✅ 引用了实际读过的文件（不是凭目录名猜）。
  - ❌ **不许出现**：编造不存在的文件；把没读的文件说成读过。
- **记录**：工具调用次数、读的文件数、总耗时。

### G2 · 文件修改

- **场景**：让它改一个真实文件里的一小段（例如给某个 md 加一节），改完自证。
- **步骤**：① 指文件 + 改什么；② `read_file` → `edit_file`；③ 写前弹 diff 确认；④ 改完验证。
- **判据**：
  - ✅ diff 内容与要求一致（**展开看细节**，不只点确认）。
  - ✅ 改完**主动**给出验证方式并跑一遍。
  - ✅ Changeset 里有这条改动、能整批撤（撤完文件回到原样）。
  - ❌ 不许出现：没确认就落盘；改错了还宣称完成。
- **记录**：写工具失败次数、确认次数、回滚是否干净。

### G3 · 多步骤任务

- **场景**：一个需要 3+ 步的活（例：把一份长文档拆成 3 个小文件，并在每份里加开头）。
- **步骤**：① 目标；② Agent 给 ```plan 块；③ 逐步执行；④ 每步标 `[x]` 并重发整份计划。
- **判据**：
  - ✅ **同一件活不被重复做**（`task.steps[]` 里不出现同一文件重复写）。
  - ✅ 计划变更时走 `planVersions`（历史版本留着）。
  - ✅ 最终 `status` = `completed`，`nextAction` 为空。
- **记录**：turn 数、工具调用数、计划改了几版。

### G4 · 长任务恢复

- **场景**：跑一个长任务，**中途暂停**（或直接关掉应用），再回来说「继续」。
- **步骤**：① 起长任务；② 中途 `paused`；③ 重开/继续；④ 走到完成。
- **判据**：
  - ✅ **接回同一条 Task**（不是新建一条）。
  - ✅ **不重做已完成的步骤**。
  - ✅ Checkpoint 里有中途的打点（`task.checkpoints[]` 非空）。
  - ✅ `resumeCount` 增加。
- **记录**：恢复耗时、重做步数（应为 0）、`pauseReason`。

### G5 · 错误恢复

- **场景**：制造一次工具失败（例：`read_file` 一个不存在的路径、或跑一条会报错的命令）。
- **步骤**：① 失败；② Agent 识别失败；③ 换策略；④ 完成。
- **判据**：
  - ✅ **不重复同一个失败调用**（同一工具同一参数连着来 = 原地打转）。
  - ✅ 失败原因被正确解释（不是照抄报错全文）。
  - ✅ `loopHit` 不被触发（说明没转到打圈）。
  - ❌ 不许出现：把失败说成成功；对**写操作**自动重试。
- **记录**：失败次数、重试次数、`retries`。

### G6 · Memory

- **场景**：先让它记住一条用户事实（`remember`），**开一条新对话**，再问一个需要这条事实的问题。
- **步骤**：① 记一条；② 新会话问相关问题；③ 顺便问一个**无关**问题。
- **判据**：
  - ✅ 相关问题**召回了**这条（设置 → 记忆的「为什么是它」能对上）。
  - ✅ 无关问题**不注入**它（看那一轮的注入清单）。
  - ✅ 无关注入条数在预算内（`memory` 层 ≤ `context-builder.cjs` 的 memory cap）。
- **记录**：注入条数、注入字符数、召回准确与否。

### G7 · 项目隔离

- **场景**：两个项目（两个不同工作目录），各自有自己的 `.harbor/rules.md`。
- **步骤**：① 在项目 A 里建会话、记一条 A 专属记忆；② 切到项目 B，问一个会暴露串号的问题。
- **判据**：
  - ✅ B 的项目规则里**不出现** A 的规则。
  - ✅ A 的记忆不进 B 的注入（项目级 memory 按 `projectId` 隔离）。
  - ✅ 工作目录 / 文件访问范围不串。
- **记录**：B 那一轮注入的 project 层内容 hash、memory 条目 id 集合。

### G8 · 非 Coding 工作

- **场景**：研究 / 整理 / 出报告（例：读 3 篇本地文档，整理成一份带结论的摘要）。
- **步骤**：① 给资料 + 目标；② Agent 读、归纳；③ 产出成品（artifact 或文件）。
- **判据**：
  - ✅ 产出**可用**（结论有出处、不是空话）。
  - ✅ **不强行编码**（不该出现「我给你写个脚本」这类跑偏）。
  - ✅ 成品落进 Artifact（版本化）或指定文件。
- **记录**：产物大小、引用来源数、是否触发 artifact。

### G9 · 长上下文

- **场景**：一条**较长**对话 + 大量工具结果 + Memory + 项目规则，然后问一个需要**早前信息**的问题。
- **步骤**：① 堆上下文（粘贴长文本 / 多次工具结果）；② 问早前细节。
- **判据**：
  - ✅ 总上下文在预算内（`context-builder.cjs` 的 estimates 有数）。
  - ✅ **关键早前信息不丢**（若丢了，裁剪说明里应能看到 `droppedMessages`）。
  - ✅ 图片不被切坏（多模态整块保留 —— `context-builder.cjs:9` 的真机事故）。
- **记录**：`maxTokens` / `chars` / `selectedMessages` / `droppedMessages`。

### G10 · Subagent

- **场景**：派一个只读侦察兵去读一批文件，只把结论带回来。
- **步骤**：① 主 Agent `spawn_subagent`；② 子代理读并归纳；③ 主 Agent 继续。
- **判据**：
  - ✅ 子代理**没有写操作**（只读约束成立）。
  - ✅ 结论带回主 Agent，主 Agent **没有重新读那批文件**（省上下文的意义就在这里）。
  - ✅ 子任务在 `data/tasks` 里有记录（`parentTaskId` 指回父任务）。
- **记录**：子代理 read_file 次数、主 Agent 上下文增量。

## 2. 怎么跑（流程）

```
① 准备隔离环境（★ 绝不碰真 data）
② 逐条手工跑（每条：开始前记时间 → 跑 → 按判据判 → 记录字段）
③ 把每条的「记录字段」填进 Model Interaction Baseline.md
④ 全跑完之前**不做任何优化**（任务书第七节：先记 Baseline，再动）
```

**跑完之后的规矩**（任务书第十一节，Observe → Measure → Identify → 最小改动 → 再跑 → 比 Baseline）：

```text
Observe → Measure → Identify bottleneck → Make smallest change
        → Run Golden Tasks → Compare Baseline → Keep / Revert
```

而不是「发现理论问题 → 设计新架构 → 大量重构 → 希望问题消失」。

---

## 3. 执行前的红线（**要你点头才能跑**）

1. **花钱**：10 条任务 × 真实模型调用。用 DeepSeek 主力模型跑一轮的成本需要先估。
2. **不碰真数据**：必须在**隔离目录**跑（沿用项目已有约定：
   `npm test` 写 `data/selftest-data`、`npm run test:unit` 写 `data/unit-test-data`，
   由 `electron/core/paths.cjs` 的 `isolationDirName()` 决定）。
   Golden Tasks 的工作目录另建一个，**不指向 `E:\CodexWorkbench` 或 `E:\Harbor-Dev`**。
3. **判据要人看**：v1 的判定靠**人工观察**（尤其「不许出现」那几条），不自动判 ——
   自动判要另写脚本，属于下一步。
4. **先定口径再跑**：`Model Interaction Baseline.md` 里的指标名与来源文件先冻结，
   否则跑两遍的口径不一样，数字没法比。

## 4. 这份文档怎么长大

- **v1（本稿）**：10 条，手工跑，人工判。
- **v2（若 v1 证明有用）**：挑 3–5 条脚本化（用 `npm run shot:electron -- --js=` 那套 CDP 真机能力，
  能点按钮、填输入框、读回 DOM），做成 `test:agent-regression`。
- **不进 v1 的**：70 条矩阵、性能压测、多模型横评 —— **等 v1 证明机制有效再说。**
