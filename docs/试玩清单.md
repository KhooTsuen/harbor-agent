# 试玩清单（照着点就行）

> **2026-09-29 重写**：每条都写成「**你要说什么话 / 点哪里 → 应该看到什么 → 不该看到什么 → 不对说明哪坏了**」，
> 话术可以直接复制。术语看不懂就翻最后的[词表](#附-1--词表看不懂的词都在这)。
>
> **忙的话只做两件**：**A 组（10 分钟）** + **D4（30 秒）**。A 组最值钱（任务跑起来时你看得见什么），D4 是这次新加的。
>
> ⚠️ **本次修了旧版一句话**：旧版说「下一步」建议里那些按钮「点一下只是把话填进输入框，不会自己跑起来」——
> 这句**不对**。现在的实现是：**[查看 Diff]** / **[查看测试结果]** 只切标签或展开内容（纯看），
> **[运行测试] [提交修改] [继续检查] [继续优化] [定位失败原因] 点了就等于替你发了一句话，它会真的开始做**。
> 详情见 B1。

## 0 · 开工前 3 件事（5 分钟）

### 0.1 用哪个包

**双击 `E:\Harbor\Harbor.exe`** 就行（这是最新版，2026-09-29 打的）。
也可以在仓库里跑 `npm run dev`（效果一样，只是从源码启动）。

### 0.2 造一个「沙箱」目录，别拿真项目试

1. 在文件资源管理器里新建一个**空文件夹**，比如 `E:\harbor-试玩`（右键 → 新建 → 文件夹）
2. 把应用的工作目录指到它 —— 二选一：
   - **只给这一条对话用**：侧栏上面那个「**新建项目**」→ 选你刚建的空文件夹
   - **改全局默认**：设置 → **权限与安全** → **工作目录** → 填/选那个文件夹
3. **确认一下**：回到对话，看**输入框下面那行小字**，它显示的应该就是你那个沙箱目录。
   （工作目录全应用只在这一处显示，别处不重复。）

> 为什么用空目录：下面有几题会让它**新建、修改**文件。在沙箱里玩，坏了删掉重来即可；
> 在真项目里玩，出问题你没法收拾。

### 0.3 把工具权限设成「需要确认」

**设置 → 权限与安全 → 工具权限**，选 **「需要确认」**（默认就是它）。

| 档位 | 行为 |
|---|---|
| 只读 | 只能看文件，不能改 |
| **需要确认** | 写文件、改文件、跑命令都会**弹窗问你**（下面 B3 要看的就是这个弹窗） |
| 完全访问 | 不打断，直接改直接跑 |

> 小提示：设置里叫「**需要确认**」，而任务控制台那一行显示成「**询问**」—— 两个词是同一件事，别以为是两个设置。

## A 组 · 最值钱的 10 分钟（任务跑起来时，你看得见什么）

### A1 控制台：跑动中你能看见八个数字

**你要做什么**

1. 新建一条对话（工作目录 = 沙箱）
2. 把下面这段**整段复制**发出去（它是一条要好几步的活，正好够看）：

   > 在工作目录里新建三个文件，内容照抄：
   > `README.md`：标题「示例项目」，小标题「## 安装」，下面两行「1. 装 Node」「2. 跑 npm install」
   > `build.sh`：三行 echo —— 「1) 安装依赖」「2) 编译」「3) 打包」
   > `tests.py`：一行 `print("3 tests passed")`
   >
   > 建完之后：对比 README.md 和 build.sh 说的步骤，再跑一次 `python tests.py`（没装 python 就跑 `node -v`），最后给结论。

3. **趁它还在跑**（输入框旁边是「暂停/停止」的时候），点右栏 **任务** → 那条任务的 **详情** → **控制台**

**应该看到**：**八行**，外加一排按钮

| 行 | 正常长什么样 |
|---|---|
| 状态 | 「进行中」 |
| 当前步骤 | **计划里的一条短句**，比如「读 README.md」 |
| 运行时间 | 秒数在走 |
| Tool Calls | 一个数字，在涨 |
| Retry | 「0 次」 |
| 权限 | 「询问」（= 你设的「需要确认」） |
| 模型 | 你正在用的模型名 |
| Token | **一个数字**，比如「14K」 |

跑着的时候按钮是这 6 个：**暂停 / 停止 / 查看详情 / 查看 Diff / 查看 Tool / 调整权限**
（它暂停之后会多一个 **继续**。）

**不该看到**

- 当前步骤是一大段**文件内容**（那是老毛病：把「最近一步的摘要」当成了「下一步计划」）
- Token 显示 `—`

**不对的话把哪个告诉我**

- 少行 / 少按钮 → 说清少了哪一个
- Token 是 `—` → 说清你用的哪个模型（有些第三方中转站不返回用量，那是兼容性，不是 bug）
- 当前步骤是一坨文件内容 → 直接说「当前步骤是文件内容」

### A2 停下来之后，输入框应该变回「发送」（回归点）

**你要做什么**

1. 接着 A1，点控制台里的 **暂停**
2. 看**输入框右边那个按钮**

**应该看到**

- 输入框右边是 **「发送」**（一个向上箭头），**不是**「停止生成 / 暂停生成」
- 任务行里出现「**继续**」，任务状态变成「**已暂停**」

**不该看到**：任务明明停了、输入框还写着「停止生成」（这是老毛病 ② 复发，一定要告诉我）

### A3 中途改方向：还是**同一条**任务

**你要做什么**

1. 接着 A2（任务是「已暂停」），**不要点「继续」**
2. 直接在输入框打这句发出去：

   > 改一下方向：别管 build.sh 了，只把 README 的安装那一节说清楚。

3. 等它停下来，看右栏 **任务** 里有几条任务，再看那条任务的详情

**应该看到**

- 任务**还是 1 条**（不是变成 2 条）—— 这是关键
- 详情里出现「**你改过方向 · 1**」，下面列着你刚打的那句**原话**
- 如果它重排了计划，会多一个版本，理由写着「**按你的改动重新规划**」

**不该看到**：变成两条任务（= 没接回原来那条，这一轮的修复没生效）

### A4 Token 是真数字，不是摆设

**你要做什么**：等 A1 那条任务跑完，再看一次控制台里的 Token。

**应该看到**：数字比跑动中**更大**（或至少不是 0 / `—`）；底栏「日志」里那条命令的用量也对得上。

**不对的话**：跑完还是 `—` → 告诉我模型名（同上，有些站点不返回用量）。

## B 组 · 核心流程（15 分钟，做完更放心）

### B1 「下一步」建议 —— ★ 先看清哪个按钮会真的开始跑

**你要做什么**

1. 让 Agent 改一个文件，比如发这句：

   > 把 README.md 的标题改成「示例项目（试玩版）」。

2. 等它**成功结束**
3. 看**输入框上方**冒出来的那排按钮

**应该看到**：一排建议（给哪几个，看这轮干了什么）：

| 这轮的情况 | 它给的建议 |
|---|---|
| 改了文件、没跑测试 | [运行测试] [查看 Diff] [提交修改] [继续优化] |
| 改了文件、测试通过 | [查看测试结果] [查看 Diff] [提交修改] [继续优化] |
| 改了文件、测试没过 | [查看测试结果] [定位失败原因] [查看 Diff] |

**★ 每个按钮点了会发生什么（旧版就是这里写错的）**

- **[查看 Diff]（纯看）**：只把右栏切到「审查」，不发任何消息
- **[查看测试结果]（纯看）**：就地展开结果，不发消息
- **[运行测试] / [继续检查] / [继续优化] / [定位失败原因]（会开始跑）**：点了 = 替你发了一句话，**它会真的开始干活**（所以别乱点）
- **[提交修改]（会开始跑，但不会偷偷提交）**：它发出去的那句话是「先把 diff 和提交信息给我看，我确认之后再提交」——
  也就是说**真正提交还要在你点头之后**，但它会开始准备

**你可以这样验一下**：点 **[查看 Diff]** → 右栏跳过去、对话里**没有**新消息进来；
再回头点 **[继续优化]** → 对话里会多一条你说的话，它开始跑。

### B2 Diff：改了什么，一眼看到

**你要做什么**：接 B1，点 **[查看 Diff]**，看右栏。

**应该看到**

- 右栏切到 **审查** 标签
- 改动的**文件名** + `+N −M` 的统计 + 逐行的绿/红差异
- **窗口右上角**也有一个 `+N −M`，数字跟这里**一致**（有改动时才出现）

**不对的话**：两处数字不一样 → 告诉我两个数字分别是多少。

### B3 权限弹窗里的 Diff（默认折叠）

**你要做什么**

1. 发一句要改文件的话（比如「把 README 的安装那一节改成 3 步」）
2. 弹窗一出来就看它，**先别点**

**应该看到**

- 弹窗**默认是收着的**：只有一行「会改 1 个文件 +1 −1」+ 一个 **[查看 Diff]**
- 点 **[查看 Diff]** 才展开具体改了哪几行；再点变「收起」
- 按钮是三个：**[允许本次] [查看 Diff] [拒绝]**
- **关掉弹窗 = 拒绝**（不会偷偷执行）

**不该看到**：跑命令的确认也出现「查看 Diff」（那种没有 diff，不该有这个按钮）

### B4 撞上上限：它是**停下来问你**，不是失败

这里有两道不同的闸，随便验哪一道：

**（a）全局用量闸（1 分钟，最容易复现）**

1. 设置 → **数据与用量** → **用量闸（预算）**
2. 把「**每天上限（token，0 = 不限）**」填成 `1000`
3. 回对话随便发一句让它干活的话

**应该看到**：它**在调模型之前就被拦下**，并给一句人话 —— 大意是「今天的用量已经到上限了（xxx / 1000 token）。
这是你在设置里设的闸门，不是故障；要接着用就把上限调高或关掉」。
**验完记得清空那一格**（清空 = 0 = 不限；默认就是不限）

**（b）单个任务的预算（五项上限）**

每个任务自己有一套上限：**轮数 / 工具调用次数 / 运行时长 / 重试 / 本任务的 token**（默认 50 轮 / 100 次 / 30 分钟 / 3 次 / 10 万 token）。
它按任务类型自动给，**撞上之后任务卡片上才会出现「调整预算」**（没撞的行不给这个按钮，免得每行都多一个）。
撞上时的样子：

- 任务状态是 **「已暂停」**（不是「失败」）
- 卡片上写着「已达到本次任务的轮数上限（50 / 50）」这类说明
- 给三个选择：**[继续] [调整预算] [停止]**
- 点「调整预算」会**就地展开**一张五字段的表单（留空 = 用默认值，占位符里写着默认；**运行时长按分钟填**）

**不该看到**：「转圈被拦下」那种情况也给「调整预算」—— 转圈和预算无关，那种只给 **[继续] [停止]**。

### B5 暂停 vs 停止，是两件事

**你要做什么**：同一条任务，分别试一次。

| | 暂停 | 停止 |
|---|---|---|
| 什么时候生效 | 做完**手上这一步**才停 | **立刻**断，正在跑的命令会被杀掉 |
| 之后能怎样 | 状态「已暂停」，点 **继续** 能接上 | 这一轮就结束了，已经产出的内容留在对话里 |

**应该看到**：按钮名字和结果对得上上面这张表。

### B6 Tool 流水：能搜的日志

**你要做什么**：在控制台点 **[查看 Tool]**。

**应该看到**：底部面板打开并切到 **日志** 那一栏 —— 一张全局的工具流水（时间 / 工具 / 状态 / 耗时），**上面有搜索框**，能按工具名或输出内容搜。
（底栏也可以用 `Ctrl+J` 开。）

## C 组 · 只有你能判断的三项

### C1 界面真的不冻吗

**你要做什么**：发一个**长活**（比如「对比 README 和 build.sh 的步骤，再跑一次 tests.py」），在它跑的时候：

- 用鼠标滚对话历史 → 应该顺滑
- 在输入框里打字 → 应该一个字都不卡
- 切到另一条对话再切回来 → 内容应该还在

**不对的话**：卡顿 / 掉字 / 白屏 —— 告诉我当时在做什么、大概卡几秒。

### C2 通知会不会抢走焦点

**你要做什么**

1. 让一个任务跑着，把窗口**最小化**（或切到别的软件去打字）
2. 等它完成

**应该看到**：通知弹出来，但**你的输入焦点没被抢走**（你在别的软件里打的字，还进到原来那个窗口）；任务栏图标不闪。

### C3 状态词是不是一套话

**你要做什么**：同一个任务，看三个地方说的是不是一致 —— 任务行的状态、**底栏**（窗口最下面那条）的状态、**控制台**里的「状态」那一行。

**应该看到**：三处用词是同一套（不会一处说「执行中」、另一处说「运行中」），颜色也是同一套语义色。

## D 组 · 边界与恢复（有空再看）

- **D1 两个对话不串**：开两条对话同时跑任务，切来切去 —— 进度各归各的，不互相覆盖。
- **D2 诊断报告**：任一任务 → 详情 → **诊断** → **复制全文**。应该只写台账里**真有的**东西（状态、用时、模型、计划进度、失败步骤、改动文件、命令退出码、授权次数、检查点、恢复次数），**不猜**。这份已经脱敏，可以直接发我。
- **D3 重启后能接着做**：放一条「已暂停」的任务不管，**重启应用**，看它还在不在、点「继续」能不能接上。
- **D4 ★ 错误清单（这次新加的，30 秒）**：右栏切到最右边的「**错误**」标签。

  **应该看到**：按严重程度分组的清单。
  - 平时是**空的**，文案是「最近 7 天没有记录到错误。出现问题时这里会自己出现记录（只记不修）」——**空着是好事**
  - 右上角三个按钮：**复制成 Markdown** / **打开数据目录** / **刷新**
  - 左上角能切「7 天 / 30 天」；数字那块写「N 种 / M 次」（N 是**种类**、M 是**总次数**，同一个错刷 100 次算 1 种 100 次）
  - 点一条能展开：**建议 / 位置 / 首次与最后时间 / 原文**

  **以后怎么用它**：哪天碰上「点了没反应 / 发不出消息」这类毛病，先点这个标签 → 点**复制** → 粘给我。
  比翻日志快，而且里面的「位置」直接告诉我是哪个环节（通道 / 工具 / 模型 / 终端）出的。

  **不该看到**：读不出来时假装「一切正常」—— 读失败会照实说「读不出错误清单：原因」。

## 附 1 · 词表（看不懂的词都在这）

| 词 | 什么意思 |
|---|---|
| **已暂停（paused）** | **不是失败**。撞上限、被转圈检测拦下、你按了暂停、应用被关掉 —— 都会停在这个状态，能「继续」 |
| **轮数上限** | 一个任务最多跑多少轮（一轮 = 发一次模型请求 + 跑它要的工具）。默认 50 |
| **用量闸** | **全局**的 token 上限（每天 / 每月），防「忘了关跑一晚上」。**默认不限** |
| **任务预算** | **单个任务**的五项上限（轮数 / 工具次数 / 时长 / 重试 / token），默认 50 / 100 / 30 分钟 / 3 / 10 万（**以「调整预算」表单里的占位符为准**，那儿写的就是当前默认值） |
| **转圈检测** | 认得出「A→B→A→B」这种原地打转：先提示模型换个法子，连着几次不听才停下来交给你 |
| **纯看 / 会跑** | 按钮的两种性质。**纯看**=只切标签或展开内容，不发生任何事；**会跑**=点下去等于替你发了一句话 |
| **错误清单** | 内核在**出错的第一现场**记的一份记录（右栏「错误」标签和命令行 `npm run errors` 看的是同一份数据） |
| **工作目录** | Agent 干活的落脚点。只在**输入框下面那行小字**里显示一次 |

## 附 2 · 已经自动跑过的（你不用手点）

`npm run acceptance` 会用**真模型**跑 8 类任务 × 3 次，而且**按磁盘产物判成败**（不信模型的自我汇报）。
我发布前会跑；下面这些场景**已经被它盯着**，手点时不用重复：

| # | 场景 | 看什么 |
|---|---|---|
| T1 | 只读答疑 | 该不动文件时真不动 |
| T2 | 单文件修改 | 改对位置，不被「顺手重构」带偏 |
| T3 | 改完跑测试 | 改完真的跑了测试 |
| T4 | 新建文件 | 新建 + 细节（中文逗号） |
| T5 | 失败处理 | 失败如实报告、不瞎建文件 |
| T6 | 多文件重构 | 拆文件 + 改两处 import + 跑测试 |
| T7 | 中文文件名 | 中文路径/文件名不翻车 |
| T8 | 长文件找针 | 300 行日志里找到唯一那行并只回答编号 |

所以**手点这一份的价值在别处**：界面看得见 / 按得动、状态词一致、通知不抢焦点、边界与恢复 ——
这些机器判断不了，只能靠你的眼睛。
