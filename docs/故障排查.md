# 故障排查

> 面向**用的人**，不是改代码的人。
> 开发者要看的是 [`踩坑记录.md`](踩坑记录.md)（那份带报错堆栈）。
>
> 排查顺序永远是：**先看屏幕上的提示** → 再看日志 → 再动数据。**别急着删 `data/`。**

---

## 一、先找到日志

| 文件 | 看什么 |
|---|---|
| `data/logs/YYYY-MM-DD.log` | **人看的**。时间戳带本地时区、每行带会话/任务短码 |
| `data/logs/actions-YYYY-MM-DD.jsonl` | **机器看的动作流水**：你点了什么、调了哪个通道、成没成、多久 |
| `data/audit/YYYY-MM-DD.jsonl` | 每次工具调用（参数已脱敏） |
| 设置 → 关于 → **导出诊断包** | 一键打包上面这些（**不含密钥**） |

日志里每行开头有短码 `[sess…wi6c03 · rls6gw]` —— 同一件事的几行带同一个短码，好对。
热路径还会写一行 `新一轮：来源=用户发送|点继续|编辑后重答|重新生成|切提问版本`
—— **回答「这一轮是谁起的」**，查「它怎么又自己跑了一轮」时先看这行。

## 二、按现象查

### 「发消息没反应 / 一直转圈」

1. 看日志有没有 `请求模型[...]` 那行。**没有** → 请求没发出去，看下面「通道失败」
2. **有** → 看紧接着的错误类型（见第三节对照表）
3. 最常见：`auth`（Key 不对）或 `network`（连不上，中转站挂了）

### 「回答是空白，但没报错」

大概率是**中转站在 HTTP 200 的正常流里发了错误**（OpenRouter 这类很常见）。
应用会把它抛出来（0.23.0 修过），如果确实空白，导出诊断包看日志里的 `chunk.error`。

### 「提示：凭证解密失败」

```
凭证解密失败（Error while decrypting ... safeStorage.decryptString）。
通常是换了 Windows 账户或把 data/ 拷到了别的机器，重新填一次 API Key 即可。
```

**照提示做就行**：设置 → 模型 → 重填 API Key。
原因：密钥是用 **Windows DPAPI 绑当前账户**加密的，**换账户/换机器就解不开**。
（这是设计，不是 bug —— 换来的是「密钥不以明文躺在磁盘上」。）

### 「设置莫名其妙全没了」

看 `data/` 下有没有 `config.json.broken-<时间戳>`。
有 → 配置文件损坏过，主进程**留了现场**并把配置重置了。
把那份 `broken` 文件打开，需要的内容手动抄回 `config.json` 即可。

### 「终端打不开」

```bash
npm run pty:check
```
- 源码跑：`node-pty` 没编译成功 → `node node_modules/node-pty/scripts/post-install.js`
- 便携版：原生模块没拷进包 → 重新 `npm run package`

### 「Agent 看的还是旧的工作目录」

**默认工作目录只影响「没有自己目录的对话」。**
你改了默认值，**已有对话不会跟着变** —— 每条对话的目录记在它自己的会话文件里。
要改某条对话的目录：在那条对话的设置里改。

### 「某个操作被拦了」

提示会写清楚**为什么**（比如「这条命令被拦下了（危险 — 格式化磁盘）」）。
这是**保护措施，不是故障**。确实要跑 → 在**终端面板里自己敲**（人在回路里，就不拦）。

### 「任务停在中间不动了」

三种，界面分得开：

| 界面显示 | 意思 | 怎么办 |
|---|---|---|
| **已暂停** | 撞上限（轮数/工具次数/时长/token）或你自己按了停 | 右栏「任务」→ 继续；或先改方向再继续 |
| **等待确认** | 它在等你批一个权限 | 输入框上方那条确认 |
| **失败** | 某一步真错了 | 看任务详情里的失败原因（留的是原话） |

**它不会静默重跑，也不会静默丢弃。**

### 「它是不是在转圈」

`loopGuard` 会认 A B A B 这种重复。先自己改道，几次不听才停下来交给你。

## 三、错误类型对照表

内核把错误分了 15 类，每类有明确处置。你看到的提示对应下表：

| 提示里的说法 | 内部类型 | 会不会自己重试 | 你该做什么 |
|---|---|---|---|
| 网络请求失败 | `network` | ✅ 重试 | 等一下；一直失败就查网络/中转站 |
| 请求超时 | `timeout` | ✅ 重试 | 同上 |
| 被限流了 | `rate_limit` | ✅ 退避后重试 | 等一下，别连续点 |
| 对方服务器出错 | `server` | ✅ 重试 | 等，或换个供应商 |
| **认证失败 —— 检查 API Key** | `auth` | ❌ | **要你出手**：设置里重填 Key |
| 请求参数不被接受 | `bad_request` | ❌（会重新规划） | 一般是模型不认某个参数，换模型试试 |
| 这个模型不支持该能力 | `model_unsupported` | ❌ | **要你出手**：换个模型 |
| 上下文超出模型上限 | `context_overflow` | ❌（会自动压缩一次再试） | 压完还超 → 开个新对话，或减少历史 |
| 文件不存在，或者读完之后被改动了 | `file_changed` | ❌（会重新读） | 正常，它会自己重读 |
| 权限不足 | `permission` | ❌ | **要你出手**：批准那个权限 |
| 工具执行失败 | `tool_failure` | ❌（会重新规划） | 看输出，一般是命令本身错了 |
| 命令非零退出 | `process_exit` | ❌ | 看退出码和输出 |
| MCP 出错 | `mcp` | ✅ 重试 | 查那个 MCP 服务器 |
| （你按了停） | `aborted` | ❌ | — |

## 四、数据在哪、怎么救

```
data/           ← 删了它 = 清空全部状态。**动手前先备份！**
  config.json     配置
  sessions/       对话
  tasks/          任务台账
  changesets/     改动事务（回滚用）
  backups/        自动备份（每 24 小时一次，留最近 10 份）
  credentials.json 密钥
```

**换电脑**：整个程序目录（含 `data/`）拷过去就能用 —— 但**密钥要重填**（见上）。

**误删/改坏了**：
1. 先看 `data/backups/` —— 自动备份里有 `config.json` / `memory.md` / `sessions` / `skills`
2. 对话文件是 **JSONL 追加式**，崩了只丢最后一行，前面的还能读；实在坏了用文本编辑器删掉坏的那行
3. 改动过的文件：对话区横幅有「**撤销这些改动**」（**整批撤**，不是逐个文件）

> ⚠️ **`data/backups/` 里没有 `credentials.json`**（有意为之：密钥不该被备份到处拷）。
> 恢复备份后要重填 Key。

## 五、给「报 bug」的人：怎么提供有效信息

1. 设置 → 关于 → **导出诊断包**（这个包里**没有密钥**，可以直接发）
2. 说清**你点了什么**（日志的动作流水里有，但你说得更快）
3. 如果是「它自己又跑了一轮」，把日志里 `新一轮：来源=...` 那几行贴出来
4. 别只说「报错了」—— 提示里那句话本身就是分类，直接贴它

## 六、已知的、不是 bug 的行为

| 现象 | 为什么 |
|---|---|
| 换机器后密钥要重填 | DPAPI 绑账户，换来的是密钥不明文落盘 |
| 改了默认工作目录，老对话不变 | 每条对话的目录记在自己的会话文件里（侧栏「对话文件夹」按它分） |
| 界面里有些地方会把旧名 `personal-agent` 露出来（导出文件名等） | 历史残留，正在清 |
| 编辑中间那条消息后，**当前版本**下后面几轮「不见了」 | 设计：它们属于旧版本，**切回那一版就回来了** |
| 「危险」命令怎么配 allow 都还要再问一次 | 这几类没有「默默允许」的正当场景 |
