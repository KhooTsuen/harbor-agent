> **这是什么**：Harbor 从「能跑」长到「20 万行」之后，把**散落各处**的改进点收成一张单子 ——
> 每条都指得住 `文件:行号` 或一条可跑命令，并标清**改了要动几个文件、撞哪条红线**。
> 给你「研究用」的原料，**不是承诺**：做不做、什么顺序，你拍板。
>
> **和 [`improvement-checklist.md`](improvement-checklist.md) 的分工**（别当重复）：
> - 那份是**对「外部给的清单」的核对账** —— 回答「外部要求的那批，做了没」，已清账。
> - 这份是**从当前代码 / 文档里自产**的候选 —— 回答「接下来还能往哪改」。
> 两者**来源不同、问题不同**；真要合并先想清楚（本项目「同一件事写两份」栽过跟头）。
>
> **记号**：❌ 未做 · ⚠️ 部分 · ✅ 已做 · 🚫 有意不做 · 🔒 你已定过的禁区
>
> **数字口径**：本文出现的计数**都是快照**（2026-10-13），标了「看命令」的以命令输出为准
> （`AGENT.md` 硬约束 8：会涨的数字不写死）。

## 一、结构收敛（同一个事实几处说）—— **最值钱的一类**

> 这一类的总病根（`Architecture Reality Audit.md` §0 原话）：
> **「不是概念太多，是同一个事实有好几种说法 + 几个子系统各判各的。」**
> 每条都实测复核过（行号与审计几乎逐字对上）。

### A1 · 权限 / 风险 / 范围判定分散在 5 套表达 ❌

- **现象**：同一件事（这个动作允不允许 / 危不危险 / 要不要问用户）在
  `risk.cjs` · `scale.cjs` · `capability.cjs` · `gate-denied.cjs` · `action.cjs` **各有一套**。
  `level` 字段在 risk 是「危险度四级」、在 scale 是「要不要问三级」—— **同名不同义**。
  实测：`capability.cjs:115` 的 `isInside`（realpath 口径）与 `scale.cjs:128` 的 `scopeOf`
  （命令文本 token 口径）**算的是同一件事、两个名字、两种算法**。
- **后果**：UI 要分两套解析；审计里 `permission` 与 `action.permission` **值域不通**。
- **规模**：改内核**判定逻辑** → 撞硬禁区 10（`risk/scale/capability`）。
- **建议**：**先做零代码的一步** —— 在 `安全模型.md` 加一节「输入 → 输出 → 归一取值」映射表
  （审计 §11 改进 A）。**先记账，不动判断逻辑**；归一另开专项。

### A2 · 渲染层 ↔ 持久化层之间没有形状自检 ❌（**性价比最高**）

- **现象**：内核存的字段形状变了，渲染层 TS 类型不会报错（`.cjs` 和 `.ts` 之间没有类型传递）。
  **真实漂过两次**：`src/types/models.ts:93-98` 的注释自认 `general.browserNavigation`
  内核侧有、渲染层类型漏了。
- **后果**：静默不一致（用户看到某功能「没反应」）。
- **规模**：**只加自检**（复刻 125 / 126 / 134 那套「从两侧源码抠出来真比一遍」）→ **不撞红线**。
- **建议**：**这是清单里第一个该做的**（见 §七）。

### A3 · Decision 没有任何落盘点 ❌

- **现象**：`decisions.cjs` **一个 `fs` 都没有**（实测 grep 无命中）；`events.cjs` **不落**
  `confirm_request`。也就是「用户当时批了什么 / 答了什么」**磁盘上查不到**。
- **后果**：不可回溯 —— 出了争议只能翻内存（早没了）。
- **规模**：要**新增落盘** → 撞数据结构（硬禁区 3），得写迁移。
- **建议**：**先只登记**。真要做得先回答「Decision 属于哪个实体」（硬禁区 11）。

### A4 · Task 字段有直写旁路（零校验）❌

- **现象**：`task-io.cjs` 直接 `stringify` 落盘，**没有形状校验**（比「两边各写一份」还松）。
  目前靠 `migrate` 兜住。
- **规模**：**先加形状自检**（不撞）—— 审计 §12 第 6 条明确：「先补形状自检，再谈别的」。
- **建议**：与 A2 同批做（同一个模式、同一类收益）。

### A5 · checkpoint 打两次点 ⚠️（同一件事两处写）

- **现象**：`tool-runner.cjs:287` 与 `loop-tools.cjs:201` **各写了一遍** `taskCore.checkpoint(...)`，
  连 label 字符串都逐字一样。
- **规模**：动**内核关键文件**（`loop-tools.cjs`）。
- **建议**：收敛成一处调用；**单独批**。

### A6 · 公共标识 `{sessionId, taskId}` 三处各写一遍 ❌

- **现象**：`decisions.cjs` · `events.cjs` · `audit.cjs` 各自组装这组字段，**没有共同定义**。
- **规模**：中；**这正是 C2 的下一条候选**（`docs/research/truth-map-design.md` §5 之后的条目）。
- **建议**：与 C2 同一条线走（逐条批准）。

### A7 · 状态词汇渲染层三套 + 内核一套 ❌

- **现象**：UI 视觉语言（`statusLanguage.ts`）、`TaskRecord.status`
  （`src/types/task.ts:60`，六种：`running/waiting_user/paused/completed/failed/cancelled`）、
  测试状态、内核相位 —— **四套词表**。
- **规模**：触数据结构（改 `TaskRecord.status` 就是硬禁区 11）。
- **建议**：**先不合并**，只在文档里列清「谁是谁」；真要统一另开专项。

### A8 · risk 危险模式判两遍（表 + 内联正则）❌

- **现象**：`risk-patterns.cjs` 的三张表是等级的实际来源，而 `risk.cjs:114/118` **又内联两张正则**
  算 `installs` / `elevation`（实测行号仍在）。`npm install`、`runas/sudo` 各判两遍。
- **规模**：撞硬禁区 10。**建议**：登记；动的时机与 A1 一起。

### A9 · 「同一件事的 5 种说法」还缺一份映射表 ❌

- **即 A1 的零代码版本**（审计 §11 改进 A）。**能先做、不撞红线。**

## 二、耦合与拆分

### B1 · `selftest.mjs` 的 GROUPS 是手写清单，已贴 300 行 ⚠️（**会一直挡路**）

- **现象**：每加一个自检组，都要在 `selftest.mjs` 加 1 行 `import` + 1 项 `GROUPS`。
  上轮加 `141` 组时，这个文件从 300 → **302 行**（超红线），只能**压注释**压回去。
- **后果**：**每加一组都要动这个文件、都可能纠一次行数** —— 结构性隐患，不是本次引入的。
- **规模**：改成「按编号自动发现 `groups/*.mjs`」或把 `GROUPS` 拆出去 → 动 `selftest.mjs` 入口。
- **建议**：**单独立项**（撞硬禁区 7「顺手重构」，不该顺手做）。

### B2 · `log.cjs` 是全仓头号地基 —— **知会项，不是待办** ✅

- **事实**：`npm run map` 的「扇入」段里，被引用最多的产品代码是 `core/log.cjs`
  （快照：被 91 个文件引用；最新看命令输出）。其后是 `paths.cjs` · `config.cjs` · `task.cjs` · `redact.cjs`。
- **意义**：**改 `log.cjs` 一行，波及面是整个内核** —— 该当「内核关键文件」对待。
- **建议**：不动代码；把这条写进「改它之前多跑一轮验证」的心智里（可挂进 `AGENT.md` 的核心理念区）。

### B3 · `parts.tsx` 挂在 `settings/` 却被全项目引用 ❌

- **事实**：扇入快照里唯一上榜的 UI 共享件是 `src/components/settings/parts.tsx`
  （被 33 个文件引用）。**目录名（settings）和实际角色（全局共享 UI）不匹配。**
- **建议**：归属收敛候选（挪到 `ui/` 或 `shared/`）；**纯展示层、回归面小**，随时可做。

### B4 · 环形依赖从没验证过 ❌

- **事实**：审计 §13 自己标的最大证据边界 ——「`electron/core/` 178 个模块之间的环形依赖**未验证**，
  §6 的『没发现环形依赖』是『本次抽样没看到』，不是『确认没有』」。
- **规模**：**只读、纯统计** → 不撞红线。`npm run map` 现在已能出扇入/扇出，
  **再加一段「找环」即可**（DFS / Tarjan，约 30 行）。
- **建议**：**性价比高**（一次就能从「没看到环」升级到「确认有没有环」）。

### B5 · `checks.mjs` 里还有一份 `SCAN` / `CODE_EXTS` 松散副本 ❌

- **现象**：`scripts/check-rules/checks.mjs:22-24` 注释写着「和 `tools/line-limit.mjs` 的 SCAN 保持一致」——
  **靠人记得保持一致**。上轮已把行数口径收进 `tools/line-count.mjs`，但这份副本还没收。
- **规模**：让 `checks.mjs` import `line-count.mjs`。**但 `checks.mjs` 已贴 300 行（293）**，
  动它要先拆。**建议**：与 B1 一起考虑（都是「入口文件贴线」问题）。

## 四、工具链与验证

### D1 · `contracts` 与真相源地图**没进任何闸门** ❌

- **现象**：`npm run contracts`（契约登记表）**没进 `verify`** ——
  表自己漂了（引用了不存在的文件）只有**手动跑**才看得见。`docs/真相源地图.md`
  **不在** `check-rules/checks-drift.mjs` 的 `WATCHED` 名单里 —— 谁往里抄计数不会报红。
- **规模**：D1a 加进 verify 链（动 `verify`，CI / pre-push 会一起变）；
  D1b 加进 WATCHED（动第 3 个文件，贴「3+ 文件」线）。
- **建议**：D1b 更简单、更值；D1a 要考虑「雷达不拦门」的分工（`dup` 一定不进门，`contracts` 可进）。

### D2 · 存量 `tmp/*.cjs` 没迁到探针骨架 ⚠️

- **现象**：`tools/probe.mjs`（有护栏：证据为空自动降级、`ready()` 前置检查、框架自测）只服务
  **新写的** `.mjs` 脚本；存量 `tmp/*.cjs` 一次性脚本**没有护栏**，但结论照样被当事实。
- **规模**：`tmp/` 是 gitignore 的，**可以不批量迁**（用完即弃）；但**下次写探针要用骨架**。
- **建议**：保持现状即可，**别为它专门开工**。

### D3 · `npm run dup` 的阈值是启发式的 ⚠️

- **现象**：A/B 段按「出现文件数」分组，阈值会随代码增长漂。
- **必须知道的事实**：它**只报告、退出码恒为 0、不进 verify** —— 这是**有意设计**
  （设计稿 §1：机械可以「找候选」，不可以「下判决」）。**⚠️ 别把它改成闸门。**

## 五、明确不做（🚫 —— 这一节和前几节一样值钱）

> 审计 §12 列了 **10 件「现在不该做」**，原话照抄（每条都指得住证据）：

1. 不要为「减少 Entity」删任何 Runtime 概念 —— 复杂度在这不是罪。
2. 不要给 Run / Turn / ToolCall 补独立实体 —— 除非实测证明需要跨进程恢复「半轮」。
3. 不要引入 Knowledge Entity / Vector DB / Knowledge Graph / Embedding Pipeline。
4. **不要重写 Event System** —— 它已是全仓收敛最好的一块（一处清单 + 自检 126 四路钉死）。
5. **不要重写 Context / Memory 子系统** —— 现有实现比多数「收敛方案」更细。
6. **不要全面替换 Task Model** —— **先补形状自检（就是 A2 / A4）**，再谈别的。
7. 不要按「8 阶段」顺序连推 —— 每步都撞红线，必须逐项批准。
8. 不要在没测到「模型认知负担」证据时改提示结构 —— 已核实无 ID 泄漏。
9. **不要把 risk 与 scale 合并成一个模块** —— 它们**正交**；要统一的是**输出表达**，不是模块。
10. 不要按**文件数 / 模块数**判断架构好坏，也不要把每个 `.cjs` 当 Entity。

**另外两条**：

- 🚫 **长任务上下文断层（架构级）**：曾判「先不做」；⚠️ 现在**部分已解** ——
  `project-facts.cjs`（派生视图，每轮重扫）覆盖了浅层。**深层仍缺**，但别当新活重做。
- 🚫 **CI 里跑端到端打包**：`ci.yml` 注释写明有意不做（要 Windows + 几分钟）；
  替代品是真机工具 `npm run shot:electron`（手动跑）。

## 七、建议顺序（如果只做 5 件）

> 排序依据**不是「看着重要」**，是「**改动最小 + 能单独验证 + 不撞红线**」（审计 §11 的口径）。

| 先做 | 为什么是它 |
|---|---|
| **1. A2 + A4（形状自检）** | **不撞红线**、纯新增自检、复用现成模板（125/126/134）；堵的是**真实漂过 2 次**的缝。审计 §12 第 6 条也点名「先补形状自检」 |
| **2. D1b（真相源地图进 WATCHED）** | 一行改动，防住「文档里又抄计数」；顺带把 C 任务的成果焊死 |
