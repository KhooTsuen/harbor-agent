## 一、结构收敛（同一个事实几处说）—— **最值钱的一类**

> 这一类的总病根（`Architecture Reality Audit.md` §0 原话）：
> **「不是概念太多，是同一个事实有好几种说法 + 几个子系统各判各的。」**
> 每条都实测复核过（行号与审计几乎逐字对上）。

### A1 · 权限 / 风险 / 范围判定分散在 5 套表达 ❌

- **现象**：同一件事（这个动作允不允许 / 危不危险 / 要不要问用户）在
  `risk.cjs` · `scale.cjs` · `capability.cjs` · `gate-denied.cjs` · `action.cjs` **各有一套**。
  `level` 字段在 risk 是「危险度四级」、在 scale 是「要不要问三级」—— **同名不同义**。
  实测：`capability.cjs:115` 的 `isInside`（realpath 口径）与 `scale.cjs:128` 的 `scopeOf`
  （命令文本 token 口径）**算的是同一件事、两个名字、两种算法**。
- **后果**：UI 要分两套解析；审计里 `permission` 与 `action.permission` **值域不通**。
- **规模**：改内核**判定逻辑** → 撞硬禁区 10（`risk/scale/capability`）。
- **建议**：**先做零代码的一步** —— 在 `安全模型.md` 加一节「输入 → 输出 → 归一取值」映射表
  （审计 §11 改进 A）。**先记账，不动判断逻辑**；归一另开专项。

### A2 · 渲染层 ↔ 持久化层之间没有形状自检 ❌（**性价比最高**）

- **现象**：内核存的字段形状变了，渲染层 TS 类型不会报错（`.cjs` 和 `.ts` 之间没有类型传递）。
  **真实漂过两次**：`src/types/models.ts:93-98` 的注释自认 `general.browserNavigation`
  内核侧有、渲染层类型漏了。
- **后果**：静默不一致（用户看到某功能「没反应」）。
- **规模**：**只加自检**（复刻 125 / 126 / 134 那套「从两侧源码抠出来真比一遍」）→ **不撞红线**。
- **建议**：**这是清单里第一个该做的**（见 §八）。

### A3 · Decision 没有任何落盘点 ❌

- **现象**：`decisions.cjs` **一个 `fs` 都没有**（实测 grep 无命中）；`events.cjs` **不落**
  `confirm_request`。也就是「用户当时批了什么 / 答了什么」**磁盘上查不到**。
- **后果**：不可回溯 —— 出了争议只能翻内存（早没了）。
- **规模**：要**新增落盘** → 撞数据结构（硬禁区 3），得写迁移。
- **建议**：**先只登记**。真要做得先回答「Decision 属于哪个实体」（硬禁区 11）。

### A4 · Task 字段有直写旁路（零校验）❌

- **现象**：`task-io.cjs` 直接 `stringify` 落盘，**没有形状校验**（比「两边各写一份」还松）。
  目前靠 `migrate` 兜住。
- **规模**：**先加形状自检**（不撞）—— 审计 §12 第 6 条明确：「先补形状自检，再谈别的」。
- **建议**：与 A2 同批做（同一个模式、同一类收益）。

### A5 · checkpoint 打两次点 ⚠️（同一件事两处写）

- **现象**：`tool-runner.cjs:287` 与 `loop-tools.cjs:201` **各写了一遍** `taskCore.checkpoint(...)`，
  连 label 字符串都逐字一样。
- **规模**：动**内核关键文件**（`loop-tools.cjs`）。
- **建议**：收敛成一处调用；**单独批**。

### A6 · 公共标识 `{sessionId, taskId}` 三处各写一遍 ❌

- **现象**：`decisions.cjs` · `events.cjs` · `audit.cjs` 各自组装这组字段，**没有共同定义**。
- **规模**：中；**这正是 C2 的下一条候选**（`docs/research/truth-map-design.md` §5 之后的条目）。
- **建议**：与 C2 同一条线走（逐条批准）。

### A7 · 状态词汇渲染层三套 + 内核一套 ❌

- **现象**：UI 视觉语言（`statusLanguage.ts`）、`TaskRecord.status`
  （`src/types/task.ts:60`，六种：`running/waiting_user/paused/completed/failed/cancelled`）、
  测试状态、内核相位 —— **四套词表**。
- **规模**：触数据结构（改 `TaskRecord.status` 就是硬禁区 11）。
- **建议**：**先不合并**，只在文档里列清「谁是谁」；真要统一另开专项。

### A8 · risk 危险模式判两遍（表 + 内联正则）❌

- **现象**：`risk-patterns.cjs` 的三张表是等级的实际来源，而 `risk.cjs:114/118` **又内联两张正则**
  算 `installs` / `elevation`（实测行号仍在）。`npm install`、`runas/sudo` 各判两遍。
- **规模**：撞硬禁区 10。**建议**：登记；动的时机与 A1 一起。

### A9 · 「同一件事的 5 种说法」还缺一份映射表 ❌

- **即 A1 的零代码版本**（审计 §11 改进 A）。**能先做、不撞红线。**

## 二、耦合与拆分

### B1 · `selftest.mjs` 的 GROUPS 是手写清单，已贴 300 行 ⚠️（**会一直挡路**）

- **现象**：每加一个自检组，都要在 `selftest.mjs` 加 1 行 `import` + 1 项 `GROUPS`。
  上轮加 `141` 组时，这个文件从 300 → **302 行**（超红线），只能**压注释**压回去。
- **后果**：**每加一组都要动这个文件、都可能纠一次行数** —— 结构性隐患，不是本次引入的。
- **规模**：改成「按编号自动发现 `groups/*.mjs`」或把 `GROUPS` 拆出去 → 动 `selftest.mjs` 入口。
- **建议**：**单独立项**（撞硬禁区 7「顺手重构」，不该顺手做）。

### B2 · `log.cjs` 是全仓头号地基 —— **知会项，不是待办** ✅

- **事实**：`npm run map` 的「扇入」段里，被引用最多的产品代码是 `core/log.cjs`
  （快照：被 91 个文件引用；最新看命令输出）。其后是 `paths.cjs` · `config.cjs` · `task.cjs` · `redact.cjs`。
- **意义**：**改 `log.cjs` 一行，波及面是整个内核** —— 该当「内核关键文件」对待。
- **建议**：不动代码；把这条写进「改它之前多跑一轮验证」的心智里（可挂进 `AGENT.md` 的核心理念区）。

### B3 · `parts.tsx` 挂在 `settings/` 却被全项目引用 ❌

- **事实**：扇入快照里唯一上榜的 UI 共享件是 `src/components/settings/parts.tsx`
  （被 33 个文件引用）。**目录名（settings）和实际角色（全局共享 UI）不匹配。**
- **建议**：归属收敛候选（挪到 `ui/` 或 `shared/`）；**纯展示层、回归面小**，随时可做。

### B4 · 环形依赖：**已实测 —— 有 11 个真环**（2026-10-13）⚠️

- **原来**：审计 §13 把「环形依赖」列为最大的证据边界（「未验证」）。
- **现已验证**（只读全仓扫描，展开见 §五 E1）：`electron/core` **有 11 个真实环**，
  全部用「惰性 require」破了（未破的环 = 0）—— 所以审计 §9.2 的「**没发现环形依赖**」**不成立**。
- **真正的缺口不是环本身，是「无人盯环」**：新增一条顶层 `require` 造出新环、
  或把某条破环软边挪到顶层，**没有任何东西会报红**。
- **建议**：见 §五 E1（先加只读「找环」报告，再把「未破的环 = 0」钉成断言）。

### B5 · `checks.mjs` 里还有一份 `SCAN` / `CODE_EXTS` 松散副本 ❌

- **现象**：`scripts/check-rules/checks.mjs:22-24` 注释写着「和 `tools/line-limit.mjs` 的 SCAN 保持一致」——
  **靠人记得保持一致**。上轮已把行数口径收进 `tools/line-count.mjs`，但这份副本还没收。
- **规模**：让 `checks.mjs` import `line-count.mjs`。**但 `checks.mjs` 已贴 300 行（293）**，
  动它要先拆。**建议**：与 B1 一起考虑（都是「入口文件贴线」问题）。

## 四、工具链与验证

### D1 · `contracts` 与真相源地图**没进任何闸门** ❌

- **现象**：`npm run contracts`（契约登记表）**没进 `verify`** ——
  表自己漂了（引用了不存在的文件）只有**手动跑**才看得见。`docs/真相源地图.md`
  **不在** `check-rules/checks-drift.mjs` 的 `WATCHED` 名单里 —— 谁往里抄计数不会报红。
- **规模**：D1a 加进 verify 链（动 `verify`，CI / pre-push 会一起变）；
  D1b 加进 WATCHED（动第 3 个文件，贴「3+ 文件」线）。
- **建议**：D1b 更简单、更值；D1a 要考虑「雷达不拦门」的分工（`dup` 一定不进门，`contracts` 可进）。

### D2 · 存量 `tmp/*.cjs` 没迁到探针骨架 ⚠️

- **现象**：`tools/probe.mjs`（有护栏：证据为空自动降级、`ready()` 前置检查、框架自测）只服务
  **新写的** `.mjs` 脚本；存量 `tmp/*.cjs` 一次性脚本**没有护栏**，但结论照样被当事实。
- **规模**：`tmp/` 是 gitignore 的，**可以不批量迁**（用完即弃）；但**下次写探针要用骨架**。
- **建议**：保持现状即可，**别为它专门开工**。

### D3 · `npm run dup` 的阈值是启发式的 ⚠️

- **现象**：A/B 段按「出现文件数」分组，阈值会随代码增长漂。
- **必须知道的事实**：它**只报告、退出码恒为 0、不进 verify** —— 这是**有意设计**
  （设计稿 §1：机械可以「找候选」，不可以「下判决」）。**⚠️ 别把它改成闸门。**

## 五、地基层体检（只读全仓扫描 · 2026-10-13）

> 这一节**不是抄现有文档**，是**一次只读全仓扫描**的产出 —— 目标是把「地基」层面的问题挖出来。
> 每条写了**复算方式**；扫描脚本是一次性的（`tmp/` 已清）。
> ⚠️ 下面的数**都是快照**（2026-10-13），代码在涨，以复算为准。

### E1 · ⚠️ 环形依赖：实测 **11 个真环**（推翻审计 §9.2 的「没发现环形依赖」）

- **实测**：`electron/core` **222** 个模块，去注释后**发现 11 个环**（清单见下），
  **全部至少有一条「函数内 require」**（惰性 require 破环）→ **未破的环 = 0**。
  审计 §9.2 把「没发现环形依赖」当成「不是问题」；**这次是「确认有 11 个」，不是「抽样没看到」**。
- **环清单**（按边数）：
  - `loop.cjs → loop-run.cjs → loop.cjs`
  - `task-io.cjs → task-index.cjs → task-io.cjs`
  - `changeset.cjs → changeset-rollback.cjs → changeset.cjs`
  - `projects.cjs → session.cjs → session-read.cjs → projects.cjs`
  - `projects.cjs → session.cjs → session-write.cjs → projects.cjs`
  - `tools/index.cjs → plugin-tool → permission → registry → subagent-tool → subagent → loop → tools/index.cjs`（7 边）
  - `loop-prompt.cjs → …（同一条链）→ loop-prompt.cjs`（8 / 9 / 10 边，共 5 条变体）
- **为什么「用惰性 require 破了」不等于「没问题」**：破环 = 把 `require` 挪进函数体，
  代价是**把「加载期错误」换成了「运行期错误」** —— 加载期的环会**立刻崩**（好在发现），
  运行期的惰性 require 拿不到就是**静默的 `undefined`**。本项目**有过这种先例**
  （自检 `12-requires` + 内核 lint 就是为「搬家剩旧名字 → ReferenceError」立的）。
- **最要命的**：**没有任何自检盯着「环」**。新增一条顶层 `require` 又造出一个环、
  或把某条破环软边挪到顶层，**没人会报红**。
- **规模**：**只读、纯统计** → 不撞红线。加一个「找环」自检（约 30–40 行，复用 `npm run map` 的依赖图）。
- **建议**（**本清单最该先做的自检之一**）：① 先加只读「找环」报告（像 `map` 那样只列出、不拦门）；
  ② 再把「**未破的环 = 0**」钉成断言 —— 这是**当前事实、也是安全底线**（未破的环会崩）。

### E2 · ⚠️ 原子写覆盖不全：`safe-write` 只护住 7 个模块，用户数据仍大量裸写

- **`safe-write.cjs` 的存在理由（它自己的文件头原话）**：
  > 「直接 `fs.writeFileSync(整个文件)` 是『先截断、再写』：写到一半崩溃 / 断电 / 被杀，
  > 文件只剩前半截。**会话与记忆都是用户一点点攒出来的，不能这么丢。**」
- **实测**：用 `writeAtomic`（原子写）的模块只有 **7 个** ——
  `download-store` · `memory-store` · `projects` · `schedule-store` ·
  `session-compact` · `session-crypto` · `session-io`。
- **但下面这些同样写「用户数据」的模块，仍是裸 `fs.writeFileSync(整个文件)`**：

  | 文件 | 写什么 | 坏了会怎样 |
  |---|---|---|
  | `electron/core/task-io.cjs:47` | **任务台账** | 台账损坏（用户任务没了） |
  | `electron/core/config.cjs:129` | **用户配置** | 配置损坏 |
  | `electron/core/credentials.cjs:82` | **凭证** | 密钥丢失 |
  | `electron/core/changeset.cjs:87` | **改动事务 meta** | **撤不回去** |
  | `electron/core/artifact.cjs:96` | 产物 meta | 产物索引坏 |
  | `electron/core/task-index.cjs:77` | 任务索引 | 索引漂移 |
  | `electron/core/capability.cjs:72` | 路径授权表 | 授权丢失 |

- **为什么是「地基」问题**：同一个事实（**怎么安全地覆盖一个用户数据文件**）**有两套做法** ——
  memory / session 走原子写，task / config / credentials 不走。**标准不统一**，
  且违背项目理念「**用户永远拥有数据**」与硬约束 5（不能丢用户数据）。
- **规模**：让这些模块改 import `safe-write` → **动 6–8 个内核文件**（撞硬禁区，需逐条批）。
- **建议**：**先做零代码的一步** —— 写一条**只读检查**，列出「写 `data/` 下用户数据文件、
  但没走 `writeAtomic`」的模块（把口径钉住）；**再逐条批准**迁到原子写。
  （口径：**只有「覆盖写用户数据」才算** —— `log.cjs` / `events.cjs` / `audit.cjs` 等
  **追加式**日志用 `appendFileSync` **是合理的**，不在本条范围。）

### E3 · `newId` 在 **8 个模块各写一遍**，格式还不一致

- **实测**：`findstr /n "function newId" electron\core\*.cjs` → **8 处**：
  `artifact` · `changeset` · `confirm-bridge` · `download-store` ·
  `memory-schema` · `schedule-store` · `session-io` · `task-io`。
- **格式三种**：
  - `art_` + base36 + rand4（**无下划线**）
  - `mem_` / `task_` / `cs_` / `dl_` / `sch_` + base36 + `_` + rand4（**有下划线**）
  - `sess_` + base36 + rand**5**（无下划线）
- **隐式契约没被强制**：`session-io.cjs:31` 注释自述「会话 id 的白名单：`sess_` + 小写字母数字」
  —— **存在一个 id 格式契约，但它是靠注释说的，没有自检**。
- **后果**：哪天要统一 id 策略（加时间排序 / 加长度限制 / 加前缀校验），**要改 8 处、必漏一处**。
- **规模**：抽一个 `id.cjs`（`newId(prefix, {sep})`）→ 动 8 个内核文件 ± 自检。
  属 C 任务同类（「同一个事实多处说」），**登记，择日单独批**。

### E4 · 状态词汇散落在 **~90 个文件**（A7 的规模证据）

- **实测**：直接写状态字面量（`status: 'running'` / `'running' |` 联合类型）的文件 **~90 个**（含测试）；
  产品代码里 `src/types/task.ts` · `src/lib/statusLanguage.ts` · `src/types/conversation.ts` ·
  `electron/core/task.cjs` · `subagent.cjs` · `download-queue.cjs` 等。
  更高频的是**裸出现**：`'failed'` 出现在 **71** 个文件、`'completed'` 60、`'paused'` / `'running'` 各 49。
- **意义**：这是 A7「状态词汇渲染层三套 + 内核一套」的**量化证据** ——
  不是「几个枚举对不上」，是**状态词像散沙一样撒在全仓**。
- **建议**：与 A7 一起看；**先别合并**（撞数据结构），先做「**状态词该来自哪个枚举**」的登记（C 任务手法）。

### E5 · 贴线文件 **72 个（产品代码）**，其中 **6 个正好 300 行**

- **实测**：`≥270 行` 的文件 **106 个**，其中**产品代码 72 个**、测试/脚本 34 个。
  **正好 300 行**（贴着红线站）的有 6 个产品文件：
  `config.cjs` · `llm.cjs` · `mcp-connection.cjs` · `search.cjs` ·
  `handlers/safety.cjs` · `main.cjs`（另有 `scripts/selftest.mjs`）。
- **意义**：B1（`selftest.mjs` 贴线）**不是孤立现象** —— **整个地基层都贴线**。
  下次任何人往这些文件加一行，都得先拆。**这是「越做越大」最直观的症状。**
- **建议**：不批量拆（撞硬禁区 7）；但**新活一律别往贴线文件里塞**，先问「它该住哪」。
  `check:lines` 已有 `--warn=270` 告警带（只提示、不判红），可据此安排。

### E6 · 空 `catch` 块 **10 处**（吞异常）

- **实测**：`audit` · `backup` · `browse-ops` · `browse-settle` · `config` ·
  `credentials` · `image-task` · `pty` · `safe-write` · `session-write` —— 各 1 处。
- **说明**：**不一定是 bug**（有的是「删了就跳过」「尽力而为」的合理场景），
  但**没有一处写了「为什么可以吞」**。项目自己的教训是「**无声异常最查不出来**」
  （`doneUnblocks.test.ts` 文件头记的「收尾被吞进订阅回调、事后查不到」就是这个形状）。
- **建议**：**低优先**。逐处过一遍，该留注释的补一句「为什么这里可以吞」。

### E7 · 耦合中心：`register-handlers.cjs` 扇出 **35**

- **实测**（扇出 = 引用的模块数）：`electron/register-handlers.cjs` **35** ·
  `main.cjs` 25 · `loop.cjs` 22 · `tools/registry.cjs` 22 · `loop-prompt.cjs` 21。
- **说明**：`register-handlers` 是 IPC 处理器的总装配点，扇出大是**它存在的目的**（可接受）。
  真正要留意的是 **`loop-prompt.cjs`（扇出 21）** —— 审计 §9.1 已点名它「单点耦合 7–8 个子系统」，
  这里给了数字：**改任何一侧都要动这个内核关键文件**。
- **建议**：登记；与 A1 / A5 一起，作为「内核关键文件别乱动」的量化依据。

## 六、明确不做（🚫 —— 这一节和前几节一样值钱）

> 审计 §12 列了 **10 件「现在不该做」**，原话照抄（每条都指得住证据）：

1. 不要为「减少 Entity」删任何 Runtime 概念 —— 复杂度在这不是罪。
2. 不要给 Run / Turn / ToolCall 补独立实体 —— 除非实测证明需要跨进程恢复「半轮」。
3. 不要引入 Knowledge Entity / Vector DB / Knowledge Graph / Embedding Pipeline。
4. **不要重写 Event System** —— 它已是全仓收敛最好的一块（一处清单 + 自检 126 四路钉死）。
5. **不要重写 Context / Memory 子系统** —— 现有实现比多数「收敛方案」更细。
6. **不要全面替换 Task Model** —— **先补形状自检（就是 A2 / A4）**，再谈别的。
7. 不要按「8 阶段」顺序连推 —— 每步都撞红线，必须逐项批准。
8. 不要在没测到「模型认知负担」证据时改提示结构 —— 已核实无 ID 泄漏。
9. **不要把 risk 与 scale 合并成一个模块** —— 它们**正交**；要统一的是**输出表达**，不是模块。
10. 不要按**文件数 / 模块数**判断架构好坏，也不要把每个 `.cjs` 当 Entity。

**另外两条**：

- 🚫 **长任务上下文断层（架构级）**：曾判「先不做」；⚠️ 现在**部分已解** ——
  `project-facts.cjs`（派生视图，每轮重扫）覆盖了浅层。**深层仍缺**，但别当新活重做。
- 🚫 **CI 里跑端到端打包**：`ci.yml` 注释写明有意不做（要 Windows + 几分钟）；
  替代品是真机工具 `npm run shot:electron`（手动跑）。

> 排序依据**不是「看着重要」**，是「**改动最小 + 能单独验证 + 不撞红线**」（审计 §11 的口径）。
