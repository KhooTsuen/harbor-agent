## 2. 逐项展开

### ① CE-018 · 首轮缓存优化（`7373d2b`）

**问题（真实 usage 实测）**：所有提示层以前拼在**同一条** system message 里。服务端 prompt 缓存是**前缀匹配** ——
易变区（记忆 / 任务状态 / 会话状态 / 当前时间）动一个字，它**后面**的一切（含整段历史消息，可达 4~12 万 token）
全部失效。命中约 3,700 token ≈ 稳定区大小，断点正好在易变区开头。

**受控 A/B**（同一段 4 万 token 真实历史、同一任务、只改易变层位置、真实 DeepSeek usage）：

| 组 | 结构 | prompt | hit | **miss** | 命中率 |
|---|---|---|---|---|---|
| A 现状 | `[{system: S+V}, ...H]` | 54,847 | 8,960 | **45,887** | 16.3% |
| B 候选 | `[{system: S}, ...H, {system: V}]` | 54,848 | 54,656 | **192** | 99.6% |

**同一次调用少 45,695 未命中 token**；三轮重复、V 每轮唯一，结果完全一致。

**改法**：`prompt-stack.splitMessages` 按 ORDER 派生的稳定名单把层拆成两条（**唯一真相源，不另立名单**）；
`loop-prompt.cjs` 拼成 `[稳定区, ...历史, 易变区]`。**层内容一字未改、角色仍是 system** —— 只挪位置。
拆出的两条拼回来与旧的 `build().message` **逐字节相同**（自检 `148-prompt-split.mjs` 钉着）。

**刻意不做**：不降级成 user 消息（会削弱指令权威性 —— 实测 system 中间/末尾 DeepSeek 均接受且模型正确遵循）；
不碰 compact；不删工具历史；不动严格模式 / 记忆检索 / 安全层。

**前置验证**：DeepSeek 接受中间/末尾的 system message（三组都 200、`finish=stop`、模型正确答出上下文里的数字）。

**回归**：工具调用正常（B 结构下 `list_dir` 照常调到）；带「必须遵守」指令时照做；
`npm run verify` 全绿、内核自检 **4371 / 0**（+4）。提示词版本 `prompt-stack/11 → /12`。

**真机确认**：源码树里一个真实会话第 1 轮命中率 45.4%（首次全价）、第 2 轮 **92.4%（miss 仅 576）** —— 历史全部命中。

### ② 功能 B · 余额查询（`50b78ac`）

**官方端点**（查的是官方文档，不是凭记忆）：
`GET https://api.deepseek.com/user/balance`，`Authorization: Bearer <key>`，
返回 `{ is_available, balance_infos: [{ currency, total_balance, granted_balance, topped_up_balance }] }`。
来源：https://api-docs.deepseek.com/zh-cn/api/get-user-balance/

★ **端点不在 `/v1` 下**（供应商 baseUrl 是 `https://api.deepseek.com/v1`）—— 用 `buildUrl` 会拼成
`.../v1/user/balance` → 404。所以取 baseUrl 的 **origin** 再拼 `/user/balance`。

**三条硬规矩**：
- **只由用户点击触发** —— 渲染层无 `useEffect` / `setInterval` / `setTimeout`（自检钉着）；
- **「上次查询时间」只存内存** —— 瞬时提示，不值得为它动数据结构；
- **余额是字符串，绝不 `Number()`** —— 接口少给字段时 `undefined + 数字 = NaN`，界面会显示「余额 NaN」。

**失败不崩**（三条路都回 `{ok:false,error}`）：网络不通 / Key 无效（401、403）/ 接口变更（404、非 JSON、schema 认不出）。
非 DeepSeek 供应商**当场说不支持**，不发那个必然 404 的请求。

**凭证**：走 `config.hasKey()` / `config.providerKey()`（与 `provider:ping` 完全同一条），**不新增凭证存储位置**。

**IPC**：必须新增 `provider:balance`，**不能复用**现有通道（`provider:ping` 是 POST 到 chatPath 测对话、
`listModels` 是 GET `/models`、`stats:summary` 是纯本地读 jsonl）。
**三处同步**（少一处就静默失效）：`EXPECTED_CHANNELS` + `preload.cjs` + core `llm-probe.getBalance()`。

**真机走查**：源码树 Electron → 设置 → 数据与用量 → 真实点「查询」→ 真实 IPC → 真实 DeepSeek 接口 →
显示 **`8.13 CNY`**、赠金 0.00 · 充值 8.13、上次查询 03:34:55；**点击前显示「从未查询」**（证明不是加载即请求）。

**验证**：内核自检 **4391 / 0**（+20）。

### ③ 功能 A-采集 · 推理 token（`e6c9651`）

**为什么**：用量里只有「入 / 出」，而推理模型把输出的一大块花在**思考**上 —— 单看「出」看不出贵在哪。
上游一直在返回 `completion_tokens_details.reasoning_tokens`，但内核**一处都没读**
（实测 `llm.cjs` / `budget.cjs` / `stats.cjs` / `token-metrics.cjs` 四个文件里 `reasoning_tokens` **零出现**）。

**形状唯一真相源**：`budget.usageParts()` 由 `{total,input,output}` 扩成 `{total,input,output,reasoning}`；
取法收在一个新函数 `budget.reasoningOf()`（别处不许再写一遍字段路径）。

★ **`reasoning` 属于 `completion`** → 「输出 = 思考 + 非思考输出」，**不是并列两桶**；
`total` / `input` / `output` 的算法**一字未动**（自检钉着）。

**null 与 0 分得开**：上游没给 → `null`（`logLlm` 落盘记 null），给了 0 → `0`。

**老数据不炸（本轮重点）**：`stats.load()` 以前只给 `total` 补键，`byDay` / `byModel` 直接透传 ——
新字段在老桶上会是 **undefined 一路带给界面**。现在三种桶都过 `emptyBucket()` 补键；
`addInto` 累加用 `(Number(bucket.reasoning) || 0)` 兜底，**防 undefined 累成 NaN**。

**真机数据**：

| 指标 | 值 |
|---|---|
| 新增的 4 行 token-metrics | 全部带 `reasoning`（`30 / 131 / 45 / 256`），均 number 且 ≤ `completion` |
| `stats.total.reasoning` | `0 → 161`（正好 = 主循环那两条 `30 + 131`） |
| 违反「reasoning ≤ completion」 | 0 |
| NaN 检查 | 无 |

> `token-metrics` 记**全部**调用（含场景，合计 462），`stats` 只记**主循环**（161）——
> 两个口径不同，数字对不上是设计如此。

**验证**：内核自检 **4408 / 0**（+17）。隔离探针三态可分：有值 → `30`、无 details → `null`、给了 0 → `0`。

### ④ 功能 A-展示 第一批 · 配置层（`a508a72`）

**为什么**：用量页要显示「折算多少钱」，就必须有单价。而单价**不能硬编码** ——
官方分**高峰 / 空闲**两档（空闲 = 高峰 ÷ 2；高峰 = 北京时间周一至周五 9:00–12:00、14:00–18:00），
且随时会调价；换供应商更是完全不同。

**结构**（`config.json` 顶层新增）：

```json
"pricing": {
  "currency": "CNY",
  "unit": "perMillionTokens",
  "peakMode": "auto",
  "providers": {
    "deepseek": {
      "deepseek-flash": {
        "inMiss": { "peak": 2, "offPeak": 1 },
        "inHit":  { "peak": 0.04, "offPeak": 0.02 },
        "out":    { "peak": 8, "offPeak": 4 }
      }
    }
  }
}
```

内置默认值来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/（2026-10-15 读取）。

**不猜价**：三项缺一 → 该模型整份不可用（返回 `null`，界面显示「未配置单价」而不是 ¥0.00）；
官方价页**已不再列**的老模型名（`deepseek-chat` / `deepseek-reasoner`）**故意不编价**。

**老配置兼容（三层，核心是归一化）**：
`config-defaults.cjs` 给默认值（价目表拆到 `pricing-defaults.cjs`）→
**`config-normalize.cjs` 的 `normalizePricing`（命门：不在白名单 = 改了被静默丢掉）** →
`config.cjs` 的 `patch()` 加 `providers` 单独深合并。
归一化是**深合并**：老配置无 `pricing` 段自动补全；用户只填一部分（如只写 `out`）时缺的键**回落默认**。

**验收（三份真机旧配置，只读）**：

| 真实文件 | 原文件有 pricing | 归一后 | 老字段 |
|---|---|---|---|
| `E:\Harbor\data\config.json` | ❌ | ✅ 补全（CNY / auto） | `general.workdir` 在、providers **2 个**没丢 |
| `E:\CodexWorkbench\data\config.json` | ❌ | ✅ 补全 | 在、providers 1 个没丢 |
| `Harbor-Dev\...\data\config.json` | ❌ | ✅ 补全 | 在、providers 2 个没丢 |

深合并 / 单档归一 / 坏值兜底 **8 个用例全过**。

**顺带**：`selftest.mjs` 已 300 行满，分组清单抽到 `scripts/selftest/groups.mjs`（主文件 300 → 34 行）；
`12-requires.mjs` 的「每组都挂在清单上」守卫改成**两份都扫**（清单搬到哪都在网里，不静默失效）。

**验证**：内核自检 **4418 / 0**（+10）。

### ⑤ 功能 A-展示 第二批 · 折算层（`ee11aee`）

**`src/lib/pricing.ts`（新增，161 行）**

- `priceOf(pricing, providerId, model)` —— **三级匹配**：
  ① 精确 `providers[p][m]`；② `providerId` 对不上时全库找同名模型，**恰好一个声明者**才用
  （实测 `stats.byModel` **只存模型名、没有 providerId** → 第二级是主路径）；③ 其余一律 `null`。
  ★ **不猜价**：价不完整（缺项 / NaN）→ `null`；精确命中不完整时**不回退到别家**；
  同名模型出现在两个供应商下 → `null`。
- `estimateCost(tokens, price, pricing, now)` —— 双档折算，**只按当前时刻估**
  （`auto` 判此刻是高峰还是空闲，对**全部** token 用同一档）。
  `stats.json` 的聚合桶**没有时刻** → 逐笔精确分档做不到 —— 这是估算，不是账单。
- `isPeakTime` / `tierOf` —— 北京时间（硬 +8，**跟随官方而非本机时区**），区间**左闭右开**
  （12:00 整、18:00 整算空闲），周末全天空闲。⚠️ **判不了法定节假日**（没有日历表）。
- **推理不是独立桶**：返回形状里**没有** `reasoning` 这一项（单测钉着 `Object.keys` 的集合）。

**`src/lib/format.ts`**：新增 `formatMoney(value, currency)` —— 内置 `Intl.NumberFormat`，**零新依赖**。
`< 0.01` 元时给 4 位小数（缓存命中价低到「每百万 0.02 元」，两位小数会一律显示 `¥0.00`，看着像不要钱）；
`NaN` / `Infinity` 当 0。

**验证**：`pricing.test.ts`（24 条）+ `format.test.ts`（10 条），**34/34 通过**。
覆盖：三级匹配（含同名冲突 / 价不完整不回退）、双档与单档、**高峰/空闲边界**（12:00 / 18:00 / 周末 / 跨时区）、
`auto` 按传入时刻判档、token 缺字段不 NaN。
时刻用**固定日期**（2026-10-15 周四）构造，不依赖跑测试的当下。

### ⑥ 功能 A-展示 第三批 · 展示层（`b6e4c74`）

**做什么**：设置 →「数据与用量」→「用量」节下方新增「花费构成」：四格
（输入未命中 / 输入命中 / 输出（含推理）/ 其中·推理），各显示 token + 估算金额，下面一行合计；
「按模型」「最近 30 天」每行右侧补一句金额。

**★ 三条口径写进界面（不只是注释）**：
① **估算不是账单**（`auto` 只按此刻那一档；且判不了法定节假日）—— 四条提醒都在 UI 上；
② **推理不是独立计费桶**（推理那一格**不给金额**，再算一次就是重复计费）；
③ **查不到价就只显示 token**，一个金额都不显示，并写「未配置单价」。

**口径细节**：输入未命中走 `prompt − cached`（**不用 `cacheMiss`** —— 实测 5702 行里漏 64 行）；
按模型逐条折算（准确），按天按 token 比例**分摊**总额（天桶没有模型名，各天之和 = 总额）。

**真机走查（源码树 Electron，读回的真实数字）**：

```
花费构成          按当前时段价估算 · 此刻是空闲价
输入未命中（全价）  413,395   ¥0.41   共输入 2,098,259，未命中占 20%
输入命中（缓存）   1,684,864  ¥0.03   占输入 80% · 单价便宜得多
输出（含推理）      108,604   ¥0.43   推理 0% 已在其中计费
其中 · 推理            161   （无金额）  属于输出的一部分，不单独计价
合计（估算）                  ¥0.87
```

**对账（可复核）**：
- `413,395 = 2,098,259 − 1,684,864` → 走的是 `prompt − cached`，不是 `cacheMiss`；
- `¥0.87 = 0.41 + 0.03 + 0.43` → 推理没有重复计入；
- `deepseek-chat` 那行**没有金额**（价目表里没有它 → 不猜价），提醒里「有 1 个模型没配单价」正好对上。

**范围说明**：`UsageTab.tsx` 改前已顶到 300 行，在单文件里塞进整节必然破限，
故按项目惯例把 `StatCard` 与整节 `CostBreakdown` 抽到 `parts/`（`UsageTab` 300 → 199 行）。用户已批准。

**边界**：零新依赖（测试用内置 `react-dom/server`，**没有**引 `@testing-library/react`）；
零新 IPC；未碰 `electron/**` / `limits.cjs` / `compact` / 安全层 / 严格模式 / 防闪烁三件套。

**验证**：`npm run verify` 全绿（单测 **194 文件 / 1763 用例**）；`costBreakdown.test.tsx` 12 条断言。

## 3. 观察期指标（每天看什么、怎么取数）

### 指标 1 · 每天的实际花费

**取数**：设置 → 数据与用量 →「花费构成」的**合计（估算）**；或「最近 30 天」每行右侧的金额。

**口径**：按 `pricing.peakMode`（默认 `auto` = 当前时段那一档）折算，单位「元 / 百万 tokens」。
**这不是账单** —— 高峰/空闲差一倍、判不了法定节假日。对账请以 DeepSeek 官方账单为准。

> 现状快照（2026-10-15，按**空闲档**口径、deepseek-flash 价折算，取自源码树 `token-metrics.jsonl`，覆盖 10/7–10/15）：

| 2026-10-08 | ¥0.0075 | 5,401 | 11,264 | 461 |

（10-15 只有半天数据，且 10-14/10-15 正是做这三批开发的日子 —— 这两天的量不代表日常使用。）

### 指标 2 · 每任务的单位成本

**取数**：`token-metrics.jsonl` 按 `trace`（`req_*`）聚合，逐任务折算。
**⚠️ 局限（必须知道）**：该文件**只滚动保留 6MB**，历史明细有限；`stats.json` **没有任务维度**
（「按任务」是**未做**的维度 —— 缺 `taskId` 关联键，属另一轮）。
所以这项指标只能看**近期窗口**，看不了长期。

> 现状快照（同一窗口，70 个有 trace 的任务）：合计估算 **¥0.88**，**平均每任务 ¥0.0126**。
> 最贵的 5 个任务在 ¥0.038–0.078 之间（10–12 轮，未命中 7.6k–25.5k）。

2. **结构指标（更该看的）**：按「这是该任务的第几次调用」分段看命中率 ——
   它不受会话长短影响，是 CE-018 直接改善的那个量。

> 现状快照（**两份数据不是受控 A/B** —— 不同数据目录、不同会话 mix、不同长度分布，**只作方向参考**。
> 受控证据只有第 2 节 ① 那个 A/B：45,887 → 192）：
