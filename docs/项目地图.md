# 项目地图

> **这是什么**：Harbor 现在**长什么样、有多大**的一张全景图 —— 给「刚接手 / 隔几天回来 /
> 想估个活该放哪」的人一个体量感。想知道「某件事该读哪份」看 [`README.md`](README.md)；
> 想知道「一次对话在代码里怎么走」看 [`架构.md`](架构.md)。
>
> **本文数字 = `npm run map` 的输出快照（2026-10-13），不是手抄。** 代码每版都在涨，
> 要最新的就**跑一遍 `npm run map`** —— 它才是「现状」的真相源（`AGENT.md` 硬约束 8：
> 会涨的数字不写死，只准出现在「一份定义 + 命令输出」里）。凡「每版都会涨」的计数
> （IPC 通道数 / 自检项数），本文一律只给命令、不背数。

## 三、内核层 `electron/`（41,613 行）

- `core/` —— **全部业务逻辑**都在这（225 个文件 / 35,452 行）
- `handlers/` —— IPC 处理器（36 个 / 4,400 行）
- IPC 通道数：**每版都会涨** —— 看 `npm run test:app` 的 `channelsExpected` 输出，
  清单的唯一定义在 `electron/ipc-channels.cjs` 的 `EXPECTED_CHANNELS`。

`core/` 的模块按前缀成簇（看前缀就知道做了多少块）：

| 簇 | 做什么 | 簇 | 做什么 |
| --- | --- | --- | --- |
| `task-*` | 任务台账 / 生命周期 | `download-*` | 下载管理器 |
| `loop-*` | 对话主循环 | `image-*` | 生图 |
| `config-*` | 配置 | `prompt-*` | 提示词 |
| `memory-*` | 记忆 | `changeset-*` | 改动事务 / 回滚 |
| `session-*` | 会话 | `context-*` | 上下文装配 |
| `clarify-*` | 「先问我」澄清 | `risk-*` / `capability-*` | 权限 / 风险模型 |
| `mcp-*` | MCP 接入 | `project-*` | 读 AGENT.md / .harbor 规则 |
| `browse-*` | 内置浏览器 | `llm-*` / `error-*` | 模型调用 / 错误分类 |

另有 `core/tools/`（具体工具实现）。

## 怎么刷新（数字会漂，以命令输出为准）

**一条命令拿到整张图**（文件数 / 行数 / 各目录分布 / 质量网文件数）：

```cmd
npm run map
```

其余单项 —— 这些数字**每版都会涨**，命令输出才是真相源：

```cmd
git rev-list --count HEAD      :: 提交数
git tag                        :: 发布 tag
npm test                       :: 内核自检 —— 看末尾「通过 N 项」
npm run test:app               :: IPC 通道 —— 看 channelsExpected
```
