## 一个容易误解的设定

**「默认工作目录」只影响没有自己目录的对话。**
在设置里改了它，已有对话不会跟着变 —— 它们的目录记在自己的会话文件里
（侧栏「对话文件夹」就是按这个分的）。这是设计，不是 bug；
排查「为什么 Agent 看的还是旧目录」时先看这条。

想让自己在这个仓库里干活时读到上面这些规矩：
把工作目录设成仓库根目录即可 —— `AGENT.md` 会被自动注入。

### hook 里存状态 + 被两处调用 = 静默失效

`useBulkSelect()` 内部用 `useState`，「多选删除」按钮在 `SidebarHeader`、
列表在 `Sidebar` —— 两个组件各调一次就各拿到一份独立状态。点按钮只改了
其中一份，另一份读到的永远还是初始值。**tsc、eslint、151 项测试全绿**，
只是功能没了。

**规则：一个 hook 只要可能被两处调用，状态就不能存在它自己里面**
（用 zustand store / context）。这个 bug 是我把按钮从 `Sidebar.tsx` 抽成
`SidebarHeader.tsx` 时引入的 —— 抽之前两者同属一个组件，所以没事。

**测这类共享状态不能用 `renderToStaticMarkup`**：那是服务端渲染，
zustand 走 `getServerSnapshot`，永远返回初始值。要真挂 DOM（jsdom 有了），
断言「从一处改，另一处也能看到」。

### 两件直接改进验证纪律的事

**① `--self-test` 曾经查不出「handler 没注册上」。**

主进程注册 handler 的那段是**同步**跑的，`app.whenReady()` 早在它之前就挂好了。
于是中间随便哪一行抛错（真实案例：新建的 `handlers/provider.cjs` 用了 `ipcMain`
却忘了 `require('electron')`），**它后面的 handler 全部不注册，但窗口照常打开**，
Electron 只弹一个「A JavaScript error occurred in the main process」。
自检当时照样全绿 —— 因为它只查「已经能查的」，查不到「哑掉的那些」。

现在自检会清点通道：`electron/ipc-channels.cjs` 的 `EXPECTED_CHANNELS` 写死一份
「应该存在的通道」清单（2026-09-23 实测 **115** 条；加通道要同步它），
挨个检查注册情况，输出 `channelsOk` / `channelsMissing`。
（查法有讲究：`ipcMain.handle` 注册的通道**不在** `eventNames()` 里，
`listenerCount` 对它也恒为 0；真正存 handle 的是私有的 `_invokeHandlers` Map，
留了退回 `listenerCount` 的退路。）

**② 冒烟测试曾经从不触发「用量累加」那条路径。**

Agent 循环冒烟测试里 stub 的 `llm.chatStream` 直接 `return`，从不调 `options.onUsage`
—— 于是 `loop.cjs` 里 `mergeUsage` 因为拆分漏了 import，**315 项照样全绿**，
真发一句话才报 `mergeUsage is not defined`。现在 stub 会主动调一次 `onUsage`。

**共同点：一次「真的跑一遍」比一堆通过的测试管用。**

## 风险分级：三个「模式表看着挺像样」的假象

2026-09-23 例行排查时随手写了个 21 条命令的探针，**14 条判错**。三个根因都不是
「黑名单少写了几条」——那种补不完，`risk.cjs` 开头自己就写着这句话。

**① 只审命令开头 = 后面跟什么都能过。**
`LOW` 白名单全是 `^\s*(ls|dir|find|grep|…)`，只匹配**开头**。
`find . -delete` 开头是 `find` → 整条判成 **low** → 在「中风险放行」的配置下
**静默递归删除**。21 条里最吓人的就是这条。
**规则：白名单的语义必须是「整条都像只读」，不是「开头像只读」。**

**② 一张模式表只覆盖一种 shell 方言。**
表里全是 cmd / unix 写法，于是 `format c:` 拦得住、**`Format-Volume` 拦不住**；
`shutdown /s` 拦得住、`Stop-Computer -Force` 拦不住（原正则要求参数带**斜杠**，
PowerShell 用的是 `-Force`）；`schtasks /create` 有、`/delete` 没有。
账户那几条更是**完全没有** —— 而 `net localgroup administrators x /add` 等于拿下整台机器。
**规则：写"危险命令"这类表时，先把同一个动作在 cmd / PowerShell / unix 里的写法各列一遍。**

**③ 兜底写在调用方，自己反而不说 → UI 会说谎。**
`decide()` 在 `high: 'allow'` 时返回 `allow`，真实确认全靠 `tools/index.cjs` 里
一条 `|| verdict.level === 'high'` 顶着。于是设置页的风险试算显示「**直接执行**」，
实际执行却弹确认框 —— 同一个判断，两个地方说法不一样。
**规则：一条规则要写在"拥有这条规则"的那个函数里，别让调用方替你兜。**
（顺带：这条也解释了一个 UI 文案 bug —— critical 显示成「危险**风险**」，
因为标签表给的是「危险」、调用处又字面拼了个「风险」。同一个道理：拼接发生在错的地方。）

**④ 把新逻辑提到更高等级，要连「别误伤」一起验。**
`grep -r`、`ls -f`、`find -name` 和破坏性开关长得很像。把 `-r` / `-f` 收进
「破坏性参数」表，就会误报一堆正常命令 —— 而**误报的代价是这个分级被用户整个关掉**，
那比不修还糟（人不会去改一个天天拦自己的东西，只会关掉）。
所以自检里「**没治过头**」和「治住了」是同等重要的验收项：
`npm install` 仍是中风险·直接执行、`grep -r` 仍是低风险·直接执行，都写进断言。
