## 一、三层，一条咽喉

```
┌─ 渲染层  src/  (React 18 + TS 严格 + Zustand)
│    components/ 159 · lib/ 84 · stores/ 43 · hooks/ 16 · types/ 12 · constants/ 7
│
├─ 桥梁    electron/preload.cjs
│    只暴露 **一个** ipcRenderer.invoke —— call(channel, ...args)
│    所有界面动作都从它出去（所以「用户点了什么」不用逐个埋点，自动全在网里）
│
└─ 内核    electron/  (CommonJS，**不 require electron，可单独测**)
     core/ 106 · handlers/ 21 · 顶层 *.cjs 10
                        │
                        └─ data/  ← 唯一的数据落点（config / sessions / tasks / changesets / memory / audit / logs）
```

**最关键的一条设计约束**：`electron/core/**` **不 require electron**。
所以 `npm test`（内核自检 1800+ 项）能直接把内核 require 进来跑，**不需要起 Electron、不联网**。
这是整个项目可靠性的地基 —— 内核里想用 electron 的东西，一律靠**依赖注入**（`ctx`）。

## 二、一次对话经过哪些文件

```
用户按发送
  │
  ├─ 渲染层   src/stores/thread/turns.ts
  │     ① 本地先落一条占位消息、先置「这条在跑」（不等主进程回音）
  │     ② await sendChat(...)
  │
  ├─ IPC      preload.cjs → handlers/chat.cjs   (通道：chat:send)
  │
  ├─ 内核     loop-run.cjs        任务/事务外壳：建 task、开 changeset、挂 AbortSignal
  │           loop.cjs            runLoop —— 一轮一轮转
  │             ├ loop-prompt.cjs 组装系统提示（含 AGENT.md 注入、任务台账、记忆）
  │             ├ loop-model.cjs  调模型（含 context_overflow 自动压缩重试）
  │             ├ loop-route.cjs  选供应商/模型（Model Router，默认关）
  │             ├ loop-tools.cjs  解析 tool_calls
  │             └ loop-guard.cjs  循环检测 + 用量闸
  │
  ├─ 工具      core/tools/index.cjs  ← **唯一咽喉**，四件事都在这里做：
  │             ① 参数校验（validateArgs）  ② 风险分级（risk.cjs）
  │             ③ 路径授权（capability.cjs）④ 审计落盘（audit.cjs）
  │
  ├─ 事件      lifecycle.cjs（13 相位）→ events.cjs（16 个 agent.* 名）
  │             → chat-emit.cjs → 渲染层
  │
  └─ 渲染层   src/stores/thread/streamEvents.ts 按事件改 store
              → MessageList / TaskConsole / StatusBar 重渲染
```

**两套「刹车」别搞混**：`MAX_TURNS = 200` 是**保险丝**（防死循环）；
`budget.maxSteps = 50` 是**停下来问人**。性质不同，刻意分开。

## 三、内核的主要模块（按职责）

| 区域 | 文件 | 管什么 |
|---|---|---|
| **入口** | `main.cjs` | 装 crash-guard → 锁 data 路径 → 建窗 → registerHandlers |
| **通道** | `ipc-channels.cjs` | `EXPECTED_CHANNELS`（115 条）写死一份「应该注册的通道」，自检逐条点名 |
| | `register-handlers.cjs` | `wrapInvokeHandlers()` 包住所有 `ipcMain.handle` —— 任何通道失败/慢调用都进日志 |
| **Agent 循环** | `loop*.cjs` × 6 | 见上图 |
| **任务台账** | `task*.cjs` × 15 | io 底座 / 门面 / notes 记账 / plan / resume / recovery / diagnose / steering / index / notify / outcome / context / hint |
| **事务** | `changeset.cjs` | begin → record 快照 → commit/rollback（**整批撤**，不是逐个文件） |
| **安全** | `capability.cjs` / `risk.cjs` / `redact.cjs` / `credentials.cjs` / `audit.cjs` | 见 [`安全模型.md`](安全模型.md) |
| **会话** | `session*.cjs` × 5 | JSONL 追加式；按 key 收敛同一次流式的多个快照 |
| **工具** | `tools/*.cjs` | 一个文件一个工具；`registry.cjs` 注册表，`index.cjs` 执行咽喉 |

## 四、数据长什么样

```
data/
  config.json          配置（密钥只有 credentialRef，真值在 credentials.json）
  credentials.json     凭证库（Electron safeStorage = Windows DPAPI；拿不到就明文并**如实标注**）
  capabilities.json    已放开的路径（一次性 / 本会话 / 永久）
  sessions/sess_*.jsonl  一个会话一个文件，**追加式**（崩了只丢最后一行）
  tasks/task_*.json    任务台账 + 检查点 + 步骤 + 错误 + 用过的模型
  changesets/<id>/     改动事务（回滚用）
  memory.json/.md      结构化记忆（旧的 .md 会自动迁移）
  audit/YYYY-MM-DD.jsonl  工具调用审计（参数**已脱敏**）
  logs/YYYY-MM-DD.log  人看的日志 + actions-*.jsonl 机器看的动作流水
  plugins/  skills/  backups/  artifacts/(规划中)
```

**为什么用 JSONL 而不是大 JSON**：追加就是 append（长对话不会越写越慢）、
中途崩了只丢最后一行、出问题能直接用文本编辑器看。

## 五、几个「为什么这么定」的决策

| 决策 | 理由 |
|---|---|
| 内核不 require electron | 为了能脱离 GUI 跑 1800+ 项自检 |
| 单文件 ≤ 300 行 | 拆出来的文件能被一次读完；拆分踩过的坑见 `踩坑记录.md` |
| 密钥走 safeStorage 而不是 keytar | 零新依赖，避开「原生模块装不上/打包漏拷/ABI 不对」三连坑 |
| 用 ChangeSet 而不是逐文件回滚 | 模型改三个文件做一件事，第二个改错了 —— 只撤第二个反而更糟 |
| 删会话不删 artifacts？ | （待定，见 `改造任务/Artifact系统.md`） |
| 事件统一走 `lifecycle` → `events` | 以前各模块自己 emit，前端要认十几种形状 |

### 重试与降级（一次讲全）

改进清单里挂过一条「重试策略代码里明确，但没有一处文档把它讲全」——就是这一节。

- **模型调用**（`llm.cjs`）：同一供应商失败 → 指数退避重试；仍不行 → **换一个配好的供应商**，
  而且换之前**明确告诉用户**（界面上出现「已换用一个供应商 · 原因：…」）。
  试几次由任务预算的 `maxRetries` 管（默认 3）。
- **工具调用**（`tools/*`）：只有**读**性质的操作（读文件 / 搜索 / 列目录）允许自动重试；
  **写操作永不自动重试** —— 失败原因不明时重放一次写，可能把改坏的东西再写一遍。
  写失败就把原话交给用户。
- **上下文超限**（`context_overflow`）：不重试 —— 走压缩（`/compact`）之后再继续。
- **命令**（`run_shell`）：不做自动重试；退出码与输出原样回到模型，由它决定下一步。
- **用量闸拦住**（`limits.cjs`）：不重试、不排队 —— 直接停下并说清「这是你设的闸门，不是故障」。

一句话：**能安全重放的才重放；写操作宁可停下来问人。**

## 六、想动手改？先看这几处

| 你想改 | 看这里 |
|---|---|
| 加一个工具 | `electron/core/tools/`（一个文件一个）+ `registry.cjs` 注册 |
| 加一个 IPC 通道 | `handlers/` + **`ipc-channels.cjs` 同步**（漏了自检会红）+ `preload.cjs` |
| 加一个工具调用事件类型 | `events.cjs` 的 `eventForTransition` |
| 改提示词 | `loop-prompt.cjs` / `prompt-stack.cjs` —— **改完必须跑内容回归自检**（提示词漏层是踩过的坑） |
| 改数据结构 | 必须写迁移，且**保留旧数据**（用户已经有真实数据） |
| 改 UI | `npm run shot:electron` 拿真机截图，别只跑单测 |

**改完至少跑**：
```bash
npm run typecheck && npm run lint && npm run test:unit && npm test && npm run build
```
`.cjs` **不参与 tsc** —— 改内核只跑 typecheck 等于没验。
