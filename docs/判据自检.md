# 判据自检 —— 防假红 / 假绿

> 一句话：**测试脚本本身也要被验证。**
>
> 起因：批③ 的四个 bug、批④ 真机挖出的三个缺陷，都是**静默失败**，只是后者落在测试脚本里。
> 然后是 2026-10-02 一晚上连撞三次**判据自己出问题**：
>
> | 实例 | 性质 | 根因 |
> |---|---|---|
> | T10 把「说明.md 会从 6 行变成 20 行左右」判成「没说清风险」 | **假红** | 判据用**词表**代替了「说清」；detail 里没带它看到的原文，只能靠猜 |
> | T1 在模型一次都没答上来时，按「文件没被动」判 ✅ | **假绿** | 判据**观测不到**时默认给了「过」 |
> | 自检「删完数量回到原样 —— 7」（立刻重跑就绿） | **假红** | 断言数**共享目录**的既有条目数，默认「世界只有我在动」 |
>
> 规矩一旦只写在脑子里，就会在「这次赶时间」的时候被跳过 —— 所以这份文档是**实施说明**，
> 每条都指到代码里的具体位置。

## 六条（①–⑤ 已实施，⑥ 待做）

### ① 判据必须带证据

`verify()` 的返回值多了 `evidence`：**它看到的事实**（哈希 / 计数 / 原文片段）。
会自动进 `acc-report.json`，也能在控制台看到（驱动的 `↳ 观测：…` 那一行）。

- 代码：`tools/acceptance-verdict.mjs`（`pass/fail/unknown` 三个构造器 + `normalize`）、
  `tools/acceptance-cases.mjs` 里每条判据的 `evidence`。
- 为什么：假红那次如果 detail 里带着卡片原文，一眼就能看出是判据窄，而不是模型没说。

### ② 结局从两态改三态

`pass` / `fail`（被测对象确实没做到）/ **`unknown`（判据没能观测到）**。
`unknown` **既不算过也不算不过**，退出码仍为非 0，但**打印不同字样**（「⚠️ 有 N 轮判据没能观测到」）。

- 代码：`tools/acceptance-verdict.mjs` 的 `observeRound()` + 驱动的每轮护栏。
- 四种「观测不到」：撞了驱动截止时间 · 日志里有「凭证解密失败」 · 这一轮没有「请求模型」 ·
  台账里一条步骤都没有。
- 为什么：T1 那次假绿就是「模型没跑」被算成了 ✅ —— 只读类用例的判据最容易变成恒真。

### ③ 每条判据都要能红（反向用例）

`scripts/selftest/groups/106-acceptance-verdicts.mjs`：把「肯定不过」的输入喂给**每一条**判据，
断言它会红、且带着证据；再挑几条钉「正常产物下会判过」（否则判据是恒假）。
**全在临时沙箱（`os.tmpdir()`）里跑，不需要真模型。**

- 为什么：能通过不算测试，能失败才算。只读任务的判据（T1/T5）最容易恒真，
  所以它们要**先把沙箱弄坏**再验。

### ④ 跑之前先验前置（把假绿挡在源头）

`tools/acceptance.mjs` 的 `preflightBad()`：启动应用**之前**检查三条，任一不成立就 `exit 2` 拒绝开始 ——

- `config.json` 的 `general.workdir` 必须指向沙箱（空着会让「新建对话」弹**原生**文件夹选择框，
  系统模态 CDP 点不动，驱动整轮报废）；
- `credentials.json` 的 `backend` 必须是 `safeStorage`，且有条目；
- `data/chromium/Local State` 必须在（safeStorage 的密钥在里面）。

### ⑤ 断言不要依赖「世界只有我在动」

写进 [`踩坑记录.md`](踩坑记录.md)：数**共享目录**条目数的断言（如 `data/backups`）
要么按**集合差异**判，要么用 `os.tmpdir()` 下的专属夹具（git 夹具已有先例）。

### ⑥ 判据也要被观测（**待做**，下一批）

每次跑完统计三件事，做成趋势而不是一次性结论：

- **有没有 `unknown`**（有就说明前置或观测链路有洞）；
- **每条判据红过几次**（从没红过的，可能是**假绿**）；
- **红了之后重跑就绿的比例**（经常红又立刻绿的，是**假红**，例如那条数 `data/backups` 的断言）。

落点建议：`acc-report.json` 已经逐轮留了 `结局` / `证据` / `观测护栏`，
再攒一个跨轮次的汇总文件（`acc-trend.json`）即可；自检那边同理，把每次的失败项记进一个
逐步累积的清单（`tmp/selftest-history.jsonl`），跑 `verify` 时顺带追加一行。

## 怎么用（给下一个改这块的人）

```bash
npm run test                                   # 含 106 组：判据能不能红 / 会不会把 unknown 当过
E:\nodejs\node.exe tmp\b4-acc-run.cjs          # 真机 + 真模型（前置检查 → 跑 → 三态报告）
```

看报告先看这三列：`结局`（三态）、`证据`（判据看到了什么）、`观测护栏`（是不是根本没跑起来）。
**不要在「有 unknown」的报告上宣布成功** —— 那正是这套东西要防的事。
