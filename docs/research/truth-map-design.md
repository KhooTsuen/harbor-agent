## 0. 一句话

把「同一个事实在几处被定义」从**只读审计散文里的一段**，变成两样东西：

1. **契约登记表**（正面）：每个跨模块契约，定义处 / 镜像 / 钉子各在哪 —— 机器可读；
2. **候选扫描器**（反面）：找出「可能又写了一份」的地方，**只报告、永不拦门**。

## 1. C 其实要回答两个不同的问题（混在一起就会做错）

| | 问题 | 能否机械判定 | 产物 |
|---|---|---|---|
| **Q1** | 这个契约，**定义处 / 镜像 / 钉它的自检**分别在哪个文件？ | ✅ 能 | 登记表 |
| **Q2** | 这两处，是不是在说**同一个业务事实**？ | ❌ 不能（要判断） | 人工 review 的候选清单 |

审计 §3 已给判据原话：**「判据不是『变量名相同』，是『表达的是同一个业务事实』」** —— 所以 Q2 天生不可机械判定，这是 C 最大的坑。

**仓库里现成的反例（证明 Q2 不能自动）**：

- `level`：risk 里是「危险度四级」、scale 里是「要不要问三级」——**同名不同义**，自动扫描必误报。
- `keyOf`（`artifact.cjs` vs `changeset.cjs`，审计 §3.8#5）——**看着一样，其实各管各的范围键**。
- 审计 §9.2 列了 6 条「只是理论风险」——**明确不该动**的重复。

> **C 的第一原则：机械可以「找候选」，不可以「下判决」。**
> 一个「扫到重复就报红」的门，会把上面这些合法差异全变成假阳性，最后没人看它。

## 3. 三根支柱

### P1 · 契约登记表 `scripts/contracts/registry.mjs`（正面清单）

机器可读：一个数组，每条一个契约：

```js
{ id, name, sot, mirrors: [], pin, driftConsequence }
// sot   = 唯一真相源文件（唯一）
// mirrors = 必须与它一致的镜像（可空）
// pin   = 钉它的自检组名（没有就写 null —— 那就是缺口）
// driftConsequence = '静默出错' | '不一致但报错' | '只是冗余'
```

- `docs/真相源地图.md` **由它生成**（或引用）—— 文档不背清单，避免漂（`AGENT.md` 硬约束 8 的精神）。
- **登记表本身也要有自检**：`pin === null` 的条目数、每个 `sot` 路径是否存在。

**为什么值得**：现在问「事件名有几处定义」要读 3 个文件；有登记表后一处看全。

### P2 · 一致性自检（把没钉的钉上）—— 复用 126 / 134 模式

模板已成熟：「从两侧源码抠出来真比一遍」（126 四路钉事件、134 双向钉 IPC）。
对登记表里每个「机械可查、但 `pin === null`」的契约，补一个自检组：抠两侧名字集合 → 断言相等 → 差异写进报错信息。

**第一个具体目标**：`decisions.cjs` 的 3 个事件名（实测确认，见 §5）。

⚠️ **补钉的过程若发现「真的漂了」**（两边值不一样），要**先定谁是真值**：改代码让两边一致，**不是只加一个红的测试**。

### P3 · 候选扫描器 `npm run dup`（反面：找遗漏，只报告）

扫什么（都是「候选」，不判红）：

- 同一**字符串字面量**出现在 ≥N 个不同源文件（事件名 / 字段名 / 枚举值）
- 同一**函数名**在多个模块各自定义
- 同一**字段名**在不同模块有不同值集合

输出：候选清单，并标注「原文注释里有没有人已经认过这事」。
**永不拦门**：不进 `verify`、不参与退出码。它是**给人看的雷达**，不是闸门（理由见 §1）。

## 4. 判据（C 最难的一步，必须先写死）

| 问题 | 判据 |
|---|---|
| 什么算「同一事实多处定义」 | 两条表达**在业务上可互相替换**才算（不是名字像） |
| 什么算「合法差异」 | 不同作用域的**合法覆盖**（User 用 pnpm / Project 用 npm）= Override，非 Conflict（见 [`../Memory设计.md`](../Memory设计.md) §3） |
| 排序依据 | **漂了会怎样**：静默出错（高）> 不一致但报错（中）> 只是冗余（低） |
| 处理方式 | 高：登记 + 补钉；中：登记；低：**登记「已知、不管」** |

**「登记已知、不管」是合法结果** —— 否则 C 会退化成「消灭所有重复」的大重构（审计 §12 明令不做）。

## 5. 第一个缺口（seed）—— 实测证据

```text
electron/core/decisions.cjs:35   const CONFIRM_REQUEST = 'confirm_request'
electron/core/decisions.cjs:49     timeoutEvent: 'confirm.timeout'
electron/core/decisions.cjs:54     timeoutEvent: 'clarify.timeout'

electron/core/event-types.cjs:70   'confirm_request'
electron/core/event-types.cjs:71   'confirm.timeout'
electron/core/event-types.cjs:72   'clarify.timeout'
```

- `decisions.cjs` **不 require `event-types.cjs`**（`findstr require(` 无命中）。
- `decisions.cjs` **没有 `emit({`** → 自检 126 扫不到它（126 只扫「会 emit 的文件」）。
- ⇒ 这 3 个名字**改一处漏一处，没人报红**。审计 §3.5 早写了，至今未钉。

**修法（C2 第一条）**：`decisions.cjs` 从 `event-types.cjs` require 那 3 个名字（或反向：把 decisions 的名字并入 event-types 再 require）。
**红线**：动 2 个内核文件 —— 贴近「3+ 文件」临界，要走批准。

## 6. 分批（每批撞不撞红线）

| 批 | 做什么 | 文件数 | 红线 |
|---|---|---|---|
| **C1** | 登记表（数据）+ `docs/真相源地图.md` | 2（新） | **不撞**（只新增，不改行为） |
| **C2** | 逐条补钉；每条一个自检组 | 每次 1–2 | 撞硬约束 9（跨模块约定）→ **每条单独批准** |
| **C3** | `scripts/dup-scan.mjs` + `npm run dup` | 2（新） | **不撞**（纯新增工具、report-only） |

**关键**：C1 / C3 零风险可先做；C2 **必须一条一条来**，因为每条都可能暴露真漂移（要修代码，不是只加测试）。

## 7. 明确不做（照抄审计 §12 + §9.2）

- ❌ 不合并「所有」重复 —— 大多数是合法差异（§9.2 六条）。
- ❌ 不做大重构（改 risk / scale 结构、补 Run / Turn 实体）—— 那是别的立项。
- ❌ 不按「文件数 / 模块数」判断健康度。
- ❌ 不让候选扫描器进 `verify`、变成拦门的闸。

## 8. 怎么算「做完了」（可验证）

- **C1**：多一条 `npm run contracts`，打出登记表；`docs/真相源地图.md` 与它一致。
- **C2**：每条补钉的自检组**先能报红（临时改坏真值试一次）再转绿** —— 证明它真在管。
- **C3**：`npm run dup` 跑出的候选里，**§5 那条应出现在结果里**（能被人一眼判定真假）。

## 9. 与 B 的关系

B（扇入 / 扇出）答「**谁引用谁**」（机械、已做）。
C 答「**谁定义了什么、定义了几次**」（一半机械、一半判断）。
合起来才是完整的结构图：**B 是连线，C 是节点上的标签。**
