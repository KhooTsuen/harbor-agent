## 4. 过程中发现并修的**真问题**

### ① ★ ☰ 与抽屉**同名**会制造成假绿（v2 差点踩响）

v1 里抽屉自己用的 `aria-label` 是 **`选择对话`** —— 而那正是 ☰（抽屉开关）的验收锚点。
**同名**会让 `CLICK_TITLE_EXPR` 在抽屉已开时**点到抽屉自身**：点自己 = 什么也没发生，
判据照样「通过」。这是最难查的一类假绿（脚本照跑、数字好看、功能没验）。

**修法**：抽屉改名 `会话抽屉`，☰ 保留 `选择对话`；锚点归属表写进
`lib/ext-probe-panel.cjs` 文件头；158 自检加一条断言钉死「两者不同名」。

### ② 验收脚本会「静默失效」（v1 的最大风险，已全堵上）

「读当前页」原来是**带文字**的按钮，三个判据按 `textContent` 找它。v1 把它改成**图标按钮
（没有文字）**→ 按文字找**永远不成立**，而脚本**照跑不误**（假红/假绿，不报错）。

| 位置 | 改法 |
|---|---|
| `ext-probe-panel.cjs` 的 `CLICK_READ_EXPR` | 按 `aria-label="读当前页"` |
| `accept-phase2.cjs` ⑨ | 同上 |
| `accept-phase3b.cjs` 的 `PANEL_READY` | 拆成 `{send, read, title}`，`read` 按 aria-label |

**同族的第二个坑**：`STATUS_TEXT_EXPR` 取文档里**第一个** `[role=status][aria-live=polite]`。
顶栏的连接状态文字若带 `aria-live`，就会把它顶掉 → accept-phase2/3a 的「读当前页给人话」
当场变假红（**看起来像产品坏了**）。处理：顶栏连接文字是**纯文本**（状态点只有 `role=status`、
**没有** `aria-live`），抽屉里的提示用 `role=alert`；自检钉死「对话区恰好一个、
顶栏 0 个」。

### ③ `accept-phase3b.cjs` 自身的环境依赖 bug（v1 复跑红了两次）

**现象**：⑥b「连上的是我装的 host」FAIL + 后续流式全无输出。
**根因**：Edge 一起来，SW 就按**当时**的注册表 `connectNative`；等脚本读到 extId 再改注册表，
**它已经连上旧 host 了** —— 而**换注册表不会让它重连**。
**修法**：**起 Edge 之前先摘注册表**（`S.regDel`）→ SW 首次必失败 → 装好隔离 host 后它按
`RECONNECT_MS=3000` 自己重连。`killStrayHosts()` 删除。
⚠️ **副作用**：若此刻正开着 Edge 用扩展，会短暂显示「未连接」，脚本 `finally` 恢复注册表原值。

### ④ 我自己写的一条断言被注释误伤（v1）

新断言写的是 `!/aria-live/.test(appSrc)`，而 `App.tsx` 文件头**正好在解释这件事**
（"顶栏里绝不能出现 `[role=status][aria-live=polite]`"）→ 被自己的注释判红。
改成匹配带引号的属性形态。（与 156 那次「注释里提到 `pendingRead`」同族。）

### ⑤ ★ 我把两个会写**同一个注册表键**的验收**并行**跑了（本轮，我的操作失误）

跑 v2 回归时我用 `&` 并行启了 `accept-phase3a` 与 `accept-phase3b` —— 两者都写
`HKCU\...\NativeMessagingHosts\com.harbor.agent`，`finally` 的「先摘 → 装隔离 → 恢复原值」
互相踩，**键被删掉**。已按下文恢复，并把「不许并行跑这两个脚本」记在这里。
**教训**：这两个脚本对同一份全局资源有写冲突，只能**串行**跑。
