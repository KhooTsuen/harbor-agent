## 2. 滚动行为测量（UX-04，真实数字）

假模型 `long` 模式持续流式（90 段 / ~14s）。测得**真正的对话滚动容器**：`DIV.h-full overflow-y-auto outline-none [overflow-anchor:none]`。

| 时点 | scrollTop | scrollHeight | clientHeight | 说明 |
|---|---|---|---|---|
| 流式中（底部跟随） | 93 | 886 | 793 | 内容溢出即**贴底** ✓ |
| `mouseWheel deltaY=-1500` 后 | **0** | 1008 | 793 | 向上滚 → 到顶 |
| 再等 4 秒（内容继续长到 1471） | **0** | 1471 | 793 | **scrollTop 保持 0，未被新内容推走** ✓ |
| 收尾后 | **0** | 2430 | 793 | 用户仍停在 FREE，未被劫持 |

**结论**：设计层声明的「FREE 模式按锚点位移补偿、末尾长高不推用户」（`useAutoScroll.ts:20-27`）在**真机行为层成立**（本轮由「4 秒内 scrollTop 不变 + scrollHeight 增长 463px」证实）。

## 5. Phase 1 改动提案（**仅提案，不实施**）

> 原则：**只改展示层**，不触碰 Runtime / IPC / 权限 / 任务持久化 / 事件契约；**不删除任何功能**；优先复用现有状态与事件。所有改动**可单文件回滚**。

### 方向 A · 安全可见性

**A1（P0-1）给「错误」补真实角标**
- **做什么**：右栏「错误」标签显示一个角标 = **最近 N 天 P0/P1 的未读错误数**（复用 `error:list` 已有的 `entries[].severity/count/lastSeen`，不新增 Runtime 状态）。「未读」以本地「上次打开错误标签的时间」为界（`localStorage`，纯展示态）。
- **为什么**：错误记录现在只有「打开才看得到」，长任务里出错极易漏看。
- **影响组件/数据源**：`RightTabs.tsx`（加 badge，参照现有 `browser` 点标写法）、一个轻量 hook 调 `listErrors({days})` 汇总 P0/P1 计数；`ErrorsPanel` 打开时写「已读时间」。**不碰内核**。
- **风险**：历史错误误报 → 用「未读」阈值兜住；`days`/严重性阈值需你定。
- **回滚**：还原 `RightTabs.tsx` 与该 hook 即可。
- **验收**：真机注入一条 P0（构造内核错误）→ 不开错误标签也能在标签上看到角标；打开后角标清零。

**A2（P0-1 延伸）右栏折叠 / 窄窗口下错误仍可见**
- **做什么**：右栏隐藏时，把「有未读 P0/P1」透出到**一个始终可见处**（顶栏「切换右侧面板」按钮上加一点标，或底部状态栏加一段）。同样只读现有错误计数。
- **为什么**：需求二明确「右栏折叠、切换标签、窗口缩小时，关键错误是否仍然可见」——当前折叠后完全不可见。
- **影响组件**：`AppTitleBar.tsx`（`PanelRight` 按钮）或 `StatusBar.tsx`。**不碰内核**。
- **风险**：与已有「未完成任务」提示并存时的视觉拥挤 → 需与你确认落点。
- **回滚**：还原对应组件。

**A3（P0-1 延伸）等待授权 / 危险操作 / 策略拒绝 / 普通故障的显示差异**
- **现状**：授权 = 输入区上方卡（已好）；危险操作 = `PermissionDialog`（anchored）；普通故障 = toast + 工具失败行。
- **建议（待你定）**：**策略拒绝**目前没有独立表达（与普通故障同形）。提案**只做展示层区分**：在 `PermissionBar` / 工具失败行里，当内核给的是「策略拒绝」类原因时用**不同措辞 + 状态色**。**这需要内核在既有事件里带出一个可判别的标记** —— 属「改事件契约」，**按红线暂停，先提交设计说明等你确认**。
- **明确不做**：不在正则里解析模型自然语言来倒推「策略拒绝」（禁止伪造 Runtime 状态）。

### 方向 B · 任务进度语义

**B1（P0-4）计划 vs 执行分离**
- **做什么**：凡展示「步骤」处，统一加**「计划」**前缀/标签，明确它来自模型的计划块；真实执行状态（相位、轮次、工具计数）单独呈现，**不与计划混排**。落点：右栏任务行（`TaskRow`）、任务详情、消息内 `PlanCard`。
- **为什么**：避免把模型计划步骤当成执行进度。
- **影响组件**：`TaskRow.tsx` / `TaskRowDetails.tsx` / `PlanCard.tsx`（展示层）。**不改任务台账结构**。
- **风险**：纯文案与布局，低。
- **回滚**：还原对应组件。

**B2（P0-4）无可信总量时禁用百分比**
- **做什么**：当前进度条只能表示「相位」（如「进行中」），**不显示虚构百分比**。核对现有百分比来源，凡无真实分母的一律去掉数字、只留相位/计数。
- **验收**：跑一个多步任务，界面**不出现**任何「%」除非有真实分母。

**B3（P0-2）完成 / 验证 / 产物三态分清**
- **做什么**：区分「**执行结束**」（已有）、「**验证结果**」（无独立来源，见下）、「**产物可用**」。把「成果」的语义与入口理顺（见下）：
  - 明确「成果」= 内核 `artifact:list` 的正式产物；agent 写出的文件在「审查」可见 —— 至少在**「成果」空态文案**里说清这个分工，或提供「查看本次改动文件」的入口（**只加提示/链接，不搬数据**）。
- **明确不做**：**无验证证据时绝不显示「验证通过」**。当前无「验证通过」独立态 → **不新增该状态**（如需，属内核改动，先设计说明）。

### 方向 C / D（右侧层级、中央降噪）——本轮**只登记问题、不提案细节**
- 待 Phase 1 验收后再做**带真机对照**的提案（跨轮工具聚合、历史成功降权、诊断层折叠、重复状态去重、右栏 8 标签权重）。**P0-1 / P0-2 / P0-3 / P0-4 / P0-5** 是它们的输入。
