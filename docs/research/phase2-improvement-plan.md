## 0. 结论先行

**右栏的八块能力（审查 / 文件 / 浏览器 / 成果 / 任务 / 下载 / 状态 / 错误）都保留，不动功能、不删入口。**
Phase 2 要解决的不是「标签太多」，而是三件事：

1. **八标签同层同权重** —— 高频（审查 / 文件 / 任务）与低频（下载 / 状态 / 错误）看起来一样重，用户得逐个点开才知道哪个有东西。
2. **「需要你注意」的东西散在标签里** —— 未读错误（Phase 1 已加角标）、在跑 / 等待的任务、未提交的改动、进行中的下载，各在各的标签后面；右栏折叠或窄窗时，用户没有一处能一眼看全「现在有什么在等我」。
3. **几组关系没被说清** —— 「成果 vs 审查」（两条数据源）、「当前任务 vs 历史任务」、「任务 vs 状态」。

**建议**：先做**方案甲（纯层级调整，零新增容器）**；方案乙（加一条「需要你注意」汇总条）作为备选，等甲落地看到效果后再决定要不要上。两者都**不隐藏任何标签、不把操作藏进二级菜单**。

## 2. 现状：右栏是怎么组织的（供对照）

- **结构**：`RightPanel`（`aside`，`RightPanel.tsx:150-273`）＝ 顶部 `RightTabs`（标签栏）+ 内容区（按 `activeRightTab` 条件渲染，`:180-247`）。
- **宽度**：`LAYOUT.rightPanel` 最小 320 / 最大 480（`constants/index.ts:135`，默认见同处 `LAYOUT`）。折叠时 `RightPanelHost` 加 `hidden` 但**不卸载**（保浏览器 webview 状态，`RightPanelHost.tsx:9-19`）。
- **各标签数据源**（`ui-component-map.md` §2.4）：

  | 标签 | 组件 | 数据源 | 状态提示 |
  |---|---|---|---|
  | 审查 | `DiffViewer` + `RollbackRecord` | `useTaskStore.diff` | 有：改动文件数 |
  | 文件 | `FileTree` / `FilePreview` | `fsTree(workdir)` | 无 |
  | 浏览器 | `BrowserTab` | `useBrowserStore` | 有：Agent 动过网页圆点 |
  | 成果 | `ArtifactsPanel` | `artifact:list` | **无** |
  | 任务 | `TaskCenter` | `useTaskStore` | **无** |
  | 下载 | `DownloadsPanel` | downloads API | **无** |
  | 状态 | `StatePanel` | 当前对话长期状态 | 无 |
  | 错误 | `ErrorsPanel` | 内核错误清单（只读） | 有（Phase 1 未读点） |

- **Phase 1 已铺好的地基（可直接复用，无需重造）**：
  - `src/lib/errorSignal.ts`：纯函数判「严重 / 未读」；
  - `src/stores/useErrorsStore.ts`：错误清单唯一抓取入口 + 未读状态；
  - `src/hooks/useErrorSignal.ts`：按事件触发（**无定时器**）；
  - 顶栏右栏按钮已带同一未读信号（折叠/窄窗兜底）。

## 3. 现有用户操作路径盘点（**先说明会受什么影响**）

Phase 2 若只动视觉权重 / 顺序 / 加一条汇总条，会牵动下面这些**已经存在的**路径。逐条列出，供你判断可接受度：

| 路径 | 现在怎么走 | 方案甲影响 | 方案乙影响 |
|---|---|---|---|
| 看当前对话的改动 | 右栏 ▶ 点「审查」（默认标签） | **0**：审查仍在最左第一位 | 同甲，另可从汇总条「N 处改动」直跳 |
| 看工作目录文件 | 右栏 ▶ 点「文件」 | 位置可能右移一位（若把高频集中到前段） | 同甲 |
| 看待办 / 后台任务 | 右栏 ▶ 点「任务」 | **0** | 另可从汇总条「N 个任务在跑」直跳 |
| 看内核错误 | 右栏 ▶ 点「错误」（Phase 1 起有未读点 / 顶栏兜底） | **0** | 另可从汇总条直跳 |
| 找 Agent 产出的正式成果 | 右栏 ▶ 点「成果」 | **0** | 同甲；可考虑给「成果」加「有正式产出」提示（见 §4 甲的 C-3 补充） |
| 看下载 / 状态 | 右栏 ▶ 点「下载」/「状态」 | 位置右移（低频后置） | 同甲 |
| 折叠右栏后想找回它 | 点最右 `‹` | **0** | **0**（汇总条仅在展开时出现，折叠态仍靠顶栏兜底） |
| 用键盘 / 快捷键切标签 | 目前无标签级快捷键（命令面板 `CommandPalette` 管其它） | **0** | **0** |

**关键结论**：
- 两条路径**完全不受影响** —— 折叠/展开（`RightPanelHost`）与标签内容渲染（`RightPanel.tsx:180-247`）都不动。
- 唯一有体感的变化是**标签位置**（甲）和**右栏顶部多一行**（乙）。前者靠「高频集中在前」降低找的成本，代价是**肌肉记忆会变一次**；后者多占约 24–28px 高度，**窄窗口下会更挤**（这是我们最担心的一点，见 §6 风险）。

## 4. 两种轻量方案对照

> 两个方案都不改功能、不删入口、不动数据源、不触 Runtime/IPC/权限/台账。
> 都**不使用二级菜单** —— 八个标签始终都在标签栏里，只是权重 / 位置 / 是否配汇总条不同。

### 方案甲 · 纯层级调整（低风险，建议先做）

**做法**（候选，控制在展示层）：

1. **按频率重排 + 分组**：标签顺序改为 `审查 · 文件 · 任务 · 成果 ｜ 浏览器 · 下载 · 状态 · 错误`，两组之间加一条发丝分隔线（纯装饰，不改变可点性）。
2. **给「有内容」的低频标签补提示**（复用现有能力，不新增数据源）：
   - 「任务」：在跑 / 等待用户的任务数 > 0 时一个静态点（数据取 `useTaskStore` 已有的 `unfinished` / 状态计数）；
   - 「下载」：下载进行中时一个静态点（数据取 `DownloadsPanel` 已订阅的同一份）；
   - 「成果」：仅当本次会话**确有正式产物**时才提示（取 `artifact:list` 已有的计数）。
   > 三处提示**一律静态、不闪**，颜色走 `statusLanguage`（沿用 Phase 1 的错误角标做法）；**「有内容」≠「未读」**，措辞上不夸大。
3. **两个标签互指**：成果空态已有说明（Phase 1），在「审查」头补一句「这些是工作区改动；正式产物在『成果』」，反之亦然 —— 一句静态说明，不做跳转也能懂。

- **改动文件（候选）**：`RightTabs.tsx`（顺序 / 分隔线 / 角标）、`RightPanel.tsx`（传新的角标数据）、`ArtifactsPanel.tsx` / `RightPanel.tsx:184-187`（互指文案）。
- **不动**：任何 store 逻辑、任何 IPC、任何面板内部结构。
- **回滚**：单文件级改动，`git checkout` 对应文件即可。

### 方案乙 · 加一条「需要你注意」汇总条（中风险，备选）

在甲的**全部内容**之上，额外在标签栏下方加**一条常驻摘要行**（仅当有内容时出现）：

```
⚠ 1 条未读严重错误   ·   ⟳ 2 个任务在跑   ·   ± 3 处未提交改动   ·   ↓ 1 个下载中
```

- 每个 chip 可点 → 跳到对应标签（等价于现在点标签，只是省去「逐个点开找」）。
- **不替代原入口**：标签栏原样保留，汇总条是「聚合视图」不是「唯一入口」。
- 数据全部来自**已有的 store 订阅**（`useErrorsStore` / `useTaskStore` / downloads），**不新增轮询**。
- **改动文件（候选）**：新增一个小组件（如 `RightAttentionBar.tsx`）+ 在 `RightPanel.tsx` 标签栏下挂一行。
- **回滚**：删掉这一个组件与它的一行挂载即可。

### 对照表

| 维度 | 方案甲 | 方案乙 |
|---|---|---|
| 新增文件 | 0（改现有 3 处） | 1 个小组件 + 1 行挂载 |
| 右栏高度占用 | 0 | **+24~28px**（窄窗更挤） |
| 解决问题 C-1 / C-2 | ✓ 分组 + 顺序 | ✓（含甲） |
| 解决问题 C-3 | ✓ 补低频率标签提示 | ✓（含甲） |
| 解决问题 C-4（折叠/窄窗兜底） | **部分**（仅错误有顶栏兜底） | **部分**（同甲；汇总条只在展开时在） |
| 肌肉记忆变化 | 标签位置变一次 | 标签位置变一次 + 顶部多一行 |
| 窄窗风险 | 低 | **中**（320px 宽时汇总条易换行 / 挤压） |
| 回滚成本 | 极低 | 低 |
| 依赖 Phase 1 | 无（可独立） | 无 |

## 5. 明确不做的事（红线，与「禁改项」一致）

- **不删任何标签 / 功能 / 诊断入口**（任务、错误、状态、下载全部保留）。
- **不把标签收进二级菜单**（你明确要求；甲乙都不这么做）。
- **不合并数据源**：「成果（artifact）」与「审查（diff）」保持两条，只做互指。
- **不改 Runtime / IPC / 事件契约 / 任务台账 / 权限模型 / 数据结构**。
- **不新造状态**：所有提示都派生自现有 store，不新增 Runtime 状态。
- **不加轮询、不加动画闪烁**（沿用 Phase 1「静态、不闪」的做法）。
- **不给「当前任务」编造进度百分比**（Phase 1 · B2 已定：无可靠分母就不显示）。

## 6. 风险与回滚

| 风险 | 等级 | 说明 / 缓解 |
|---|---|---|
| 标签重排导致肌肉记忆失效 | 低 | 高频集中在前，总体更易找；一次性的变化 |
| 窄窗（320px）下标签栏更挤 | 中（乙） | 甲不受影响；乙需实测 320/360/480 三档，必要时汇总条在窄窗折叠成一行滚动或隐藏 |
| 新增角标被误读成「未读」 | 中 | 措辞 / `title` 明说「有 N 个在跑」而非「未读」；不因「看过」而清零（它们不是未读语义） |
| 汇总条与顶栏兜底重复 | 低 | 顶栏管折叠态、汇总条管展开态，分工写清 |
| 单文件超 300 行红线 | 低 | `RightPanel.tsx` 当前 275 行、`RightTabs.tsx` 134 行；乙的新组件单独成文件，甲尽量在 `RightTabs` 内完成 |

**回滚**：甲 / 乙都是展示层小改，按文件 `git checkout` 即回；乙多一步删组件。

## 7. 建议与待你决定

**建议**：先实施**方案甲**（零新增容器、零新数据源、可单文件回滚），跑真机对照（CDP + 隔离假上游，沿用 Phase 0/1 方式），看「找东西」是否更快、窄窗是否更挤；**再决定要不要上乙**。

**需要你拍板的点**：

1. **方案选哪个**：甲（先做） / 乙（直接上汇总条） / 甲乙都先不做，只看这份设计。
2. **标签顺序**：是否接受把顺序调成「审查 · 文件 · 任务 · 成果 ｜ 浏览器 · 下载 · 状态 · 错误」（高频在前）；还是保持现有顺序、只加分隔线不重排。
3. **低频标签要不要补「有内容」提示**（任务 / 下载 / 成果）：补（更接近乙）还是不补（更纯的甲）。
4. **「当前任务」要不要在任务标签里置顶**（把当前这条对话正在跑 / 等待的任务单独提到最前）：这是 C-7 的对应项，属展示层排序，不触台账。
