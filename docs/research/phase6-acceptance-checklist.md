## 0. 为什么必须由人来点

打包脚本的第 0 步是 `taskkill /F /IM Harbor.exe` —— 它要关掉**所有** Harbor 窗口才能替换
被占用的文件。而当前这个 Agent 会话就跑在其中一个 Harbor 进程里，**我执行打包 = 自杀**。
所以这一步只能由你在应用之外（双击 .cmd）来做。

## 1. 打包（你操作）

**双击这一个文件即可**，它把整套流程串好了：

```
E:\Harbor-Dev\update-all.cmd
```

它依次做（就是 `npm run package` 的完整流程 + 同步）：

| 步 | 做什么 | 说明 |
|---|---|---|
| 1 | `npm run verify` | 全链检查，**几分钟**；红了就停、什么都不改 |
| 2 | `taskkill /F /IM Harbor.exe` | **会关掉当前 Harbor 窗口**（含本会话）—— 正常现象 |
| 3 | `npm run package` | 构建 + 打包到 `E:\CodexWorkbench\dist-portable\Harbor` |
| 4 | 备份旧 app | 两份副本各备份到 `resources\app.bak-<时间戳>`（可回滚） |
| 5 | `robocopy /MIR` 同步 | → `E:\Harbor-Dev\dist-portable\Harbor\resources\app` 和 `E:\Harbor\resources\app` |
| 6 | 读回版本 + 重启 dev | 自动重开 `E:\Harbor-Dev\dist-portable\Harbor\Harbor.exe` |

**要点**：

- 两份副本的 **`data\` 目录不被碰** —— 会话 / 记忆 / 凭证全部保留（脚本只 `robocopy` `resources\app`）。
- 全程日志：`E:\Harbor-Dev\update-all.log`。跑完看**最后一行**应是 `ALL DONE`。
- 回滚（万一）：把对应 `resources\app.bak-<时间戳>` 拷回 `resources\app` 即可。
- 构建源 `dist-portable\Harbor\data\credentials.json` 会被打包脚本**移到** `data\backups\<时间戳>\`
  （防止 API Key 跟着便携版走）—— 这是打包脚本的既定行为，不是故障。

**打包完成后**（不用开应用也能核对）：读

```
E:\Harbor-Dev\dist-portable\Harbor\resources\app\build-info.json
```

它的 `gitCommit` 应等于**打包那一刻的 HEAD 短哈希**（在 `E:\CodexWorkbench` 跑
`git rev-parse --short HEAD` 对照即可；不必记具体值 —— 文档还会往前走），
`buildTime` 是刚才的时刻（我也可以在你打包完后帮你读这两份对一下）。

## 2. 真机验收清单（你操作，逐条打勾）

### 第 1 条 · 设置页有开关、默认关

- [ ] 打开 Harbor → 设置 → **助手**（开关那一栏）
- [ ] 看到新开关：**「严格模式：每步强制验证」**
- [ ] 它**默认是关闭**的（未勾选）

### 第 2 条 · 关着的时候，行为与升级前一致

- [ ] 保持严格模式**关闭**，跑一个普通小任务（例：「把这个文件里的错别字改一下」，或你自己挑一个）
- [ ] **观察**：任务过程中**没有任何**额外的「请先验证」这类提示；完成即结束
- [ ] 预期：从用户视角看，和升级前一模一样（严格门禁完全不介入）

### 第 3 条 · 开着的时候，连续写 3 次会被顶回来验证

- [ ] 打开设置 → 助手 → **开启**「严格模式：每步强制验证」
- [ ] 跑一个会**连续改文件**的多步任务（例：「帮我写一个简单的 Python 脚本并保存到工作目录，然后改两处注释」）
- [ ] **观察 A**：当它**连续改了 3 次文件**（write_file / edit_file）却**一条命令都没跑**时，
      是否**立刻停下**并顶回一句要求验证？
- [ ] **观察 B**：那句提示是否**带【严格模式】**、且**说清了「你改了文件但没跑命令」**？
      内核有两种措辞，**出现在哪种都对**：
      · 中途门禁（每累计 3 次写）：`【严格模式】你已连续改了 3 次文件（write_file / edit_file），但一条验证命令都没跑过。`
      · 收尾门禁（模型想结束时）：`【严格模式】你改了 3 次文件之后还没跑过任何命令 —— 未验证不得收工。`
- [ ] 它随后**真的跑了一次验证**（命令 / 或回读刚改的文件），欠账清零、继续往下做
- [ ] **收尾**：回到设置 → 助手 → **关闭**「严格模式：每步强制验证」（恢复默认）
