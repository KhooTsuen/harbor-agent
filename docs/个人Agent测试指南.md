# Harbor Agent 个人使用测试指南

## 1. 目的

本文档面向个人开发者和个人用户，目标是用较低成本确认三件事：数据安全、任务可信、失败可恢复。它不要求每次执行企业级测试矩阵。

完整测试用例请参阅 [详细测试文档](./详细测试文档.md)；工具说明请参阅 [AI测试工具清单与接入指南](./AI测试工具清单与接入指南.md)。

## 2. 三种测试频率

| 频率 | 适用情况 | 必做内容 |
|---|---|---|
| 日常 | 普通代码或配置修改 | 类型检查、单元测试、一次真实对话 |
| 重大修改 | 修改 Electron、会话、权限、文件工具、发送或 UI | 完整验证、文件任务、停止和恢复 |
| 发布前 | 打包、分享给他人或长期使用 | 发行包、干净目录、凭证扫描、备份恢复 |

## 3. 最小环境和数据

建议使用 Windows 10/11、Node.js 24、npm、专用测试工作区和限额测试 API key。进入项目目录后记录版本：

```powershell
Set-Location E:\CodexWorkbench
node --version
npm --version
git rev-parse --short HEAD
```

不要直接在重要项目或个人资料目录测试。准备 `E:\Harbor-personal-test\workspace`，放入 `hello.txt`、`README.md` 和一个故意失败的测试。测试前备份整个测试目录，不要只复制凭证文件。

## 4. 日常检查

执行：

```powershell
npm run typecheck
npm run test:unit
npm test
npm run build
```

启动应用完成一次真实对话：新建会话，输入“请列出工作区文件，不要修改任何文件”，发送，确认回答逐步出现；关闭再打开，确认会话仍存在。修改 `electron/`、会话、权限、文件工具或发送流程时不能跳过 `npm test`。

## 5. 重大修改检查

### 5.1 完整门禁

```powershell
npm run verify
```

保存完整输出。不要用最后一个通过的命令代替完整结果。

### 5.2 文件修改

在专用工作区发送：

```text
请读取 hello.txt，把 Hello Harbor 改成 Hello Harbor User。修改前说明目标文件，完成后说明实际结果。
```

确认：权限提示清楚；只修改目标文件；文件内容真实改变；没有修改父目录或其他文件；任务账本和日志记录了工具调用。模型说“完成”不算证据，必须检查磁盘文件。

### 5.3 停止和失败

让 Agent 执行较慢任务并点击停止。确认流式内容停止、子进程退出、已有内容保留、状态不是成功。再让一个命令确定失败，确认错误可见、任务没有伪报成功、关闭重启后状态仍正确。

检查进程：

```powershell
Get-Process Harbor, node, electron -ErrorAction SilentlyContinue
```

## 6. 发布前检查

```powershell
npm run verify
npm run package
```

把 `dist-portable/Harbor` 复制到新目录启动，验证它不依赖源码或开发服务器，能发送消息、停止任务、关闭并恢复会话。检查 `data/logs`、`data/tasks`、`data/sessions`、截图、录屏、Git diff 和发行包中没有真实凭证。

可使用以下命令做关键词初筛（可能有误报）：

```powershell
rg -n -i "api[_-]?key|authorization|bearer|secret|password|token" E:\CodexWorkbench\src E:\CodexWorkbench\electron E:\CodexWorkbench\scripts E:\CodexWorkbench\tools
```

发布前备份并恢复整个测试 `data`，确认会话、任务账本和设置可读取，恢复不会自动重复危险任务。

## 7. 个人用户核心用例

| ID | 操作 | 通过标准 |
|---|---|---|
| P-001 | 启动应用 | 无白屏、无崩溃 |
| P-002 | 新建会话并发送 | 消息顺序和回答正确 |
| P-003 | 关闭再打开 | 会话可恢复 |
| P-004 | 只读询问 | 没有文件变化 |
| P-005 | 修改测试文件 | 目标文件真实改变，其他文件不变 |
| P-006 | 拒绝权限 | 被拒绝动作没有执行 |
| P-007 | 运行中停止 | 任务停止且不显示成功 |
| P-008 | 制造失败 | 错误可见且可诊断 |
| P-009 | 切换两个会话 | 消息和草稿不串线 |
| P-010 | 中文文件名和长文本 | 不乱码、不崩溃 |
| P-011 | 发行包启动 | 脱离源码仍可运行 |

## 8. 个人多代理测试

个人使用时建议最多两个角色：主代理负责修改和运行测试，验证代理只读检查文件差异、日志、任务账本和截图。GUI 窗口同一时间只能由一个代理控制；每个代理使用独立 `run_id`、data、workspace 和端口；失败报告不得被重试覆盖；验证必须检查实际产物而不是模型自报。

## 9. 失败处理

1. 停止可能继续产生副作用的任务。
2. 保存错误截图、命令输出、任务 ID 和时间。
3. 检查目标文件、任务账本和日志。
4. 检查 Harbor、Electron、Node 和工具子进程。
5. 复制测试目录保留现场。
6. 判断是产品、模型、网络、数据还是环境问题。
7. 修复后重新执行原用例。

个人报告可以记录日期、版本/提交、测试类型、命令、通过/失败、工作区变化、凭证泄露情况、残留进程和证据位置。

## 11. 个人版通过标准

个人 Agent 基本可用的最低条件是：能稳定启动和退出；能发送消息并显示结果；只读任务不偷偷修改文件；文件任务的实际产物与回答一致；权限拒绝有效；任务可停止；失败不伪装成功；重启后会话和任务状态可理解；没有发现凭证进入 Git、日志、截图或发行包；发行包能在独立目录运行。

以上任一项失败，都应暂停高风险任务，保留现场并修复。企业级供应链、签名、跨用户、灾难恢复、多模型基准和复杂多代理矩阵，按需启用 [详细测试文档](./详细测试文档.md) 对应章节即可。
