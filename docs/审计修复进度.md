## 独立项：`looksSecret()` 状态 bug（硬禁区，已授权）

- **症状**：`PATTERNS` 里很多正则带 `/g`，`.test()` 会把 `lastIndex` 留在正则对象上 →
  同一根字符串连判两次结果交替翻（实测 `[true,false,true,false,true]`）。
- **修法（方案 A，用户首选）**：`looksSecret` 改成走 `redact()` 主入口做「原文 vs 脱敏后」对比。
  **先确认过没有依赖环**：`redact()` 不回调 `looksSecret`。
- **模式表一个字没改**（授权要求）；文件其余部分没动。
- **调用方核对**：全库 grep → **本仓库当前零调用**（只剩导出与注释）。唯一真实调用方在装机版旧代码里
  （旧 `schedule-store.cjs`），等下次打包就消失 → **没有调用方行为变化**。
- 测试：`src/lib/__tests__/looksSecretStable.test.ts`（18 项：稳定、没变松、没变严、记名法仍认）。
- 顺手改了两处**已过时**的注释（`memory-schema.cjs` / `diagnostics.cjs` 里原来写「别用 looksSecret，
  它有 bug」）→ 改成「那个 bug 已修」。

### 问题 13：空壳备份

- **改**（三处，后端两处 + 界面一处）：
  1. `create()`：一个用户项都没拷到 → **不产生备份**（删掉半成品并说明原因）；
  2. `list()`：每份备份现算 `empty`（一个用户项都没有）与 `missing`（缺哪几项）——
     **按磁盘算**，所以历史遗留的空壳同样能被标出来；
  3. `restore()`：空壳**直接拒绝**（后端兜底，不靠界面）；逐项跳过「备份里是空目录」的项，
     **绝不拿「没东西」去盖用户现有的东西**。
- **界面**：`BackupPanel.tsx` 给空壳标红「空备份：里面没有任何用户数据，不能恢复」并**禁用「恢复」**；
  不完整的标「缺 X」（不禁用，只让你看见）。

### 问题 22：改 meta 不再整篇重写

- **改**：新增 `session-io.writeMetaLine()` —— 只换第一行，**其余字节原样保留**；
  第一行不是 meta / 解不开时把新 meta 插到最前面（原内容一个字节不丢）；落盘走原子写。
  `session-write.updateMeta()` 改用它。
- 顺带解决两件事：解不开的行不再被静默删（以前 `readLines` 跳过它、写回时永久丢失）；
  长会话写一半崩了不会截断。
- ★ **遇到一个取舍（已解决，记下来）**：自检 `31-session-redact` 有一条断言
  「整体重写会清掉旧会话里的明文密钥」—— 那条保证原本是「整篇重写」白送的，改成只换第一行就没了。
  做法是**两者都要**：平常只换第一行；**只在检测到旧内容里还留着明文密钥时**
  （`redact(原文) !== 原文`）才逐行重新脱敏一遍，**解不开的行原样保留**、落盘仍走原子写。
  所以那条断言没有被放宽（一个字没改就绿了）。

### 问题 15：会话 id 能拼任意路径

- **改**：`session-io.fileFor()` 卡 `^sess_[a-z0-9]+$`，不合规直接抛错（不「悄悄换安全路径」）。
  四个通道（`session:read` / `update` / `delete` …）共用一个 `fileFor`，堵一处等于堵四个。
- **找到的依赖（重要）**：`session-read.list()` 会遍历目录里**每个** `.jsonl`，
  名字不合规的文件会让 `fileFor` 抛错、把整个会话列表带崩 → 那里加了白名单过滤（跳过杂物文件）。
- **实证**：真在 `data/sessions/` 放一个 `zzz-not-ours-1.jsonl`，`list()` 照常返回、不含它。

### 问题 16：超时/中断只杀 cmd.exe，孙子变孤儿

- **改**：`run_shell.cjs` 撤掉 `exec` 的 `timeout`，改自家 timer → `killTree(child)`（`taskkill /T`）并**立刻结算**；
  `handlers/shell.cjs` 四处 `child.kill()` → `killTree`（超时 / 输出超限 / `shell:abort` / `shell:abortAll`）。
- ★ **找依赖时发现的**：`task-outcome.cjs` 用 `/\[进程被超时杀掉/` 判「这条命令失败」（自检 `34-outcome` 钉着）——
  所以新文案**保留了「进程被超时杀掉」几个字**，否则超时会被算成成功。
- **实证（真跑）**：起一条会生孙子的命令（孙子 node 把 pid 写进文件），超时后用 `tasklist` 核对那个 pid 已消失。

### 问题 17：run_shell 的 cwd 是裸的

- **改**：cwd 走 `_shared.resolvePath()` → 越界抛 `PermissionRequiredError` → 由 `tools/index.cjs` 转成向用户要授权
  （和文件工具同一套）。审计留痕：把**实际** cwd 回填进 `args`（审计记的就是这个对象）。
- **实证**：`cwd: 'C:\\Windows'` → 抛「需要授权才能访问」；沙箱内照跑并把 cwd 回填。

### 问题 20：网络策略管不到 browse

- **改**：`browse.run()` 打开前调 `netPolicy.decide({ kind: 'webview', target: url, ctx })`，deny 拦下（把理由交用户）。
- **口径差异（写下来了）**：`ask` 时**放行 + 记日志**（确认界面不在工具层，而「完全访问」档的语义就是不再问）；
  `run_shell` 在同样情形下更严（直接拒）→ 两处不一致已记进 improvement-checklist。
- `search_web` **不加**：去哪儿联网完全由配置决定（provider / endpoint 是你填的），模型只能决定搜什么词，
  没有「绕过设置去访问某主机」的入口 —— 理由写在它文件头。
- 网页里的**点链接/站内跳转**本来归另一套（`navigation-policy.cjs` + `general.browserNavigation`），两套各管一段。

### 问题 21：网页标签一个权限 handler 都没装

- **改**：新增 `core/webview-permissions.cjs` —— **默认全拒**，只放行拿不到用户数据的那两个
  （`fullscreen` / `clipboard-sanitized-write`，拦住只会让正常网页坏掉）；`request` 与 `check` 两个 handler 用**同一个判据**。
  挂载点：`handlers/browser.cjs` 的 `register()` 里 `app.whenReady()` → `persist:agent-browser` 分区。
- ★ **为什么没写进 `main.cjs`**：`register()` 是启动早期跑的（`main.cjs` 模块顶层就调 `registerHandlers`），
  那时 `session` 模块还不能用；且 `main.cjs` 只有 299 行，加 5 行就过 300 红线。
- **真机实证（隔离副本）**：guest 里 `navigator.permissions.query({name:'geolocation'})` → **`denied`**（默认会是 `prompt`）；
  `getUserMedia({audio:true})` → **`NotAllowedError`（609ms）** —— 没人被问、也没等到超时。

### 问题 23：插件权限门 fail-open

- **改**（`plugin-tool.cjs`）：`risky` 改成 **fail-closed** —— 只有明确写 `network:false && write:false` 才算无副作用；
  运行时约束（`allowWrite` / `allowNetwork`）同理。`if (!approval)` → `if (approval !== true)`（与 `tools/index.cjs` 同一口径）。
- **文案同步**：`plugins.describePermissions({})` 以前写「无副作用」，现在写「未声明权限，按可能有副作用处理」——
  描述和判定必须说同一件事，否则报错会变成「（无副作用）被拒绝」这种自相矛盾。
- **实证（真跑）**：造一个不声明 `permissions` 的插件走完整 `tools.execute`：只读档拦下 ✓、完全访问照跑 ✓、
  确认框返回 `'yes'`（非 `true` 的真值）**算拒绝** ✓、返回 `true` 才跑 ✓。
- ⚠️ **行为变化**：以前「没声明权限」的老插件在只读档也能跑，现在被拦（这是修漏洞的代价）。
