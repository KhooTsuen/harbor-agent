### 问题 22：改 meta 不再整篇重写

  `session-write.updateMeta()` 改用它。
- 顺带解决两件事：解不开的行不再被静默删（以前 `readLines` 跳过它、写回时永久丢失）；
  长会话写一半崩了不会截断。

### 问题 19：主窗口没有 CSP

- 口径：`default-src 'self'` / `script-src 'self'` / `style-src 'self' 'unsafe-inline'` /
  `img-src 'self' data: blob: file: https:` / `font-src 'self' data:` / `media-src …` /
  `connect-src 'self'` / `object-src 'none'` / `base-uri 'self'` / `form-action 'none'`。
- **只在打包时注入**（`vite.config.ts` 里一个 `apply: 'build'` 的插件）：开发模式 Vite 要插
  **内联脚本**（HMR 客户端），`script-src 'self'` 会把开发模式直接拦死。**代价写清楚**：
  开发模式不受这套 CSP 约束 —— 宁可少一层，也不要开发模式坏；反过来（dev 单独放宽）等于维护
  两套规则，早晚漂。
- 真机验的**不是**「有没有那条 meta」，而是「有没有生效、有没有收过头」：
  页内挂 `securitypolicyviolation` 监听 + reload（收启动全过程）→ 主动塞内联 `<script>`
  （**必须被拦** = 生效）→ 内联 `style`、`data:` / `blob:` / `file:` 图片、`<webview>` 加载本地页面
  （**都必须能用** = 没收过头）。
- **真机逮到一条真东西**：启动时有一条 `script-src | eval`。追到打包产物 → 是 **zod** 的能力探测
  `try { Function('') } catch { return false }`（`allowsEval`）—— 它**必然失败**，而且**自己 catch 住**
  （退回非 JIT 路径，功能不受影响）。
  试过在入口里提前 `z.config({ jitless: true })` **关掉它，结论是拦不住**：zod 在**自己模块初始化**
  阶段就读了那个值（探针的堆栈证明调用点在打包产物**第 1 行**，早于任何应用代码）→ 那点改动**已撤回**
  （不留没用的代码）。所以这条违规按「**CSP 下 zod 的正常行为**」处理：真机里单独钉住
  ——**除它之外零违规，而且它必须能追到 bundles 里**（别的东西也来 eval 就红）。
  **这类问题单测结构上照不到**：单测环境里根本没有 CSP。
