## boot-scene/ —— 启动页的港湾夜景

| 文件                                                                         | 是什么                                                                     |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `source.png`                                                                 | 底图，**用户自己用 AI 生成**的（2048×1152）                                |
| `scene.b64`                                                                  | 生成产物：每格「一个字符 + 一个颜色」的网格，zlib 压缩后 base64（约 60KB） |
| 生成脚本是 `scripts/generate-boot-scene.py`（需要 Pillow + numpy，不联网）： |

```bash
python scripts/generate-boot-scene.py --check                        # 只看诊断
python scripts/generate-boot-scene.py --preview tmp/scene-preview.png # 生成 + 回渲染一张 PNG
```

**为什么产物要入库**：字符网格是按 Consolas 粗体的字形位图挑出来的，
换一台没有这个字体的机器复跑会得到略有差异的结果。
产物入库 = 每台机器看到的启动页一致；脚本入库 = 以后想调参数能复跑。

**为什么不是把底图当成图片显示**：启动页的视觉必须是**字符**拼的。
脚本对每一格做的是「在全部 95 个可打印 ASCII 里，挑一个形状最像、染色后最接近的」——
所以放大看能读出具体的字，而不是一张位图。

**为什么走 canvas 不走 DOM**：4K 网格是 384×120 = 46,080 格。
项目实测 2 万个 DOM 节点切换要 1 秒、12 万个要 9 秒。
真机测过：46,080 个字形画进一张 3840×2160 的 canvas 约 0.24–0.42 秒，一次性。

关于画面偏暗的一点说明：只给字符着色、不填格子的情况下，
字符最多只能覆盖约 46% 的格子面积（18px 粗体 Consolas 的 `@`），
所以画面天生比底图暗一档 —— 生成脚本里有提亮与亮度补偿的参数。

## 场景的当前状态

当前启动页先交付 Phase 1–2：场景分层数据 + 海面运动。

- 每格的层号（天空/海面/岛/灯塔/渔船/倒影/窗）由生成脚本分析底图后写进资源，
  运行时只动海面那一层
- 海面用**行进波**：目标墨量是 `sin(x·k − t·speed − y·k)` 的平滑函数，
  远/中/近三层速度不同，相邻格、相邻帧都连续（不是每帧随机，见文档 §10）
- 只改海面字符，保持统一底色和字符画主体
- 质量档与 Reduced Motion 在「设置 → 外观」控制

光束、云漂移、渔船、船灯、倒影、星星和 Idle/待机模式属于后续阶段，当前暂不接入。

关于画面偏暗的一点说明：只给字符着色、不填格子的情况下，
字符最多只能覆盖约 46% 的格子面积（18px 粗体 Consolas 的 `@`），
所以画面天生比底图暗一档 —— 生成脚本里有提亮与亮度补偿的参数。
