# 写一个新技能

技能就是一份 Markdown 操作手册。写一次，之后每次遇到同类任务都能照着做。

## 什么时候该建技能

- 同一套步骤**做过第二遍**了
- 用户说"以后都这么做"

一次性的任务不用建。

## 怎么建

1. 在技能目录下建一个文件夹（名字用小写英文 + 连字符，比如 `deploy-check`）
2. 里面放一个 `SKILL.md`，内容照下面这个骨架写
3. 写完不用重启，下一轮对话就会出现在系统提示的技能清单里

## SKILL.md 骨架

```markdown
---
name: 技能名（中文也行）
description: **什么情况下该用它**。这句最关键 —— 模型靠它决定要不要读这个技能。
---

# 标题

## 什么时候用

## 怎么做

1.
2.

## 注意
```

## description 怎么写才有用

它决定这个技能会不会被想起来，所以要写**触发条件**，不要写主题：

| 写法 | 效果 |
|---|---|
| ✅ 「当 npm install 报 ERESOLVE 时用」 | 事情发生了，模型能对上 |
| ❌ 「关于依赖管理的知识」 | 没有任何一刻会"发生"什么来提醒它 |

## 注意

- **正文别太长**。系统提示里只放名字和 description，正文是模型按需读的，但一口气写三千字，读进来也白占上下文
- **写步骤，别写事实**。事实会过期（比如"这个按钮在左上角"），步骤不会
- **重的内容指向唯一真相源**，技能里只写"去哪读"
